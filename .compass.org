This page configures the =compass= executable for this repository. Every
command reads it; =compass config= prints the effective configuration and
where each value came from. The command line wins over this page: =--out=,
=--meta= and =--set <codec>.<key>=<value>=.

* Paths

- =#+output:= :: The output root, relative to the checkout. It is the
  checkout itself, so a generated page lands where it is committed and
  =compass check= reports it when it drifts. An output nobody commits goes
  under =build/output/=, which git ignores.
- =#+meta:= :: The directory of the contract pages, relative to the
  checkout.

* Codecs

One row per codec: its name, =yes= or =no= for enabled, and its options as
space-separated =key=value= pairs. A codec with no row runs on its
defaults. =tangle= writes the templates of the MASD library from their
archetype pages under =share/masd/templates=, the one directory whose
tangled files are committed. =codegen= generates compass from its own
models with the MASD library under the project's library in
=projects/compass.codegen/library=, which holds the component catalogue,
the licence and the modelines. The MASD library is named by its checkout
path, =share/masd=, not as =@compass=, the copy installed beside the
binary: compass edits the library it generates itself with, and a template
read from the checkout is an input whose change regenerates what it wrote.
=no_pr_triggers= is off: ORE Studio removed its pull-request checks because
they came late and missed the paths their workflows did not name, but
compass's one Linux workflow covers every path and builds a pull request,
merged with main, in about eleven minutes. =commit_provenance= is off:
compass's own commits carry no story, task or environment trailers, so
=check --ratchet= here does not ask for them.
