This page is the node for the =masd.sql.schema= facet of the MASD
library, the plain PostgreSQL technical space =masd.sql=. Its one
archetype, [[id:16D8D930-4264-45BC-BC22-3046F9C57523][masd.sql.schema.create]], holds the template.

* Summary

A component that owns a database describes each table as a
=masd.codegen.entity= model and the database as one =masd.codegen.schema=
model in the same =modeling/= directory. This facet projects the schema
model onto =sql/schema.sql=: every schema it lists, every table of those
schemas and every function, at the current version, in one script.

* The masd.sql.schema facet

The script is the specification of the schema, never a migration. A
database that holds data is changed by the component's migrations, which
are written by hand and frozen once released; a test builds one database
from the migrations and one from this script and compares their catalogs.
A change to a model therefore shows up twice in a pull request: as the
=git diff= of =schema.sql=, and as the migration that must produce it.

Tables are written schema by schema, in the order the schema model lists
the schemas, and within a schema in an order where every table follows the
tables its foreign keys reference, ties broken by name. A table whose
profile marks it retained is introduced by a comment saying so: its rows
exist nowhere else, so once released the migration tests fail a migration
that loses its rows or drops or retypes its columns, unless a recorded
decision allows the loss.
