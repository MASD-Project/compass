This page is the node for the =masd.cpp.protocol= facet of the MASD library.
Its archetypes are [[id:9455122B-F9F6-421F-B3BD-EBFEEFF6D95F][masd.cpp.protocol.header]],
[[id:D7E6C8E2-E6EC-49FD-B85A-E0BDDCC28D4A][masd.cpp.protocol.impl]] and
[[id:B607CB2C-DCD4-4EFC-809C-E85EB06F269E][masd.cpp.protocol.tests]].

* Summary

A service's requests and responses read and write JSON through generated
code. This facet writes each message of an operation model as a struct, in
the model's =#+namespace:=, states its wire shape once as =wire_fields=, and
specialises =wire_traits= against the codec runtime of
[[id:7D0FA277-D3F7-48E9-BCDF-7A88592119E3][masd.cpp.codec]]. The JSON Schema
of every message is =json_schema<T>()= of that runtime, so each schema is the
same value as its reader's shape. A routed request has two shapes, as the
service's binding rules say: its MCP arguments, every field, which
=json_schema<T>()= and =read_json= state; and its body, only the =body=
fields, which =body_fields=, =body_json_schema= and =read_body_json= state.
In both, a field the rules let a caller leave out keeps its default and is
not required.

It is ORE Studio's =ores.cpp.protocol= header for an operation and the
=protocol_codec_impl= and =protocol_roundtrip_tests= archetypes of
=ores.cpp.wire-codec=, copied at ORE Studio commit
=bc0702ad46b8a6097ce5242ece7ba01067699f60= (=main=, 2026-11-23), and narrowed
to JSON.

* The masd.cpp.protocol facet

On by default for every operation model. The files land under the model's
own component: =include/<component>/messages/<entity>_protocol.hpp=,
=src/messages/<entity>_protocol.cpp= and
=tests/messages_<entity>_protocol_tests.cpp=. The codecs are written against
the runtime of the component the =codegen= option =codec_component= names.

A message's members are its fields, in model order, each of its
=:cpp_type:= with its =:default:=. Messages are declared after the messages
they hold, so a model may state a message before its parts. Three
properties of a field change the code:

| Property | Effect |
|----------+--------|
| =:values:= | The field's type names an enumeration of those values, declared once in the header, with =to_string=, a parser =<enum>_of= and a =text_form= that writes its names, so the reader refuses any other text and the schema lists them. The generator refuses =:values:= on a standard type or a message. Two fields that declare one enumeration must list the same values, in the model and in every operation model of the same namespace in its directory; each declaration is guarded by its qualified name, so headers that declare it can be included together. |
| =:encoding: base64= | The member is the runtime's =base64_bytes=, so its JSON is base64 text and a reader refuses anything else. |
| =:http_in:= | Where a route reads the field. A field that is not =path= may be left out when it is a vector or a message, has a =:default:= or states =:required: false=: its =field= states =may_be_absent=. A request with a =body= field also states =body_fields=. |

The context lists each routed request's fields again as =path_fields=,
=query_fields= and =body_fields=, with each field's =http_name=, so the
templates that bind a request read where its fields come from as data.

Where compass's copy diverges from ORE Studio's:

| Divergence | ORE Studio | compass | Kind |
|------------+------------+---------+------|
| Formats | JSON and MessagePack | JSON only | Facet not enabled: MessagePack is off |
| NATS | =nats_subject=, =requires_session= and the derived subject | None: compass's messages cross HTTP and MCP only | Unused |
| =response_type= | An alias on each request | None: the routes of the HTTP task bind the response | Unused |
| Opt-in | =ores.cpp.wire-codec= on per model | On for every operation model | Default |
| Enumerations | Declared by hand beside the domain types | Generated from a field's =:values:= | compass's models |
| Bytes | None | =base64_bytes= for =:encoding: base64= | compass's models |
| Declaration order | Model order | Each message after the messages it holds | Fix to offer ORE Studio |
| Round trip | =ores::testing::check_wire_roundtrip= | Samples 0 and 1 and the default, each against the JSON Schema; a member added and each required member removed, refused by the reader and the schema; each member that may be absent removed, accepted by both; and for a request with a body, its body read and checked against the body schema | Fewer formats, more checks |
| Optional members | Only =std::optional= | Also a member the binding rules let a caller leave out | compass's models |
| Body | None: NATS carries the whole message | =body_fields=, =read_body_json= and =body_json_schema= per request with a body | compass's models |
| An enumerator out of range | Written as its first name | =to_string= throws | Fix to offer ORE Studio |
