This page defines the =knowledge= document type — one entry in the
[[id:8B29A8D8-E004-4E87-B81D-ABEAF68F2B98][document types]] taxonomy. The general contract every document follows
(frontmatter, state, linking, tags) lives on the taxonomy page; this
page carries only what is specific to =knowledge=.

* Contract

- Implements :: loading. See
  [[id:F5CB5A45-6557-410B-9E4F-542957561A16][Regulatory Functions]].
- Folder ::
  - Cross-cutting knowledge (not specific to one component) lives at
    =doc/knowledge/{domain,architecture,...}/=.
  - Component-specific knowledge (deeper analyses tied to one
    component's code) lives co-located at =projects/<comp>/docs/=.
- Level :: =cross=
- Not stateful — no TODO. Audit may flag stale facts via a tag.
- How to create :: see [[id:4D3C2B1A-9E8F-4A7B-6C5D-3E2F1A0B9C8D][New knowledge document]] in the codegen recipe.

** Index pages (knowledge / meta variant)

When a knowledge or meta document's role is /navigation/ — it
summarises a tree of related documents and links to them — it is
called an /index page/. Examples in this repo: [[id:B69989F6-19E1-430D-AC6D-B2416E4C433F][Compass]],
[[id:E5635EAC-CCE9-C0A4-A00B-C1780FF4A88E][Agile]], [[id:4D3C2B1A-9E8F-4A7B-6C5D-3E2F1A0B9C8D][Product backlog]], the [[id:4D3C2B1A-9E8F-4A7B-6C5D-3E2F1A0B9C8D][next]] and [[id:4D3C2B1A-9E8F-4A7B-6C5D-3E2F1A0B9C8D][deferred]] bucket indexes.

Index pages have three extra requirements on top of the usual
knowledge / meta contract:

1. /Blurb before the first headline/. One paragraph between the
   frontmatter and the first =*= heading. It tells the reader, in one
   look, what is being indexed and why. Without it, the page lands on
   a heading with no orientation. The blurb hyperlinks key terms (the
   things this page is indexing) to their glossary entries or to the
   downstream pages.
2. /Internal links woven into content/. Cross-references to other
   docs in this repo sit inline in the prose or in the bullet lists
   they pertain to — /not/ in a separate "See also" dumping ground.
   Every section should link somewhere relevant when the topic
   demands it.
3. /=* See also= is for external references only/. Blog essays,
   external standards, vendor docs — material that lives outside
   [[proj:doc][=doc/=]]. If the only thing you'd put in See also is an internal
   id-link, the link belongs in the body instead.

If all three rules hold, the page is acting as an index. If none do,
it is a normal knowledge document — no extra obligations.
- Required sections ::
  - /Blurb/ — the 3-5 sentence overview, between the frontmatter and
    the first =*= heading. Knowledge docs do /not/ carry a separate
    =* Summary= section; the summary is the blurb.
  - =* Detail= — the content.
  - =* Patterns used= — optional; present when the page describes how services
    work together. One line per
    [[id:4D3C2B1A-9E8F-4A7B-6C5D-3E2F1A0B9C8D][service architecture pattern]]
    the page applies, linked, saying how it applies it. The pattern lists the
    page back under =* In compass-ng=, and
    =build/scripts/check_pattern_uses.py= checks both directions.
  - /See also/ — optional, for external cross-references only
    (internal references weave into the body).
