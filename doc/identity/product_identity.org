This is the product identity of compass-ng — the System 5 document in our
cybernetic information architecture, where identity is the durable policy layer.
It states what compass-ng is, who it serves, and what it will not do.

* Vision

** Vision statement

compass-ng makes the checks and generators of a large, LLM-developed code base
fast enough to run on every edit. It loads the project's org documents, C++,
SQL and build logs into memory once, in a data-oriented layout, and runs
/codecs/ over them. A codec reads the in-memory tables and produces either
output files or diagnostics:

- *Code generation.* Typed model documents become C++, SQL, CMake, TypeScript
  and documentation through templates.
- *HTML export.* Every org document becomes HTML byte-identical to the Emacs
  export. This path reads the parsed documents directly, without models or
  templates.
- *Gates.* Rules over models, documents and source code report violations, and
  each violation names its fix.
- *Analysis.* Established build-health and design metrics over C++ and SQL
  show what makes the build slow or the design tangled.

A codec is enabled or disabled by configuration, and declares the document types
it reads. A run parses only content that no worktree of the repository has
parsed before, runs only the codecs whose inputs changed, and writes only the
outputs whose content changed. Diff mode runs the same pipeline and writes
nothing.

compass-ng is the engine under the agent process. Process skills such as pstack
tell an agent to encode each repeated correction as a check. compass-ng makes
that check fast enough for the agent to run while it works, rather than an hour
later in CI.

compass-ng grows from the document management of compass, ORE Studio's
=projects/ores.compass= and the =doc/= contract it serves. "compass-ng" names
the new implementation; "compass" names the old one.

** Qualities

- *Fast.* All of ORE Studio's org, C++ and SQL (about 37,000 files, 310 MB)
  parses cold in under 5 seconds on 8 cores. A warm run with nothing changed
  finishes in under 1 second. A full code regeneration takes less than 30
  seconds.
- *Minimal work.* Nothing is parsed twice, no codec runs whose inputs did not
  change, and no file is written whose content did not change.
- *Shared across worktrees.* Parsed data and codec results are stored by content
  hash, so every worktree of a repository reuses the work of the others.
- *Memory-efficient.* Data-oriented tables with interned strings and handles; no
  per-document object graphs.
- *Self-hosting.* compass-ng checks and generates its own documentation as soon
  as it can.

* Audience

| Client      | Surface                      | Needs                                                                                |
|-------------+------------------------------+--------------------------------------------------------------------------------------|
| LLM agents  | =compass= CLI, edit hook     | A verdict on the files just changed in under a second; the fix named in each error. |
| Developers  | =compass= CLI, local gate    | Code generation and every gate that needs no build, in seconds.                      |
| CI          | =compass check=              | The same command and verdict as the local run.                                       |
| Site readers| Generated HTML               | The documentation site, identical to the Emacs export.                               |

* Out of scope

- Everything in ORE Studio's compass that is not about documents, code
  generation or checks: environments, deployment, systemd, NATS and pull
  requests.
- Running builds and tests. compass-ng reads build logs and decides which build
  gates a change needs; it does not compile or run test suites.
- Semantic C++ analysis. compass-ng works from syntax trees and the include
  graph. Facts that need the compiler come from compiler output.
- A long-running server is not decided. It is added only if a measured use case
  needs it.
