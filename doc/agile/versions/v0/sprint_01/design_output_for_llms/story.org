* Goal

Most of compass's readers are LLM agents working in ORE Studio, and every line
compass prints costs them context. Every command answers in a few lines: what
happened, what is wrong, and the one thing to do next. Everything else a run
knows (each step, each unit, every finding, the timings, the full diffs) goes
into a log file in the project directory that the agent can grep when it needs
more, and the terminal output says where that file is.

* Acceptance

- Every command prints a one-line verdict first (pass, fail or error, with counts), then at most a bounded number of findings, grouped by rule when a rule repeats, and ends with the path of the run's log.
- Every result and every finding carries a next action: the command to run, the file and line to change, or the exception to write.
- Each run writes a complete, grep-able log to a git-ignored directory inside the checkout: the command, the =--version= facts, every step and unit with its timing and cache source, every finding in full, and every diff; old logs are pruned.
- Findings have one stable line format, documented and locked by tests, and a machine format (JSON Lines) for tools.
- =compass explain <rule>= gives the rule's statement, why it exists, the memory or document behind it, how to fix it and how to excuse it.
- Errors say what failed and what to do about it, never a bare exception text, and exit codes 0, 1 and 2 keep their documented meanings.
- The output is deterministic: sorted, relative paths, no colour or progress output when not on a terminal, no timings unless asked.
- =compass hook= follows the same contract within Claude Code's hook payload.
