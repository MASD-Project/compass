* Acceptance

- Parse time for all C++ and all SQL is known on 8 cores, with a per-file ERROR count; a fallback is named if C++ exceeds 5 seconds.

* Plan

- vcpkg overlay ports under =build/cmake/overlays/common=, as in ORE Studio:
  =tree-sitter-cpp= 0.23.4 from its repository and =tree-sitter-sql= 0.3.13
  from its release tarball. Both ship the generated =parser.c= and
  =scanner.c=, so the ports compile them directly, without the tree-sitter CLI
  or Node.js. =tree-sitter= itself comes from vcpkg.
- Add a =parse= stage to =compass-bench=: parse every C and C++ file and every
  SQL file in the file table with tree-sitter, one parser per thread, over the
  mapped bytes.
- Per file, record the parse time and the number of =ERROR= and =MISSING=
  nodes. Trees are deleted after counting; nothing is kept.
- Report per language: files, bytes, median, min and max wall time over the
  repetitions, MB/s, files with errors, total error nodes, and the ten worst
  files by error count and by parse time.
- If parsing all ORE Studio C++ takes more than 5 seconds on 8 threads, the
  result names a fallback: a lighter scanner for the facts the metrics need.

* Result

- tree-sitter 0.27 with the C++ (0.23.4) and SQL (0.3.13) grammars comes in
  through overlay ports in =build/cmake/overlays/common= that compile the
  shipped generated sources, with no CLI or Node.js.
- =compass-bench parse= parses every C++ and SQL file on all cores, counts
  =ERROR= and =MISSING= nodes per file, and reports per language.
- *The C++ budget is missed.* All of ORE Studio's C++ takes 11.5 s on 8
  threads, against a 5 s budget, and 55 s on one thread (3.6 MB/s). The
  fallback named in the plan applies; see the story's Decisions.
- *The SQL grammar does not fit ORE Studio's SQL.* 3,003 of 3,470 files have
  error nodes. The files are psql scripts: =\ir= meta-commands produce about
  one error each, and PL/pgSQL =$$= function bodies do not parse.
- C++ error nodes cluster in test files (7,804 files in all), which needs a
  closer look before any check relies on tree-sitter's C++ verdict.
- A language with no files is reported as a note; the run fails only when no
  language has files or on an I/O error. Eight injected defects in error
  counting and routing all failed the tests.
