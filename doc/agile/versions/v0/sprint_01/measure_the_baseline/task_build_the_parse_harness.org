* Acceptance

- The harness runs against a git archive of ORE Studio main and prints per-stage wall time, bytes, file count and error count.

* Plan

- New tooling component =compass.bench= with one executable, installed as
  =compass-bench=. It is the frozen harness every later measurement runs
  through.
- =compass-bench read <checkout>= lists the tracked files with one
  =git ls-files -z= call, maps each file with
  =compass::platform::filesystem::mapped_file= and touches every byte, on N
  threads (=-j=, default all cores).
- Data shape: a =file_table= in struct-of-arrays form (path, size, extension
  id) built once from the listing; a =stage_result= per stage with files,
  bytes, errors and one wall time per repetition. Work is split by handing
  each thread contiguous ranges of the table, balanced by bytes.
- Each stage runs =--repeat= times (default 5) and reports median, min and max
  wall time and MB/s, plus the count of files and bytes it processed and the
  errors it hit, so a fast number that skipped work is visible.
- A per-extension table (files, bytes) shows what the tree holds.
- Later tasks add stages (include scan, tree-sitter) to the same executable.

* Result

- =compass.bench= is the frozen harness: =compass-bench read <checkout>= lists
  tracked files with one =git ls-files -z=, builds a struct-of-arrays file
  table, balances contiguous ranges by bytes across threads, maps and touches
  every byte, and reports median, min and max over the repetitions with file,
  byte and error counts.
- A run that reads no files or hits an error prints FAILED and exits 1; a
  tracked file missing from disk counts as an error. Directories and symlinks
  are skipped.
- Reading all of ORE Studio's tracked bytes takes about a third of a second on
  8 threads with a warm cache, so I/O is not where the parse budget goes.
- =compass.bench.tests= has 13 cases; five of seven injected defects failed
  them, and the two survivors were a harmless balance variant and a guard that
  was deleted as unreachable.
