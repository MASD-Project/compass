Know why ORE Studio's CI builds failed over the last two months, day by day,
and which of those failures a compass check could have caught before the

* Acceptance

- =build/scripts/mine_failed_builds.py= lists every failed or cancelled-by-failure
  run of ORE Studio's workflows (=OreStudio/OreStudio=) between two dates,
  default the last 60 days, and downloads each failed job's log.
- It is gentle with GitHub: it sleeps between requests, watches =gh api
  rate_limit= and waits for the reset rather than failing, and caches every
  listing and log on disk so a rerun fetches only what is new.
- Each failed job is reduced to its failing step and a normalised reason (the
  first real error, with paths, numbers and hashes stripped), and reasons are
  grouped into patterns.
- A per-day report in =evidence/= lists, for each day: the failed runs, the
  workflow, job and step, the reason, the pattern, and a verdict on whether
  compass could catch it before a build: already caught (naming the codec),
  could be caught (naming the data it would read), or not catchable before a
  build (infrastructure, flaky tests, runner limits), with the reason.
- A summary ranks the patterns by count and by CI time lost, and the
  commit that introduced each catchable pattern is named where the log allows.
