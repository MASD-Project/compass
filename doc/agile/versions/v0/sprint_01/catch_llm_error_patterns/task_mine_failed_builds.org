and which of those failures a compass check could have caught before the

* Acceptance

- =build/scripts/mine_failed_builds.py= lists every failed or cancelled-by-failure
  run of ORE Studio's workflows (=OreStudio/OreStudio=) between two dates,
  default the last 60 days, and downloads each failed job's log.
- It is gentle with GitHub: it sleeps between requests, watches =gh api
  rate_limit= and waits for the reset rather than failing, and caches every
  listing and log on disk so a rerun fetches only what is new.
- Each failed job is reduced to its failing step and a normalised reason (the
  first real error, with paths, numbers and hashes stripped), and reasons are
  grouped into patterns.
- A per-day report in =evidence/= lists, for each day: the failed runs, the
  workflow, job and step, the reason, the pattern, and a verdict on whether
  compass could catch it before a build: already caught (naming the codec),
  could be caught (naming the data it would read), or not catchable before a
  build (infrastructure, flaky tests, runner limits), with the reason.
- A summary ranks the patterns by count and by CI time lost, and the
  commit that introduced each catchable pattern is named where the log allows.

* Plan

- Split the work in two so classification never touches the network.
  =mine_failed_builds.py fetch= lists the failed runs one UTC day at a
  time (a day holds well under GitHub's 1,000-result search cap), then
  fetches each run's jobs and each failed job's log into a cache.
  =mine_failed_builds.py report= reads only the cache and writes the org
  files, so the patterns can be reworked without refetching.
- Keep the cache small. A log is cut to the 400 lines that end a few lines
  after its first =##[error]= annotation, which sits in the first failing
  step, plus every other line that looks like an error. The cut log is
  gzipped. Timestamps and terminal escapes are stripped.
- Be gentle with GitHub. Each worker sleeps 1 s before every request,
  =gh api rate_limit= is read every 25 requests and the fetch waits for
  the reset below 300 remaining, and 403 or 429 backs off exponentially.
  A day's listing is cached for good once it was taken two days after the
  day ended; a job list and a log are cached for good at once. One worker
  would have taken about six hours for 2,888 runs, so the run used six
  workers, about 100 requests a minute, and leaned on the rate-limit wait.
- Classify each failed job by its failing step and first real error. The
  error is normalised (paths, line numbers, hashes, numbers, timestamps
  stripped) into a reason, and an ordered table of patterns maps the
  workflow, the step and the reason to a pattern and a verdict.
- Name, for each catchable pattern, an example run and its head commit,
  read from ORE Studio's local clone. The example is the pattern's
  earliest pull-request run where there is one, because its head is the
  branch's own commit. A commit counts as LLM-authored when it, or a
  commit a merge brought in, carries a =Co-Authored-By:= trailer naming a
  model (Claude, DeepSeek and the like).

* Notes

- The first error is found by tiers, not by the first line that says
  "error". Runner and memory failures come first, then the ER parser's
  coded warnings, compiler and linker errors, CTest's failed-test summary,
  test and Python failures, CTest's phase warning, CMake errors, and last
  the gate words (drift, stale, missing). Within a tier the earliest line
  wins. Paths are stripped before matching, because ORE Studio has files
  named for failures (=trade-import-failed-state.org=, =*-model-drift.org=)
  that the site build lists while it publishes.
- Lines that only point at an error are skipped: =Process completed with
  exit code=, =Build completed with failures=, ninja's =FAILED:= line, and
  CTest's =Submission successful= that follows a =CMake Error=. Echoed
  commands, step markers, test timings and application log lines are skipped
  too.
- The ER parser (=plantuml_er_parse_sql.py=, run as =Validate SQL Schema=
  before the build) prints every warning; the reason keeps only the first.
  A run that broke several of its rules is counted under the first one.
- Gates are classified by their step name, which names the rule they
  enforce. That map is the gate classification of
  [[id:AFF665C4-739C-4BDB-93BD-9D547351AE4F][Investigation: ORE Studio gate classification]] and the rule table of
  compass at 14c5674.
- A failure counts against the head commit of its run. On push and
  schedule runs that is main's tip, usually a merge, so the commit that
  introduced the error is somewhere in what the merge brought in. Nearly
  every merge in the window brings in at least one LLM co-authored commit,
  so the LLM column says little on merges; it is sharper on pull-request
  heads.
- The fetch was restarted four times. Twice it was to change the trimming:
  the tail first ended at the last =##[error]=, which sits in the clean-up
  steps rather than the failing one, and the kept error lines were first
  the earliest 200 rather than those nearest the tail. Those restarts
  deleted the cached logs and kept the listings and job lists, which do
  not depend on the trimming. The other two added workers. =gh api= also
  needed =--allow-escape-sequences=, since the logs carry terminal colour
  codes and =gh= refuses to print them otherwise.

* Result

=build/scripts/mine_failed_builds.py= fetched every failed run of ORE
Studio's CI from 2026-09-19 to 2026-11-18, 2,889 runs and 4,774 failed
jobs, and classified 4,841 failures into 94 patterns, leaving 63
unclassified. The run-by-run record is
[[id:080067B0-D941-4D41-9388-24E39AD37E9C][Investigation: ORE Studio failed builds by day]], and the ranking, the
verdicts and the candidates for checks are in
[[id:6947B0D8-A1AE-4180-B2D9-D33FF02C1A3B][Investigation: ORE Studio failed build patterns]].

- Two runs in three, 1,925, failed on a rule a compass codec enforces
  today, mostly ORE Studio's generator gates. Running compass before the
  push stops them with no new check.
- 650 runs and 31,349 failed-job minutes failed on patterns a new check
  could catch. The five proposed for the next task are portable C++
  facilities, TypeScript formatting, a generated domain header's
  includes, site links and pasted blocks.
- 540 runs and 113,878 minutes, most of the cost, went to tests,
  time-outs, memory, compile errors and runners, which no check before a
  build predicts.
- Most catchable checks are a generic rule over a project-owned list;
  three would need ORE Studio's design in compass.
- The LLM trailer marks 86% of failing heads against 79% of all commits
  in the window, so it does not single out the failing changes.

The task's description also names fix-up commits, PR review comments
and memories. Its acceptance does not, and they were not mined.
