* Acceptance

- The store stays under its cap, and a run after eviction still produces correct output.

* Plan

- Use is decided by reachability, as git decides it, not by access times:
  the disk is mounted =noatime=, and stamping objects on every load would make
  a warm run write. An object is live when any worktree of the repository
  refers to its ID, through that worktree's git index or its compass worktree
  index. The worktrees come from the common directory's =worktrees/= entries
  plus the main worktree.
- Only unreferenced objects are candidates. They are removed oldest first, by
  modification time, until the store is under its size cap. Objects written in
  the last hour are never removed, so a run in progress cannot lose an object
  it just wrote.
- Removal deletes the object file; a concurrent reader that already mapped it
  keeps its mapping. A loader that finds an object missing parses again, so
  collection can never break correctness.
- =compass-bench gc <checkout> --store <dir> [--cap <bytes>] [--dry-run]=
  reports store size, live and unreferenced objects and bytes, what it would
  remove or removed, and the time taken.

* Result

- The store is collected by reachability: an object is live when any worktree
  of the repository refers to its ID through its git index or its compass
  worktree index. Access times are never used.
- Unreferenced objects older than the grace period (one hour by default) are
  removed oldest first until the store is under the cap; old temporary files
  are removed whatever the cap. A victim whose size or modification time
  changed after listing is skipped.
- An index that cannot be read stops the collection before anything is
  removed, so a repository with a split index never collects.
- A removed object is parsed again on the next run; a test proves the dumps
  match.
