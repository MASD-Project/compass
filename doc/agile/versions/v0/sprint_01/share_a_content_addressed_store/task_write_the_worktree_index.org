* Acceptance

- An unchanged file is resolved from stat data alone, with no read.

* Plan

- The worktree index records, for every file compass had to hash, its path,
  stat data and ID, so the next run resolves it from stat data alone. Files
  whose ID comes from git's index need no entry. It lives in the worktree's own
  git directory (=<gitdir>/compass/index=), never in the shared store, and is
  rewritten with a temporary file and a rename.
- The same clean rule as git applies: every stat field must match, and an
  entry written in the same second as the file's modification is not trusted.
- =compass-bench warm <checkout> --store <dir>= runs the pipeline end to end:
  resolve every org file's ID (git index, then the worktree index, then hash),
  load its object from the store, parse and write any that are missing, and
  update the worktree index. The first run is cold; the second, with nothing
  changed, must finish in under one second on ORE Studio. This is the story's
  warm-run acceptance.
