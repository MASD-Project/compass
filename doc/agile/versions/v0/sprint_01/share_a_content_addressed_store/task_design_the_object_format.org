* Acceptance

- Objects load by memory-mapping with no decode step, and a version mismatch forces a re-parse.

* Plan

- An object is one parsed document: a fixed header (magic, format version,
  parser version, the content's git blob ID, table offsets and row counts)
  followed by every =compass.org= column, aligned, as raw little-endian
  arrays. Loading is mapping the file and pointing spans at the columns; there
  is no decode step.
- The =compass.org= tables gain a read-only view type over spans, so code that
  reads tables works the same over freshly parsed vectors and over a mapped
  object.
- The store lives under the repository's git common directory, in
  =compass/objects/=, so every worktree shares it. Objects are written to a
  temporary file and renamed into place, and are never modified.
- Loose objects first, one file per blob ID. =compass-bench= gains a =store=
  stage that measures a cold run (parse and write every org file) and a warm
  run (map every object and verify its header), so whether packs are needed is
  decided by a number, not in advance.
- A header whose format or parser version differs from the running build is
  treated as missing, so a stale object forces a re-parse.

* Result

- An object is a 664-byte little-endian header (magic, byte-order mark, format
  and parser versions, the source's git blob ID, size, checksum, row counts and
  column offsets) followed by every =compass.org= column as a raw array aligned
  to 8 bytes, then the interned name bytes. Loading is mapping the file and
  pointing spans at the columns after a bounds check of every offset.
- Readers take =tables_view= over spans, whether the tables come from a parse
  or a mapped object; the old read signatures are gone.
- =compass.store= is a new infrastructure component: blob IDs computed the way
  git computes them, paths under =<git common dir>/compass/objects/=, and
  writes to a temporary file renamed into place. A stored object's name equals
  git's blob ID for the same file.
- Loose objects meet the warm budget: all of ORE Studio's org loads in about
  50 ms against 1 s, so packs are not needed.
- Format and parser versions are hand-bumped constants; a pinned checksum test
  names the version to bump when the stored form changes.
- Open for the next tasks: whether the read path always verifies the checksum,
  and that blob IDs from git's index differ from working-tree hashes under
  =autocrlf= or clean filters.
