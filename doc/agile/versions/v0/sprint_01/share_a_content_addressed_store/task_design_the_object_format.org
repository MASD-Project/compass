* Acceptance

- Objects load by memory-mapping with no decode step, and a version mismatch forces a re-parse.

* Plan

- An object is one parsed document: a fixed header (magic, format version,
  parser version, the content's git blob ID, table offsets and row counts)
  followed by every =compass.org= column, aligned, as raw little-endian
  arrays. Loading is mapping the file and pointing spans at the columns; there
  is no decode step.
- The =compass.org= tables gain a read-only view type over spans, so code that
  reads tables works the same over freshly parsed vectors and over a mapped
  object.
- The store lives under the repository's git common directory, in
  =compass/objects/=, so every worktree shares it. Objects are written to a
  temporary file and renamed into place, and are never modified.
- Loose objects first, one file per blob ID. =compass-bench= gains a =store=
  stage that measures a cold run (parse and write every org file) and a warm
  run (map every object and verify its header), so whether packs are needed is
  decided by a number, not in advance.
- A header whose format or parser version differs from the running build is
  treated as missing, so a stale object forces a re-parse.
