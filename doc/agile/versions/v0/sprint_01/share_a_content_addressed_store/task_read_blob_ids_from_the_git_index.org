* Acceptance

- The ID compass computes for any file equals git's blob ID for the same content.

* Plan

- =compass.store= reads git's index file directly (versions 2, 3 and 4,
  including path prefix compression in version 4), not through =git=
  subprocesses: path, stat data and blob ID per entry.
- A tracked file takes its blob ID from the index only when git would call it
  clean: its stat data matches the entry and the entry is not racily clean
  (modified in the same second the index was written). Otherwise compass hashes
  the working-tree bytes.
- The key must name the bytes compass parses. Git's blob ID names the bytes
  after line-ending conversion and clean filters, so when =core.autocrlf=, an
  =eol= or =text= attribute, or a =filter= attribute applies, compass hashes the
  working-tree bytes instead. Detecting this conservatively is enough: any
  =.gitattributes= that sets =eol=, =text= or =filter= for a path sends that
  path to hashing.
- =compass-bench= gains an =ids= stage that reports, for a checkout, how many
  IDs came from the index and how many were hashed, how long each took, and
  that every ID equals =git hash-object= on a sample.
