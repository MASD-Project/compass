* Acceptance

- compass.bench calls the same pipeline the CLI runs and adds only timing.

* Plan

- A behaviour-preserving refactor. The pipeline steps (list, resolve, load or
  parse, registry, run codecs, sink or diff, collect) live once, in
  =compass.cli='s library, as functions the commands call.
- =compass.bench='s stages that host the pipeline (warm, codecs, gc, models)
  call those functions and add only timing and repetition; their copies of the
  loading code are deleted. Stages that measure one primitive in isolation
  (read, includes, parse, org, ids, store) keep calling the primitive.
- The bench may time a step only if the library exposes it as a step, so the
  library exposes the steps the bench times, not one opaque run function.
- Every existing test passes unchanged, and each moved stage's output on this
  repository is the same before and after, apart from its timings.

* Result

- The pipeline lives once, as steps in =compass.cli='s =app/steps.hpp=:
  =list=, =build_type_registry=, =open_files=, =resolve=, =load=,
  =corpus_of=, =read_dependency_record=, =run_codecs=, =store_objects=,
  =write_worktree_index=, =store_results=, =write_dependency_record=,
  =write_outputs=, =plan_outputs= and =collect=. The commands are built from
  them.
- The bench's =warm=, =codecs= and =gc= stages call those steps and add only
  timing; =compass.bench= lost a net 245 lines. The stages that measure one
  primitive (=read=, =includes=, =parse=, =org=, =types=, =store=, =ids=,
  =models=) call it directly.
- The refactor preserved behaviour: 22 baseline runs gave 43 output files
  identical apart from timings. One deliberate change followed: the hosting
  stages now skip =.compass.org= as the CLI does, so both read 410 files on
  this repository.
