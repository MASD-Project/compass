* Goal

A project states, as a check document, that none of its C++ types holds
more than a ceiling of data members. The types already over it are listed
with their counts, and those counts only come down. The product owner set
the first such check on 2026-11-19: no struct over fifteen fields, as a
matter of data-oriented design, apart from MSVC's limits.

* Acceptance

- A check document with =:ENGINE: limit= and =:FACT: cpp_fields= reports
  each class, struct or union with more non-static data members than its
  =CEILING=, at the type's key.
- A type its =* Ceilings= table records may reach its recorded count and
  no more; a recorded count its type no longer reaches is reported on its
  row, so the table only comes down.
- Over ORE Studio's main, the check with every type over fifteen recorded
  is quiet, and growing a recorded type, shrinking one, and adding a new
  wide type each raise the finding that says so.
- A check whose drawer says =:SEVERITY: warning= reports its findings as
  warnings and fails no command, so the wide types check gives visibility
  without gating, as the product owner asked.

* Plan

- =compass.cpp/ops/type_widths=: each named class, struct and union of a
  lexed source, at any scope, with its non-static data members counted
  one per declarator. Functions, constructors and their initialisers,
  static members, aliases, friends, nested types and Qt's macros and
  access labels do not count. The tokenizer moves from the source model to
  the lexer so both read the same tokens.
- =compass.cpp/ops/limit=: the definition (=FILES=, =OUTSIDE=, =FACT=,
  =CEILING=, one =RECORDED= per row of =* Ceilings=), a per-file fact of
  the types over the ceiling, and the findings over all files:
  =over_ceiling= and =below_record=, the rules of
  =translation_unit_budget='s ratchet.
- =compass.cpp/codecs/limit=: the scan function, a map per file and a
  reduce over them, so a run re-reads only the changed files.
- The check loader accepts =:ENGINE: limit= and reads =* Ceilings= into
  the definition, so editing a row re-runs the check and editing prose
  does not.
- =SEVERITY= in any check's Definition drawer: the descriptor carries the
  severity, every finding of a warning check is a warning, and =check=,
  =ratchet= and the edit hook fail or block only on errors.

  =workflow_plan_step= (17).
- The rows are keyed by path and type name, so moving a file needs its row
  moved; a type defined twice in one file under one name is measured by its
  widest definition.
- Generated types (entities, protocols, =xml/generated=) are most of the
  598. They are listed like the rest: their width comes from the model, and
  the fix is in the model.

* Result

The limit engine runs from a check document. On ORE Studio's main, with
the 598 types over fifteen recorded, the check is quiet; with one recorded
type grown by a field it reports =over_ceiling= against its recorded count,
with one shrunk to fifteen it reports =below_record= on its row, and with a
new sixteen-field struct it reports =over_ceiling= against the ceiling.
With =:SEVERITY: warning= those findings are printed as warnings and the
command exits 0.
