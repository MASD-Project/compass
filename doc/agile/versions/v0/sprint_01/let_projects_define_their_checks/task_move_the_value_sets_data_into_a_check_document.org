* Goal

=ore_value_sets= and =parameter_value_sets= read the curation they used to
parse out of six ORE Studio Python modules under =projects/ores.sql/utility/=
(=convention_value_sets.py=, =curve_value_sets.py=, =ore_aliases.py=,
=ore_schema_types.py=, =generate_ore_element_map.py= and
=generate_convention_kind_terms.py=) from one check document instead, so ORE
Studio can retire those modules and a refactor of them cannot break or
mislead the codecs. The generated files do not change.

* Acceptance

- Neither codec reads any of the six modules; every name they parsed is a
  table of one check document, or stays compass code where it is machinery.
- One document gives both codecs their data: its =:CODEC:= names both, so
  the generator and the gate resolve one copy.
- A missing document, table or column, or a cell that does not read, is an
  =unreadable= finding of =parameter_value_sets= and a refusal of
  =ore_value_sets=, naming the document and line.
- On ORE Studio's main, compass-ng v0.0.4 reading the Python and this build
  reading the document report the same findings and the same =diff=, also
  with the same data damaged on both sides.

* Plan

- *One document for two codecs.* Both codecs run =ops::value_sets::evaluate=
  over the same curation, so two documents would be two copies that could
  drift. The compiler is extended instead: =:CODEC:= takes several codec
  names, separated by spaces, and compass sets the same =data= option on
  each. An exception of such a document names =<codec>/<rule>=; with one
  codec it names the rule alone, as before. A codec still has at most one
  document.
- *Tables at the boundary.* =ops::value_sets::read_tables= checks every
  table and column (27 tables, 8 of them for the convention kind terms,
  which =ops::convention_terms_tables= names) and the cells that must read
  (=is_ordered= yes or no, the count a whole number, one row in the three
  one-value tables, a family convention or curve, a term in each override).
  The resolution then builds the values it used to parse from the tables,
  so the code behind it is unchanged.
- *Shared names.* =CATALOGUES= and =SCHEMA_TYPE_SETS= were stated alike in
  two modules, so each is one table; both =TYPE_SETS= are one table with a
  family column; =SCHEMA_WORDS= and =SCHEMA_NAMES= share keys, so one table.
  =TYPE_OVERRIDE='s mixed key becomes =element= and =term= columns, an empty
  element meaning every convention. =None= in =ITEM_WORDS= and in a
  =LIST_ITEM= kind is an empty cell.
- *Code that stays code.* The mapper regular expressions of
  =generate_convention_kind_terms.py= (=FUNCTION=, =DECLARED=, =ALIAS=,
  =CHILD=, =READ=, =PACK=), the curve module's =OWN_SETS=, whose date
  pattern calls the schema reader, and the schema walk of
  =ore_schema_types.py= were already compass code and stay so.
- *Deleted.* =ops::module_table= and =ops::json_of=, whose only caller was
  this codec.
- *ORE Studio's document* is generated from the Python with =ast= by
  =value_sets_doc.py=, which refuses to write when the shared tables
  disagree, so no value is retyped.
