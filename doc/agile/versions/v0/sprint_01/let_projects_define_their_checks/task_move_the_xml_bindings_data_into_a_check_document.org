* Goal

=xml_bindings= generates the XML bindings of any project from that project's
own schemas and its check document =compass/checks/xml_bindings.org=. The
codec held ORE Studio's family table, its paths, its namespace, its engine
and decimal headers, its export macro and its schema errata; now the check
document states all of them, so adding a money member to the exact decimals
is an edit and a regeneration in ORE Studio, not a compass release. The
banner of each generated file names compass and the family's schemas, not
=generate_xml_bindings.py=, which ORE Studio is deleting.

* Acceptance

- The sources of =xml_bindings= name no ORE family, no =ores::= namespace,
  no =projects/ores.ore= path and no =external/ore/xsd=.
- On ORE Studio's tree, with its check document, =compass check --codec
  xml_bindings= reports only the banner drift, and after =compass generate=
  each of the 26 generated files differs from the committed one only in its
  banner lines.
- An exact-decimal row added to the document changes the generated member
  and row; a family row taken out stops its files being generated.
- A missing document, table, column or setting is an =unreadable= finding
  and writes nothing; a family whose schemas are missing still refuses.
- A test generates the bindings of a made-up project, with its own schemas,
  namespace, directories, engine, decimal type, export macro and erratum.

* Plan

- Four tables: =Families= (stem, root element, root type, schemas, a
  space-separated list), =Exact decimals= (family, element; =*= for every
  real), =Schema errata= (written, read; was =SCHEMA_ERRATA=) and =Settings=
  (setting, value).
- The per-project settings are a key-value table, not codec options: they
  describe the project as the families do, so one page states everything
  the bindings come from, and an edit reruns the codec as any table edit
  does. Nine settings: =schema_directory=, =header_directory=,
  =source_directory=, =include_prefix=, =namespace_prefix=,
  =engine_include=, =decimal_include=, =decimal_type= and =export_macro=
  (which may be empty). =clang_format= and =clang_format_style= stay
  options, being the tooling, not the project.
- Derivations stay in the codec: accessor =<stem>_document=, namespace
  =<namespace_prefix>::<stem>=, include =<include_prefix>/<stem>.hpp=,
  files =<stem>.hpp= and =<stem>.cpp=. The include guard is now derived
  from the include path (upper case, other characters underscores), which
  reproduces ORE Studio's guards.
- =ops::xml_bindings::generate= takes a =project= with the engine and
  decimal headers, the decimal type, the export macro and the errata, and
  each family's schema names for the banner, which wraps at 80 columns:
  "Generated by compass from <schemas>; regenerate with compass generate."
- ORE Studio's document is generated from =regenerate_xml_bindings.sh= and
  =generate_xml_bindings.py= by a script that parses them and stops if a
  family breaks a derivation rule; the script's comments become the notes
  under the Families table. ORE Studio's =.compass.org= row is unchanged:
  =| xml_bindings | yes | clang_format=clang-format |=.
