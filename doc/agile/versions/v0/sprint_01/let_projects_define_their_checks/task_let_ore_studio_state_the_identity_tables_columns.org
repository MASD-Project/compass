* Goal

ORE Studio adds a context column to its market series identity table
(=provider_code=, on its branch
=feature/two-providers-of-one-fixing-collide-in-the-identity-table=) and
declares it in its own =.compass.org=, with no new compass build.
=marketdata_identity_columns= hard-coded the table's seven context columns
and the seven columns every asset class view exposes, so the change failed
the check with no way to state it.

* Acceptance

- =context_columns= and =view_columns= are options of the codec,
  comma-separated, defaulting to the lists it hard-coded, so a project
  with no setting sees no change.
- A table column the options do not name is still reported, and its fix
  says to add it to =context_columns=.
- On ORE Studio's branch, the check reports =provider_code= with no setting
  and passes with it in =context_columns=.

* Plan

- Turn the two =constexpr= arrays into options, the route the analysis
  recommends for a schema fact (=could be data=): the project's codec table
  holds =key=value= options, so ORE Studio edits its own file.
- Bump the codec's version: the result depends on the options now.
- Leave the paths and the table name for the sweep that follows: they are
  the same kind of fact, and the analysis lists 382 such items over the
  ported codecs.
