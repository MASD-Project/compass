* Goal

ORE Studio moves its ORE metamodel entities from =ores.reporting= to
=ores.ore=, which renames their tables from =ores_reporting_*= to
=ores_ore_*= and may drop the =ore_= prefix of the entity names. compass
built those names in: the six value set tables, the =value_in_set= and
=canonical_value= functions the term and curve column validators call, the
three seed paths under =populate/reporting/= and the =ores_reporting_service=
writer. This task makes =ore_value_sets=, =parameter_value_sets= and
=curve_sections_wiring= take them from ORE Studio's entity models, which a
table of its check document names by role, so the move is a change of
ORE Studio's models and data alone.

* Acceptance

- No value set table, function, seed path or writer name is a string of
  compass's code; each comes from the model of the entity the check
  document's =Value set entities= table names for its role.
- With ORE Studio's current models and that table, =compass diff= changes
  no generated SQL file.
- Moving the models to =projects/ores.ore/modeling/=, with or without the
  =ore_= prefix, moves the seeds and renames the tables, writer and
  functions.
- A role with no row, or an entity with no model, is =unreadable=; a model
  moved or added after a run reruns the codecs from the cache.

* Plan

- *Roles in data, names in models.* A =Value set entities= table of
  =compass/checks/value_sets.org= maps each role (=vocabulary=,
  =element_map_column=, =value_set=, =value_set_value=,
  =value_set_catalogue=, =setting_value_set=) to an entity name.
  =ops::value_sets::read_storage= finds the entity's one model,
  =<anything>.<entity>.org= under a =modeling/= directory, by a listing the
  cache records, and reads =:product:=, =#+component:=, the first
  =:tablename:= and =#+entity_plural:= (=compass.model='s
  =entity_claim_of=, which derives the plural as code generation does).
  The first =:tablename:= and not the one in =* Flags=: two of ORE
  Studio's six models state it only under =* SQL= / =** Flags=.
- *Derived names.* A seed goes to
  =projects/<product>.sql/populate/<component>/<component>_<plural>_populate.sql=,
  the layout code generation's =#+output:= templates give an entity's
  create scripts; it stamps =<product>_<component>_service=; the
  validators call =<product>_<component>_value_in_set_fn= and
  =_canonical_value_fn= of the value set entity's component. The product
  prefix is the model's =:product:= flag, so it is data already and needs
  no setting before [[id:65C91AED-EE91-4730-94B0-598248F5921D][Name the product root]].
- *The curve guard too.* =curve_sections_wiring= writes the curve column
  validator, which joins the same tables and calls the same functions, so
  it reads the same table: ORE Studio names it in the document's =:CODEC:=.
  Without the table it refuses the guard alone.
- =curve_parameter_paths= shares none of these names; its artefact is
  already an option.
