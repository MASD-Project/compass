A point-in-time record of an [[id:A7F8D9E2-3C4B-4A5D-B67C-8E9F0A1B2C3D][investigation]] into what compass's codecs
assume about ORE Studio. It is evidence for the
[[id:6E3237E7-C57A-4CD8-97D5-DA32BAA4359E][Analyse what is hard-coded to ORE Studio]] task and was written on
2026-11-18, at compass =01415b5= and ORE Studio =cdec0a1daa=.

It is a snapshot, not a description of the system. The design that acts
on it is [[id:225B524C-1638-4A03-B02F-66EB6759619D][Design: literate project checks]].

* Context

compass's first and only client is ORE Studio, and its codecs grew from
ORE Studio's Python gates. Many of them carry ORE Studio's paths, names,
type lists, patterns, thresholds and conventions as C++ literals or as
option defaults. The product owner wants each project to state these as
data in its own checkout, so a second project can add or tune a check
without changing compass. This page counts what there is to move, and
says which parts should not move at all.

* Methodology

- The registry. =compass check --timings= over an ORE Studio export lists
  the units of every registered codec: 71 codecs from 67 source files.
  =registrars.cpp=, =shell.cpp=, =value_sets.cpp=, =recipe_libraries.cpp=,
  =skill_tables.cpp= and =tree_gates.cpp= register more than one, and
  =rule_table= is registered in =compass.cli=.
- The readers. Five readers, one per component group, read every codec
  source in full, and the =ops/= files those codecs call where they hold
  ORE literals. They worked to one rubric and wrote one row per specific
  with its =file:line=, its kind, its class and the reason. A script
  then opened every cited line: all 527 exist, and in 426 the first
  quoted literal sits within three lines of it. The other 101 describe a
  shape rather than quote a literal (=projects/<c>/core/src/CMakeLists.txt=,
  for example); eight of those were read by hand and point at the right
  line.
- The classes.
  - /data/: the value already comes from the project: an option it sets,
    a table of =.compass.org=, a =doc/meta= contract, or a file in its
    checkout that the codec reads.
  - /ORE default/: an option exists, but its default is ORE Studio's
    value, so ORE Studio gets it without stating it.
  - /could be data/: a C++ literal whose check stays the same when
    another project states a different value.
  - /stays code/: a parser of ORE Studio's own source or grammar, or an
    algorithm ported from one of its scripts. Stating it as data would
    need a language.
- The nature of a codec.
  - /generic/: any project could run it as it is.
  - /parameterised/: generic logic over ORE values.
  - /ORE's design/: the codec encodes ORE Studio's architecture, schema,
    templates or domain.
- ORE Studio's effective settings. =compass config= over the export of
  =refs/remotes/origin/main= of =ores.git=, with the compass build
  =49f02e9=.

* Paths taken

The export needed a =git init= first: =compass check= lists files with
=git ls-files= and stops outside a repository. The ORE Studio export was
deleted when the task closed.

- Already data. 54 specifics: 15 that the project states, and 39 option
  defaults that are ORE Studio's values. ORE Studio's =.compass.org=
  states 12 option values itself; =compass config= shows 46 more
  that ORE Studio takes from compass's defaults without stating them.
- Could be data. 381 specifics. Only 197 of them sit in parameterised
  codecs, where moving them lets another project run the codec. The
  other 178 sit in codecs of ORE's design: making them options leaves a
  codec only ORE Studio can use, with a longer configuration.
- Stays code. 92 specifics, 72 of them in codecs of ORE's design.

** What stays code, and why data would be worse

- Parsers of ORE Studio's own source. =curve_wiring.cpp= reads ORE's C++
  projection by regex, =route_inventory= reads its TypeScript registry by
  indentation, =marketdata_identity_columns= reads its C++ schema DSL,
  its projector and its view SQL, and =skill_type_tables= reads its
  Python CLI. Each regex means something only beside the algorithm that
  uses it.
- Ported algorithms. The convention variant rules and their MD5 pins in
  =conventions_coverage=, the commodity decoders in =conventions_dataset=
  and the value-set generators are ORE Studio's Python, translated.
- Grammars. The NATS subject grammar of =model_rules= and
  =stream_coverage=, the tenant widening shape of =rls_widenings= and the
  guard shape of =populate_refs= have special cases a pattern language
  would have to grow to state.
- Third-party APIs. The cli library's menu quirk in =shell_menus=,
  Catch2's macros in =test_case_reachability= and Boost.Config's symbol
  macros in =exported_types= describe a library, not ORE Studio. A list
  option would pretend another framework works; it needs another reader.
- Generated text that mirrors a generator. =bff_list_requests= and
  =stream_coverage= restate the naming ORE's own generators use. Making
  that a template adds a second source to drift; comparing against the
  generator's output is better.

** Repeated literals

Several literals recur across codecs, each slightly different. Each is
one project-level setting rather than an option per codec:

- the product prefix =ores= (=projects/ores.<c>=, =ores_*_tbl=, =ores::=):
  string literals that name it sit on 395 lines of 78 codec and ops
  sources, 45 of them codec sources;
- the skipped directories (=node_modules=, =venv=, =build=, =external=),
  listed in 8 sources, in at least six variants;
- the =AUTO-GENERATED FILE= marker, in three codecs;
- the SQL root and its entry points, feeding three codecs;
- =doc/llm/skills/=, feeding four codecs.

** Rule provenance

Rules cite the ORE Studio memories they enforce by ID (=enforces= of
=types::rule=), so compass's binary carries IDs that resolve only in ORE
Studio's tree. Provenance belongs with the rule in the project: a
check document's =* Why= links it.

** Families

Each codec's primary family, from the per-codec table below. A codec
that fits two names both there; this counts the first.

| Family                                                      | Codecs | Examples                                              |
|-------------------------------------------------------------+--------+-------------------------------------------------------|
| F1 forbidden pattern: a pattern in files outside allowed paths |      3 | =portable_stop=, =no_pr_triggers=, =template_sections= |
| F2 inventory: a table or listing agrees with files on disk  |      7 | =prototypes=, =protocol_twins=, =xml_family_census=   |
| F3 generator: the output matches what the generator writes  |     23 | =codegen=, =er_diagram=, =recipe_inventories=         |
| F4 reference: a name or link resolves to a definition       |      9 | =handler_permissions=, =sql_reachability=, =lint=     |
| F5 org rule: a rule over org tables, headings or model fields |      7 | =required_sections=, =heading_numbers=, =model_rules= |
| F6 code facts: a rule over C++ or SQL facts                 |     20 | =core_link_edges=, =rls_coverage=, =unity_collisions= |
| F7 other                                                    |      2 | =skill_namespace= (a naming rule), =parameter_value_sets= |

F1, F2 and F4 are the families a definition can mostly state: a glob, a
pattern over facts compass already parses, and a message. The
exceptions are inventories and references that go through a parser of
the project's own grammar. F3 stays code
by nature, and its data (templates, outputs) is already the project's
or is a path. F5 is mostly data already: the =doc/meta= contracts. F6
splits: a threshold or a forbidden fact is data; a rule that needs
cross-file resolution is code.

codec alone. The 6.9 s warm floor is the runner's own (listing, the
dependency record), not the codecs'.

* Recommendations

- Move the 39 ORE defaults into ORE Studio's configuration first, and
  empty compass's defaults. It needs no new format and proves the
  layering.
- Turn the 197 could-be-data specifics of parameterised codecs into
  data; leave the 178 in codecs of ORE's design until their codecs'
  home is decided.
- Do not make the ORE-design codecs configurable for its own sake. Decide
  whether they stay in compass, move to an ORE Studio component of
  compass, or leave it.
- Add the five repeated literals as project-level settings before any
  codec option that would restate them.
