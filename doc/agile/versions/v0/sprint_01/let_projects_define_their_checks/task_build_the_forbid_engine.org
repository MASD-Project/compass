* Acceptance

- A definition states its files, the files it leaves out, and rules of
  CPP_NAME, CPP_INCLUDE, CPP_TEXT and TEXT, each with a message and a fix.
- A definition that cannot run says on which line and why.
- The engine reports what portable_stop reports, under the stop types rule
  of the portable C++ check, and each example of that check in the design
  fires or stays quiet as the design says.
- A run after an edit scans only the edited files.
- A document under =compass/checks/= runs as a codec named for its file,
  its exceptions table excuses its findings, and a broken document fails
  the command with its line.
- Editing a check's prose runs nothing again; editing its definition runs
  it again.
- The portable C++ check reports the line that broke ORE Studio's build
  at =1961f78f1a= and is quiet on that rule at the fix, =1e07397b28=.

* Plan

The design's =forbid= engine, built in slices so each lands tested:

1. This task. The engine in =compass.cpp=: =ops/forbid= parses a
   definition and scans one file, and =codecs/forbid= is the scan function
   every forbid check shares. A check is a descriptor of its own whose one
   option, =definition=, holds the definition's text. That text is also
   the check's cache key, so editing a check re-runs it alone.
2. Load =compass/checks/*.org=: turn each document's =Definition= drawers
   into the definition text, build one descriptor per check, and split
   the =Exceptions= table under it.
3. Run each check's =Examples= blocks as its tests.
4. ORE Studio writes =compass/checks/portable_cpp.org=, and compass deletes
   =portable_stop=.

The definition text is one =KEY value= per line, the drawer keys of the
design, with =RULE <name>= opening each rule. A drawer maps onto it line
for line, so slice 2 needs no second grammar.

* Notes

- A trailing =**= in a glob means every file under its directory. The
  shared =glob_matches= follows pathlib, where a last =**= matches
  directories only, so =OUTSIDE projects/ores.platform/**= would have left
  out nothing.
- Slice 2 proof. The two =atomic_shared_ptr= findings at =1961f78f1a=
  are =auth_handler.hpp:711= and =account_operations_handler.hpp:1089=,
  the =token_settings_= members macOS failed on; the third match, in a
  comment of =crm_ingest_bridge.hpp=, is quiet. The two findings on both
  commits are ORE Studio's to judge when it adopts the check:
  =std::getenv= in =xml_example_coverage_tests.cpp:56=, and =<unistd.h>=
  in =systemd_notify_tests.cpp:43= under
  =#if defined(BOOST_ASIO_HAS_LOCAL_SOCKETS)=. The engine reads only
  =#if 0= as dead, so the second is a false positive that wants an
  exception row.
- The design's worked examples put a sentence of prose before each
  drawer. Org reads a property drawer only on the line right under its
  heading, so the examples now put the drawer first.
- =check --commit= reads the check documents of the commit, and the
  working tree's when the commit has none, with a warning, as it does
  for =.compass.org=. That is how today's checks judge an old commit.
- Not yet done: =compass config= lists only the built-in codecs, and
  =rule_table= does not list a check's rules. The three document types
  and their contracts come with the configuration reader.
- =#include= inside =#if 0= needs no filter of its own: the source model
  already drops it. A mutation that removed such a filter changed no test
  result, so the filter went.
