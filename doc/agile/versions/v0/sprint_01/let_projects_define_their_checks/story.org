* Goal

A project adopting compass writes its own checks as data in its checkout,
the way ORE Studio's specifics would be written, and compass runs them with
the same speed, caching and exception handling as its built-in codecs.

* Acceptance

- Every ORE Studio specific in compass's codecs (paths, names, type lists,
  patterns, thresholds, document contracts) is classified as already data,
  could be data, or must stay code.
- A data format for project-defined checks is chosen, with its reasons and
  the alternatives weighed: rows in =.compass.org=, rule files, patterns over
  compass's parsed models (org tables, C++ and SQL facts), tree-sitter queries.
- ORE Studio's specifics that could be data move into ORE Studio's checkout,
  and compass checks ORE Studio with the same verdicts.
- A second project defines a check of its own without changing compass.
