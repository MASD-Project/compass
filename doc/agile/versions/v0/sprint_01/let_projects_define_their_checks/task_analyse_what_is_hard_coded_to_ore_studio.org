check would look like, before any of it moves.

* Acceptance

- A table lists every codec and the ORE Studio specifics it holds, each
  classified as already data (an option or table in =.compass.org=), could be
  data, or must stay code, with the reason.
- The patterns from Mine failed builds that compass could catch are checked
  against the proposed format: each is written in it, or the gap is named.
- A recommended format, with worked examples of three existing checks
  rewritten in it, and the cost to compass's speed and caching.

* Plan

- Inventory. Five readers, one per group of components, read every
  codec's source against one rubric and wrote a row per ORE Studio
  specific with its =file:line=. A script checked every cited line, and
  another renders the rows as the investigation's tables.
- ORE Studio's settings. Export =origin/main= of =ores.git= into the
  scratchpad, run =compass config= and =compass check --timings= there,
  and delete the export at the end.
- Design. The product owner fixed the format mid-task: literate org in a
  committed =compass/= directory. The design works inside that decision:
  where the definition sits, the type contracts, exceptions, examples as
  tests, the cache key, the layout and the migration. The comparison of
  TOML, YAML, rule files and tree-sitter was dropped.

  lists files with =git ls-files=.

* Result

The Acceptance is met:

- The table of every codec and its specifics is
  [[id:5C4E5883-CBA5-4018-9A65-1CFD276AF198][Investigation: what compass hard-codes to ORE Studio]]: 71 codecs and
  527 specifics, each with its =file:line=, class and reason. 54 are
  already data (39 of them only as compass defaults that are ORE Studio's
  values), 381 could be data, and 92 stay code.
- The five mined candidates are checked against the format in
  [[id:225B524C-1638-4A03-B02F-66EB6759619D][Design: literate project checks]]. Portable C++ facilities is written
  in full, apart from two facilities that need a C++ type fact. The
  domain header includes need one parameter, =THROUGH=. TypeScript
  formatting needs a =format= engine, which runs an external tool. Site
  links and pasted blocks stay code.
- The format is the product owner's: literate org documents in a
  committed =compass/= directory. The design gives the definition's
  place (property drawers), the type contracts, per-check exceptions,
  examples as tests, a cache key that ignores prose, and the migration.
  Its worked examples are ORE Studio's readme, configuration and local
  settings, the mined portable C++ check, and =handler_permissions=
  rewritten. The cost: a check is keyed like a codec's options, and a
  changed option re-ran one codec in 100 ms (measured). A regular
  expression with no literal to prefilter on may cost a full pass over
  its files (a guess).
