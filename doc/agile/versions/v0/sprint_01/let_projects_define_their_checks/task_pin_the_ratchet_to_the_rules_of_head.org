* Goal

=compass check --ratchet= asks one question: what did this change make
worse, under the rules as they now stand. The product owner decided on
2026-11-22 that the merge base is judged by HEAD's rules. A pull request
that adopts a check, such as ORE Studio's =knowledge_titles= document,
then passes, and a page added later with a sentence title fails.

The rules are HEAD's =.compass.org= and every check document of
=compass/checks/=: a forbid or limit check, and a document whose
=:CODEC:= gives a built-in codec its tables.

* Acceptance

- Over files that already break it, a commit that adds a check document
  reports no new diagnostic.
- A violation added in the same commit is new.
- A rule added to a check document reports no new diagnostic on old files.
- A renamed check document reports no new diagnostic under its new name.
- An exception removed from a check document leaves its finding old, not
  new.
- Each of these tests fails when the merge base is checked under its own
  check documents and exceptions.

* Plan

The plan was an overlay in the commit reader: replace the rule files of
the merge base with HEAD's before the base is checked. Reading the code
first showed it is not needed.

=options_of= (=app/application.cpp=) reads the configuration, the check
documents and both exception tables once, from the working tree, when
=--commit= is not given. =--ratchet= cannot be combined with =--commit=.
=ratchet= (=app/pipeline.cpp=) copies those options for the merge base
and sets only =commit=. So the merge base already runs with HEAD's:

- enabled codecs and their options, from =.compass.org=;
- check codecs, whose definition is built from HEAD's document;
- data tables, which reach a codec as the value of its =data= option and
  which =tables_for= reads from that value, never from the corpus;
- exceptions table of =.compass.org= and the exceptions tables of the
  check documents.

What the merge base reads from its own commit is its files: the documents,
the sources, and the exception comments in them, which are part of the
file and move with it.

The task adds the tests and states the rule in the recipes. No code
changes.

* Notes

- The four =tangle/names_missing_file= diagnostics are new on every
  ratchet, whatever the change. =check_in= computes them only for a
  checkout (=names_missing_of=), never for a commit, so the merge base
  never has them to excuse. That is a separate defect.
- A codec whose outputs are check documents writes them from HEAD's rules
  on both sides; the merge base's copy of a check document is a file like
  any other and never a rule.
- A check document present only at the merge base gives no rule; one
  present only at HEAD gives its rule to both sides.
- Removing an exception at HEAD leaves the finding old. The ratchet asks
  what the change made worse. The code did not change, so nothing is
  worse; the plain check reports the finding again, as it reports the
  findings of a newly enabled gate.
- An option of =.compass.org= that names a path absent at the merge base
  makes its codec report =unreadable= there. That diagnostic excuses only
  the same diagnostic at HEAD, matched by file, rule and message, so it
  hides nothing HEAD reports otherwise.
- The result cache keys a unit by its codec's option values and its input
  files, so the merge base's results under HEAD's rules are never confused
  with results under other rules.
- =commit_provenance= and blame read the commits of the branch and HEAD's
  findings, and this task does not touch them.
