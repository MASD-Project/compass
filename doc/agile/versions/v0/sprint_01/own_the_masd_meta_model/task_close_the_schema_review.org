* Goal

The review of #196 found that the safety net around compass's generated schema proves less than it claims. Close its should-fix findings and the nits that cost little, so a model edited without regeneration, a migration that fails on real data, or one that loses retained rows fails CI.

* Acceptance

- CI runs the built compass on the checkout and fails on generated drift and new diagnostics.
- check --ratchet reports a codec the merge base cannot run instead of exiting 2.
- The catalog comparison sees every kind of object a migration can make, each proven by a probe.
- The migrations since the last release are tested on a database that holds rows, and lose no retained row or column without a recorded decision.
- The freeze test notices a removed released migration and pins bookkeeping_sql().

* Plan

One change per finding of the review of
[[https://github.com/MASD-Project/compass/pull/196][#196]].

- *CI gate (1).* The release build of Continuous Linux runs the compass it
  built on a pull request's checkout: =check --ratchet HEAD^1 --no-blame=,
  whose merge commit's first parent is main as merged, with
  =document_index= off because its output is not committed. A push or a
  scheduled run skips it: main holds 70 findings that only a base
  excuses, and changes only through pull requests. The relevance guard now
  builds a change to a =modeling/= directory, =share/= or =.compass.org=,
  which it used to skip as documentation; those are what compass
  generates from.
- *Ratchet past a codec the base cannot run (2).* A codec that throws in a
  run now throws =codec_failure=, which names it. =check --ratchet= checks
  the merge base again with that codec off and prints that it did not run
  there. Its findings at HEAD are all new: nothing at the base can excuse
  them, and the change that makes a codec runnable owns what it reports.
  The usual case, a library added with its outputs generated, has no
  findings, so it passes.
- *Catalog comparison (4).* The catalog adds collations, triggers,
  policies and row security, persistence and storage parameters,
  privileges of schemas, relations, columns, functions and types, default
  privileges, sequence options, types with enum labels, comments, view
  definitions, the columns of every kind of relation, extensions and the
  rows of every table but =compass.migration=. A probe test builds
  =schema.sql= with and without each kind of object and requires the
  catalogs to differ.
- *Rows (5) and retained tables (6).* A database is taken to the last
  release the way it migrated, through the released migrations, and given
  one row in every table, every column filled. The migrations since then
  must apply to it. Each table the release retains, pinned in the test as
  =released_retained=, must keep every row and every column with its type
  and collation, unless =allowed_losses= names the column with the :ID: of
  the document that decides the loss. The allowance is a list in the test,
  not a marker in the migration: the check lives there, the edit shows in
  the pull request's diff, and a released migration cannot be edited to
  add or remove one.
- *Freeze (7).* The freeze test looks up every released version and
  requires it, and pins the blob ID of =bookkeeping_sql()= as v0.0.13
  shipped it.
- *Nits.* 3: =origin()= gets the checkout root and names the library that
  holds the template. 11: a generated enum is over =std::uint8_t=. 12 and
  15: =copy_writer::field(bool)= and one case per overload. 13: the
  generated =step_outcome_of= in =compass.bench=, one integer parser in
  =corpus.cpp=. 14: the stale profile and =tsv= prose.
