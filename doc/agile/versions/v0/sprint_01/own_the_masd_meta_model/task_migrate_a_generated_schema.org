* Goal

compass's database holds test activity that must survive an upgrade,
so it cannot be recreated as ORE Studio's is. Keep hand-written migrations,
frozen once released, beside the generated schema; test that both build the
same catalog; and report a change to a retained table that has no migration.
[[id:7FD52505-1436-4925-A1DE-4A3EC88F0133][Investigation: How compass generates itself]] gives the reasons.

* Acceptance

- A database test compares the catalog of every migration applied with the generated schema's.
- A model change without its migration fails the test.
- Lands before the first release that creates a database.

* Plan

The safety net is three tests in =projects/compass.db/tests/ops_migrations_tests.cpp=,
which run in the throwaway cluster every database test of =compass.db= uses.

- *The catalog comparison.* One database gets the bookkeeping SQL and every
  migration, through =io::migrate=; another gets the bookkeeping SQL and the
  generated =sql/schema.sql=. Each catalog becomes a set of lines: schemas,
  relations, columns in their order with type, nullability, identity,
  generation and default, constraints, indexes and functions. The sets must
  be equal; a failure prints the lines only one side builds.
- *The retained-table check.* =schema.sql= says above each table of the
  profile =activity-record= that it is retained. For each, every column the
  migrations build must be in =schema.sql='s table with the same type; a
  failure names the table and the column and says to add the migration that
  says what becomes of it.
- *Frozen migrations.* Each released migration is pinned by the blob ID of
  its SQL. Editing migration 1 or 2 to absorb a model change fails, so the
  only way to make the catalogs agree again is a new migration.

Migrations stay where #176 put them, the SQL texts of
=projects/compass.db/src/ops/migrations.cpp=, unchanged. Moving them to
=.sql= files would rewrite the text of two released migrations for no gain
in safety.

*Was a v0.0.13 database created?* compass 0.0.13 is released and installed
on this machine (=~/.local/opt/compass=). =compass db init= records its
connection in =<git dir>/compass/local.org=; no such file exists under
=/home/marco=, so no checkout here, compass's or ORE Studio's worktrees,
has a database. Other machines and ORE Studio's environments elsewhere could
not be checked, so migrations 1 and 2 are treated as released and frozen,
and migration 1 is not replaced.
