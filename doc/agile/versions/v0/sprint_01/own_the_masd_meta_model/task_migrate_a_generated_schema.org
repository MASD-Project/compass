* Goal

compass's database holds test activity that must survive an upgrade,
so it cannot be recreated as ORE Studio's is. Keep hand-written migrations,
frozen once released, beside the generated schema; test that both build the
same catalog; and report a change to a retained table that has no migration.
[[id:7FD52505-1436-4925-A1DE-4A3EC88F0133][Investigation: How compass generates itself]] gives the reasons.

* Acceptance

- A database test compares the catalog of every migration applied with the generated schema's.
- A model change without its migration fails the test.
- Lands before the first release that creates a database.
