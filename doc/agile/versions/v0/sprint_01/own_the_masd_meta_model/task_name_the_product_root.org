* Goal

compass's codec, its docs codecs and =compass add= name ORE Studio's
physical-space root =ores=, its library path and its =projects/modeling=
directory in code. This task makes them configuration, so the same tools serve
a project whose product is =compass=. It is the first step of
[[id:7FD52505-1436-4925-A1DE-4A3EC88F0133][Investigation: How compass generates itself]]'s order of work, and nothing else in the story can start before it.

* Acceptance

- The address root, the library path and the meta model directories are options; nothing in =compass.codegen=, =compass.docs= or =compass.model= names =ores= or =projects/ores.codegen=.
- =compass diff= on ORE Studio with its configuration stating =ores= reports no change.

* Plan

The product is one value a project states, and every root compass derived
from the literal =ores= is derived from it. It is a codec option, not a
setting compass reads from the models, because a third of ORE Studio's models
(operations, field groups, families, components) state no =:product:=, and
the physical-space graph is one per library, not one per model. #183 reads a
model's =:product:= for names a model owns, such as its tables; the option is
the default those names fall back on, and the root of what no model owns.

- =codegen= gains a required option =product=. The physical-space graph is
  rooted at it: its nodes are =<product>.*.org=, a drawer switches an
  address with =:<product>.<address>.enabled:=, and the facet lists the
  gates drop are spelled relative to the root. The component directories
  of the output paths (={component_dir}=, ={cache_component_dir}=) and a
  component's default full name are =<product>.<component>=. The library
  values gain =product=, so every template reads ={{product}}=.
- =component_files= loses its default =library=: the option is required.
- =physical_inventory= gains the required options =directory= and
  =product=: where the node pages are and which technical space is the
  root.
- =component_docs= gains the required option =product= and loses the
  default of =exceptions=.
- =compass.model='s operation loader reads the TypeScript and shell
  switches under any one-part root, because a model does not know the
  product and refuses before code generation runs.
- ORE Studio's templates render the root in four places, in three
  templates; each may become ={{product}}=, which renders the same bytes.
  ORE Studio makes that change, since the templates are its own until task
  3 moves them.

The invariant is ORE Studio's output: =compass diff= of a scratch copy of
ORE Studio's main, with the old and the new binary, the new one given the
options ORE Studio's =.compass.org= must add, reports the same files with
the same bytes.

* Notes

** What still names ores, and why

The first acceptance line asks that nothing in =compass.codegen=,
=compass.docs= or =compass.model= names =ores=. This task removes the root,
the library path and the component directory prefix. What is left is ORE
Studio's content, not a root, and moves or splits with the classification of
task 3:

- *C++ names the entity contexts build.* =ores::utility::domain::result=
  and its siblings (=entity_messages.cpp=, =family.cpp=, =messages.cpp=),
  =ores::<component>::domain::= namespaces and =ores.<component>= include
  roots (=entity_codecs.cpp=, =template_context.cpp=, =family.cpp=,
  =field_group.cpp=), ORE Studio's Qt widgets (=entity_presentation.cpp=),
  its tenant context (=entity_repository.cpp=) and its time functions
  (=entity_finders.cpp=). The investigation found the same in the
  templates: they are the Split half of the C++ families, and task 3 gives
  compass a MASD entity context instead.
- *The fallback of a model that states no =:product:=.* =entity_sql_names.cpp=
  and =junction_context.cpp= fall back on =ores=. Every ORE Studio entity
  states its product; 26 of its 27 junctions do not, so the fallback stays
  until those models state it or the context reads the option.
- *The model type names* =ores.codegen.entity= and its siblings
  (=manifest.cpp=, =load.cpp=, =component_docs.cpp=). They are the types of
  ORE Studio's models; compass's own models use =masd.codegen.*=, and
  renaming ORE Studio's is a change to its models.
- *Codecs that are ORE Studio's own checks*: =pending_models=,
  =tree_gates=, =skill_tables=, =recipe_libraries=, =trade_type_coverage=
  and the ORE half of =recipe_inventories=, and in =compass.crosscheck= the
  graph of =protocol_twins= and =generated_shape=, which now pass the root
  =ores= by name.
- *The meta model directory* =projects/modeling/= (=physical_space.cpp=,
  =entity.cpp= and =messages.cpp= of =compass.model=). The profile and
  custom type pages it names move into compass's library in task 3, which
  is when they are found through the library rather than through a second
  option.
- *=compass add=.* Its MASD types (facet, facet group, feature, profile)
  are scaffolded by the legacy Python tool in =compass.legacy=, which calls
  ORE Studio's =ores.codegen= and writes into its paths. The investigation's
  section on them assigns them to task 3.

** What ORE Studio changes

Its =.compass.org= adds four options, in the same commit that moves its pin
to the compass release that has them, since an older compass refuses an
option it does not know:

| Codec              | Options added                                                               |
|--------------------+-----------------------------------------------------------------------------|
| codegen            | =product=ores=                                                              |
| component_files    | =library=projects/ores.codegen/library=                                     |
| physical_inventory | =directory=projects/ores.codegen/library/templates product=ores=            |
| component_docs     | =product=ores exceptions=projects/ores.codegen/docs_exceptions.txt=         |

The template change is optional. =doc_component.org.mustache= (the
=:ores.cpp.scaffold.enabled:= drawer), =shell_service_vars.mustache= (the
=--address ores.shell.service= comment) and =doc_feature.org.mustache= (two
addresses in the bundle row) may write the root as ={{product}}=, and their
archetype pages with them; the output does not change. The two
=ores.cpp.field-group= of =cpp_field_group.hpp.mustache= sit inside a
={{! }}= comment and must stay as they are: a tag there ends the comment.
