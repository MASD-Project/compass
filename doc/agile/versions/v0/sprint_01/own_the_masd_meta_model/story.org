* Goal

compass generates its own code with its own tools. The MASD meta model, which
compass's code generator interprets, lives in compass, once: ORE Studio reads
it from compass and keeps only what is ORE Studio's. compass's database
schema, the row types that read it and its HTTP and MCP service are generated
from models in compass's own repository, so the generator is exercised on a
second project and any project using compass can generate the same kinds of
code.

* Acceptance

- An investigation states how compass generates its own tables and service:
  which models describe them, which technical spaces, facets and archetypes
  apply, which templates exist and which must be written, and how a
  generated schema migrates a database that already holds data. It covers
  the tables Serve the documents created by hand.
- Every page of ORE Studio's =projects/modeling= and its template library is
  classified as MASD (generic) or ORE Studio's own, with the reason.
- The MASD pages and generic templates live in compass and are deleted from
  ORE Studio in the same release; ORE Studio's code generation reads them
  from compass and its output does not change by a byte.
- compass's database schema and the row types over it are generated from
  compass's models, replacing the hand-written migrations, and the database
  tests pass unchanged.
- compass's HTTP and MCP service is generated from compass's models: its
  endpoints, request and response types and MCP tool descriptions.
- =compass generate= on compass reports nothing to write, and =compass check=
  keeps the generated code in step, as it does for ORE Studio.

* Decisions

- Move, not copy: a page of the meta model exists in one repository only.
- The HTTP and MCP service of Serve the documents is generated, not
  hand-written; search's queries may be written before then.

* Out of scope

- ORE Studio's own models (its entities, services and profiles that only it
  uses), which stay in ORE Studio.
- Replacing Mustache or the codegen engine.
