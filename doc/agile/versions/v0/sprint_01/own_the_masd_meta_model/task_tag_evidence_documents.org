* Goal

An org document kept for the record, such as a probe input or a copy of
another project's page, is saved as =.org= with the =evidence= filetag
instead of hiding behind a =.org.txt= extension. compass reads the tag in one
place and treats the document as a record: no contract holds it, its IDs
yield to live pages, no codec takes it as input unless the codec asks for
evidence, and it is still parsed and indexed.

* Acceptance

- The three =.org.txt= evidence files are =.org= files tagged =evidence=,
  and =render_probe.sh= and the pages that link them name the new paths.
- =required_sections= does not report an evidence document.
- A live document holds an ID an evidence document also carries, and a
  link to an ID only evidence carries resolves in =lint=.
- A codec that does not declare evidence neither sees, finds nor lists an
  evidence document, and a check document tagged =evidence= defines nothing.
- =document_index= lists evidence with its type.
- =evidence_location= reports an evidence document outside an =evidence/=
  directory.
- [[id:8B29A8D8-E004-4E87-B81D-ABEAF68F2B98][Document Types]] and the
  [[id:F94957C5-382A-4D6E-B292-C02C2772F038][Tag inventory]] state the rule.

* Plan

- One predicate, =org::ops::is_evidence=, reads the first =#+filetags:=.
- =codec::ops::index_corpus= flags evidence rows and lets live documents
  win an ID. =types::inputs::with_evidence()= is the only way for a codec to
  see evidence; =corpus_view= and the runner's recorded-input answers apply
  the same =read_scope=, so visibility, lookups and listings agree.
- Codecs that read evidence on purpose: =document_index= (lists it),
  =lint= (resolves links to its IDs, checks nothing in it) and the new
  =evidence_location=.
- =read_check_documents= skips evidence, since it reads files outside the
  corpus.
- The four investigations under =evidence/= that carried =:evidence:= as a
  topic tag lose it: they are live investigations held to their contract.

* Notes

- The converse rule, that every page under =evidence/= carries the tag, is
  wrong: =evidence/= directories here and in ORE Studio also hold live
  investigations written to their contract.
- The captured =.hpp.txt= and =.sql.txt= files keep their suffix. They are
  not documents, so the tag cannot apply to them, and the suffix is what
  keeps clang-format, clang-tidy, the build and the SQL codecs, which find
  their inputs by extension, from treating a captured output as source.
