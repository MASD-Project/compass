* Goal

compass copies ORE Studio's route machinery and JSON codec into MASD template
families and writes its own MCP transport, without waiting on ORE Studio, as
[[id:AF30B206-2FAB-435F-819F-9EC652D4E40D][Design: aligning the document service with ORE Studio's HTTP and MCP]]
decides. This task is the later, opt-in convergence. Once both projects
stabilise, it brings the two copies back to one and offers the families in
compass's MASD library for ORE Studio to opt into. It blocks nothing. Whether
and when ORE Studio opts in is ORE Studio's decision.

* Acceptance

- A rerunnable script renders compass's =masd.cpp.http-service= and codec
  families with ORE Studio's parameters and diffs them against ORE Studio's
  files at a named commit. Every difference is either a divergence the design
  records or is settled as a parameter or as a fix on one side.
- compass's MCP transport and ORE Studio's are compared against the design's
  behaviour table and the MCP conformance runner, and one is kept or the two
  are reconciled.
- The families are offered in compass's MASD library with ORE Studio's
  parameters, for ORE Studio to opt into. Nothing in compass depends on
  whether it does.
