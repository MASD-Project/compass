* Goal

compass's MCP and HTTP behave as ORE Studio's because they are the same code.
The generic part of ores.http moves into compass's MASD library as a template
family, =masd.cpp.http-service=, and both products generate their copy from
it, as [[id:AF30B206-2FAB-435F-819F-9EC652D4E40D][Design: aligning the document service with ORE Studio's HTTP and MCP]]
decides in its first and fifth sections.

* Acceptance

- The family holds the MCP endpoint, session registry and tool seam, the
  route with its catalogue declaration, the route builder and router with
  their start-up gates, the OpenAPI registry, the five catalogue tools generic
  over a "may call" predicate, the JSON codec runtime, and a generated test
  that runs the official MCP conformance runner.
- Its parameters are the namespace and include root, logging, the caller on a
  request, admission to =/mcp=, and the server's name and version; nothing
  else differs between the products.
- Rendered for ORE Studio at the named commit, it gives ORE Studio's files byte
  for byte, measured by a rerunnable script.
- ORE Studio's pull request that deletes its hand-written copies and generates
  them shows no diff in the generated files.
- compass generates its copy into =compass.serve=, builds on Linux, macOS and
  Windows with Boost.Beast and yyjson from vcpkg, and passes the conformance
  runner.
