* Goal

Every type compass models reads and writes JSON through generated code: row
types (whose =jsonb= columns are JSON already), enums as their names, and the
service's request and response messages. The codec is ORE Studio's:
=ores.cpp.wire-codec='s templates and the yyjson codec runtime, copied from
ORE Studio's main into MASD now, without waiting on ORE Studio, as
[[id:AF30B206-2FAB-435F-819F-9EC652D4E40D][Design: aligning the document service with ORE Studio's HTTP and MCP]] decides. A message's JSON Schema comes from its wire traits at run
time, as ORE Studio's routes take it, so a route's schema and a tool's input
schema are one value. No JSON is encoded or decoded by hand anywhere in
compass.

* Acceptance

- A template family generates, per modelled type, a JSON writer and a reader
  that rejects unknown and missing required fields with the field's name.
- Round-trip tests are generated with them: write then read gives the value
  back, for every row type, enum and message.
- Each message's JSON Schema, from =json_schema<T>()=, validates what its
  writer writes, checked in a test.
- The templates are the =ores.cpp.wire-codec= family and the codec runtime
  copied from ORE Studio's main into MASD, with the product root as a
  parameter and the MessagePack archetype left off. The task records the ORE
  Studio commit it copied from, and every change from it is a divergence the
  design records.
- The JSON underneath is yyjson, from vcpkg, on Linux, macOS and Windows.
  nlohmann-json is not added.

* Plan

Copy, then generate, in two steps that each end green.

1. *The runtime and the rows.* Copy ORE Studio's codec runtime,
   =projects/ores.utility/include/ores.utility/codec/= and
   =src/codec/text_form.cpp= at commit
   =bc0702ad46b8a6097ce5242ece7ba01067699f60= (=main=, 2026-11-23), adapt it
   in place under =compass.db= and compile it there, then turn each file into
   an archetype page of the new family
   [[id:7D0FA277-D3F7-48E9-BCDF-7A88592119E3][masd.cpp.codec]] with
   =evidence/codec_runtime_family.py=, so a render for =compass.db= gives the
   file back. A component switches the family on in a new
   =masd.codegen.component= model, [[id:F6A12086-9700-4773-9E08-5FE9BDA18272][compass.db.component]]. Copy
   =ores.cpp.wire-codec='s =codec_header=, =codec_impl= and
   =roundtrip_tests= into [[id:48CA6C74-8EF8-45B2-B6D6-CC6B508EE0D8][masd.cpp.json]] for every row, with a
   generated =text_form= per enumeration where ORE Studio reflects with
   =magic_enum=.
2. *The messages.* Once the revised service models merged (#198), read
   =masd.codegen.operation= models with a MASD reader of their own and
   generate each model's messages, enumerations and codecs with
   [[id:6BA0459B-525A-464F-954D-B0E83E83B92D][masd.cpp.protocol]], a copy of
   ORE Studio's operation protocol header with the =protocol_codec_impl= and
   =protocol_roundtrip_tests= archetypes, into =compass.serve.lib=.

Decisions:

- *yyjson, not nlohmann-json.* The runtime is yyjson underneath, as the
  design decided; yyjson joins =vcpkg.json= and =find_package=.
- *The runtime lives in =compass.db=.* The rows are there and =compass.serve=
  depends on it, so one copy serves both. The codegen option
  =codec_component=db= tells the message codecs where it is.
- *Readers are strict.* ORE Studio's reader ignores an unknown member; this
  copy refuses it by name and the schema states =additionalProperties:
  false=, so the reader and the schema agree. A refusal of a value names its
  member. Both are fixes to offer ORE Studio.
- *Messages are generated in =compass::serve::messages=.* The models stated
  =compass::db::types=, where hand-written structs of the same names and a
  generated =run_outcome= already live; two definitions of one name cannot
  meet in a translation unit. The hand-written structs, with their
  =tester=, stay until the HTTP task moves the queries.
- *Bytes are =base64_bytes=.* A field with =:encoding: base64= holds the
  runtime's =base64_bytes=, so raw bytes never reach a JSON string.
- *=document_row= has no codec.* Its =source= is a =std::string_view= the
  caller owns, which a reader cannot keep; its model switches
  =masd.cpp.json= off and says why.

Each archetype page records the ORE Studio file it copies and every
divergence; the facet pages [[id:7D0FA277-D3F7-48E9-BCDF-7A88592119E3][masd.cpp.codec]],
[[id:48CA6C74-8EF8-45B2-B6D6-CC6B508EE0D8][masd.cpp.json]] and
[[id:6BA0459B-525A-464F-954D-B0E83E83B92D][masd.cpp.protocol]] summarise them.

* Notes

- The first sampler built an enumeration's sample through =from_text=, so a
  =from_text= that misread every name passed the round trip. The text form
  now states =values= and the sampler takes them; the fault fails the test
  (=evidence/json_codec_fault_injection.txt=).
- A =std::string= field with =:values:=, such as =get_document_request.format=,
  stays a string: its JSON Schema does not list the values and the reader
  accepts any text. Refusing a text outside the list is the binding's, which
  Generate the HTTP and MCP service writes.
- Two models declare =step_outcome=; each header guards the declaration by
  its qualified name, and the context refuses two declarations that list
  different values within one model. Across models the guard keeps the first.
- macOS and Windows build only in the nightly workflows; the pull request
  dispatches both on its branch.

* Result

Every row type but =document_row=, every enumeration and every message of
the service reads and writes JSON through generated code, over a copy of
ORE Studio's yyjson codec runtime rendered into =compass.db=. Readers refuse
an unknown member, a missing required one and a value of the wrong type,
each by name, and each message's =json_schema<T>()= allows what its writer
writes, in a generated test per message. MessagePack is off and
nlohmann-json is not added. ORE Studio's generated output is unchanged by a
byte. The routes and tools that bind the messages are the next task's.
