* Goal

ORE Studio can model a time of day: a column of PostgreSQL type =time=
without time zone, whose zone lives in a separate IANA text column. compass
derives the template flags for it and maps its C++ type,
=ores::platform::time::time_of_day=, in every type table, so no generated
file carries an empty type. A template that writes a TypeScript type compass
cannot map fails the render instead of emitting =name: ;=.

* Acceptance

- A column with =:type: time= sets =is_time= when it is not null and
  =is_optional_time= when it is; the entity sets =has_time_columns=. A model
  property never sets them.
- The column is text-stored ("HH:MM:SS") and no generic member branch
  (=is_simple=, =is_already_optional=, =is_nullable_string=) takes it.
- =time_of_day= maps to TypeScript =string= (=string | null= when
  optional), to the =00:00:00= sentinel, to the bare types that need a
  default when nullable, and to the =time= wire class of
  =entity_binary_types=, whose SQL table maps =time= too.
- Writing a =ts_type= that nothing holds fails the render, naming the
  template, the field and its C++ type.
- ORE Studio's generated output is byte-identical with the old and new
  binaries.
- Catch2 tests cover each flag and mapping and fail on the old code.

* Plan

- =entity_columns.cpp= derives the flags from the lowered SQL type, beside
  =is_date=, for plain columns only, as =is_date= is.
- Each table keyed by C++ type gets a =time_of_day= row where the date has
  one: =ts_scalars= (messages.cpp), the two sentinel tables, the bare
  nullable list and =cpp_wires=. The shell token types leave it out, as they
  leave out the date.
- =render_options::required= names what must hold a value when written;
  =render_output= requires =ts_type=.
- Versions move for codegen, component_files, entity_binary_types,
  generated_column_refs and marketdata_identity_columns.

* Notes

SQL types still without a mapping, by table:

- TypeScript is keyed by C++ type, not SQL type. A column without
  =:cpp_type:= has no TypeScript type whatever its SQL type; the empty
  =bytea=, =bigint=, =text[]= and =jsonb= types of the earlier probe come
  from that. With the usual C++ types they map: =std::int64_t= to
  =number=, =std::vector<std::string>= to =string[]=, =std::string= to
  =string=, =std::vector<std::uint8_t>= to =number[]=. A qualified type
  outside =ores::<component>::domain::=, such as =std::byte=, maps to
  nothing. Such a column now fails the render.
- =entity_binary_types= places no =bytea=, =json=, range (=int8range=),
  =interval=, =timetz= or serial column on the wire, and no
  =std::vector<std::uint8_t>=, =std::int8_t= or =std::uint8_t= member.
- The sentinel tables have no row for =float=, =std::int16_t=,
  =std::uint8_t= or a byte vector; those fall back to =__none__=.
