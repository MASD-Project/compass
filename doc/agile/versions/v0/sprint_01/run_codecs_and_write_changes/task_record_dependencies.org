* Acceptance

- Changing one document re-runs only the codecs that read it, including codecs that read it through a link.

* Plan

- The =corpus_view= records every read: the documents a codec unit opens, the
  lookups it makes by ID or path, including lookups that find nothing, and the
  document path when it reads it. A corpus-unit codec also depends on the set
  of documents of its declared types, recorded as a hash of their paths and
  IDs, so adding or removing a document re-runs it.
- The dependency record maps each codec unit (codec, version, configuration
  hash, and the document for per-document codecs) to its inputs as
  (key, content ID) pairs and to the outputs it produced. It is per-worktree
  state, kept beside the worktree index in =<gitdir>/compass/=, and rewritten
  only when it changes.
- Selection compares the record with the current corpus: a unit re-runs when
  any recorded input's ID changed, when a missed lookup now resolves, when its
  type set changed, or when its codec's version or configuration changed.
- =compass-bench codecs= reports how many units ran and how many were skipped,
  and a test edits one document and checks that only the units that read it
  re-run, including a unit that reads it through a link.

* Result

- Codecs record their reads through the view with no opt-in: documents
  handed out, lookups by ID or path with their answer (misses included), and
  reads of the type registry. A corpus unit records the hash of its type set.
- The record at =<gitdir>/compass/deps= keeps each unit's inputs and outputs;
  a unit re-runs only when an input changed, a missed lookup now resolves, its
  type set changed, or its codec's version or configuration changed. A skipped
  unit's outputs come from the record, because the store's collection would
  remove objects no git index names.
- On ORE Studio a run with nothing changed runs no unit, and editing one task
  re-runs one unit per codec.
- *Recording costs more than it saves for cheap codecs.* An unchanged run over
  ORE Studio takes 17.7 ms against 12.4 ms for running both codecs with no
  record: the 6.2 MB record costs about 40 ms to read and 40 ms to check, much
  of it SHA-1 (estimated, not profiled). It pays off for expensive codecs such
  as codegen and the HTML export; a cheaper integrity check, or letting cheap
  codecs opt out, is the follow-up.
