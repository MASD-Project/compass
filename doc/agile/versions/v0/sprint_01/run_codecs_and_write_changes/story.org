* Goal

Any output or check is a codec over the in-memory tables; a run touches only outputs whose content changed, and a diff run shows the effect of a change without writing to disk.

* Acceptance

- A codec declares the document types it reads, its version, its configuration, and either output files or diagnostics; diagnostics name the fix.
- Codecs report the inputs they read while running, and the dependency record re-runs only the codecs whose inputs changed.
- An output is written only when its hash differs from the recorded one; an unchanged output keeps its modification time.
- Diff mode runs the same pipeline and prints a unified diff of every output that would change, writing nothing.
- Codec results are cached by codec version, configuration and input hashes, and reused across worktrees.

* Result

- A codec is a descriptor and a function over a view of the corpus; the view
  records what each unit reads, so only units whose inputs changed run again,
  and results are shared by every worktree through a two-level cache.
- Outputs are written only when their content changes; hand-edited or deleted
  generated files are restored, and files a codec stops producing are
  removed. Diff mode prints the same plan as unified diffs, writes nothing,
  and exits 1 when anything would change.
- For the two codecs so far, a document index and a required-sections check,
  the bookkeeping costs more time than it saves: running both over ORE
  Studio takes about 12 ms. It is built for expensive codecs. Two follow-ups
  are recorded in the tasks: a cheaper integrity check than SHA-1 for the
  dependency record, and packing the small action objects.
