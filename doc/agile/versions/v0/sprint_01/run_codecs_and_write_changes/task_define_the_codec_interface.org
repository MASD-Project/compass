* Acceptance

- The interface is documented and one output codec and one check codec implement it.

* Plan

- A codec is data plus one function. The data: a name, a version, its
  configuration, the document types it reads (resolved against the type
  registry), and whether it emits files or diagnostics. The function reads the
  corpus through a view and appends to an output table: files (path, bytes) or
  diagnostics (document, source range, rule, message, the fix to apply).
- The corpus view gives a codec the documents of its declared types only, so
  the dependency recording of the next task has one place to hook in.
- A registry of codecs, enabled or disabled by configuration, replaces any
  branching on codec names.
- Two real codecs prove the shape. An output codec writes a document index
  (ID, title, type, path per document). A check codec reports each document
  missing a section its type requires, naming the section to add.
- =compass-bench codecs <checkout> --meta <dir>= runs the enabled codecs over
  the corpus and reports per codec the documents read, outputs, diagnostics
  and time. Outputs are reported, not written; writing is a later task.
