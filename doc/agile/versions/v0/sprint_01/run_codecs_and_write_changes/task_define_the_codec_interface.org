* Acceptance

- The interface is documented and one output codec and one check codec implement it.

* Plan

- A codec is data plus one function. The data: a name, a version, its
  configuration, the document types it reads (resolved against the type
  registry), and whether it emits files or diagnostics. The function reads the
  corpus through a view and appends to an output table: files (path, bytes) or
  diagnostics (document, source range, rule, message, the fix to apply).
- The corpus view gives a codec the documents of its declared types only, so
  the dependency recording of the next task has one place to hook in.
- A registry of codecs, enabled or disabled by configuration, replaces any
  branching on codec names.
- Two real codecs prove the shape. An output codec writes a document index
  (ID, title, type, path per document). A check codec reports each document
  missing a section its type requires, naming the section to add.
- =compass-bench codecs <checkout> --meta <dir>= runs the enabled codecs over
  the corpus and reports per codec the documents read, outputs, diagnostics
  and time. Outputs are reported, not written; writing is a later task.

* Result

- =compass.codec= (domain layer, on =compass.org= and =compass.store=) holds the
  runtime. A codec is a constant descriptor (name, version, input types,
  options with defaults, rules, enabled by default) plus one function whose
  type states its unit, document or corpus, and its output, files or
  diagnostics. It reads through a =corpus_view= of its declared types only.
  The registry resolves types and applies settings; the runner runs enabled
  codecs in parallel with output identical on any thread count.
- =document_index= writes one TSV of ID, title, type and path per document;
  =required_sections= reports each document missing a section its type
  requires, naming the section to add. Both run over ORE Studio in about
  12 ms.
- =required_sections= is not yet fit to gate. In this repository its 36
  knowledge findings are true to the contract: index pages such as
  =recipes.org= and =developer.org= are typed knowledge and have no
  =* Detail=. In ORE Studio many capture findings are false, because the
  capture contract accepts =* What= and =* Why= for =* Note= in prose the
  registry builder does not read.
- Open for the next tasks: =document.path= is not yet a recorded read, codecs
  are either file or diagnostic producers with no channel for a generator to
  report a bad model, and options are strings.
