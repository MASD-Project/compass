* Acceptance

- Diff mode writes nothing to disk, which is verified by comparing the tree before and after.

* Plan

- The sink splits into a plan and an apply. The plan is a pure function from
  the run's outputs, the written-outputs record and the files on disk to a
  list of actions: write, restore, remove, keep, unchanged. Writing applies the
  plan; diff mode prints it. One decision path serves both, so they cannot
  disagree.
- Diff mode prints a unified diff per action against the file on disk (or
  =/dev/null= for new and removed files) and a summary, and writes nothing: no
  outputs, and none of the per-worktree records (worktree index, dependency
  record, written-outputs record).
- The unified diff is computed in process (Myers' algorithm, with git's default
  of three context lines), so diff mode does not depend on an external =diff=.
- =compass-bench codecs --diff <root>= runs it and exits non-zero when anything
  would change, so it can serve as a drift check.

* Result

- The sink is a pure plan (write, restore, remove, keep, unchanged per output)
  and an apply; writing is plan then apply, and diff mode prints the plan, so
  the two cannot disagree.
- Diffs are computed in process with Myers' algorithm in git's unified format
  with three context lines, and match =git diff --no-index= byte for byte on
  every test case; binary content prints git's =Binary files ... differ=.
  git's slider heuristics are not copied, so a change among repeated lines can
  be placed differently, though never longer.
- Diff mode writes nothing: no outputs, no records, no objects. The diff path
  never receives a writer. It exits 0 when nothing would change, 1 when
  something would, and 2 on failure, so it can serve as a drift check.
