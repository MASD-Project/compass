* Goal

ORE Studio added a service, =ores.orgmode.service=, and no check noticed it was incomplete: it was not in the service registry, its =src/CMakeLists.txt= was missing, its application was still the scaffold's, a second list of the services left it without a certificate, and a hand edit in the generated service grants SQL went unseen. The gate report from the environment that found them names each one (items 1.1 to 1.8).

This story makes "a service is whole" one check, =service_integrity=, rooted in the service registry: for every service it names each obligation unmet. The obligations are the project's data, in its check document, so compass carries nothing of ORE Studio's; adding something every service needs is a row. Around it, the generated outputs of the registry become drift-checked, a hidden-visibility part's public functions must be exported, and compass's own tests cover what codegen scaffolds.

* Acceptance

- =service_integrity= reports, on a copy of ORE Studio's main with each defect seeded, a service missing from the registry, a missing build file, a scaffold application, a service missing from a generated SQL file, and a second list of service names.
- Its obligations are rows of ORE Studio's check document; compass's code names no ORE Studio path.
- A hand edit to any output of the service registry is reported as drift.
- A namespace-scope function in a public header of a hidden-visibility part without the export macro is reported.
- compass's tests scaffold a flat, a composite and a hidden-visibility component and check the files written.
