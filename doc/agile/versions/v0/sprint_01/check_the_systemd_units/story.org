* Goal

An environment never starts its fleet from units that are stale or wired
wrongly. On 2026-11-22 an ORE Studio environment started its services from
systemd units deployed on 13 November: nothing deployed them again after
13 days of changes, the pooler dependency and the =After==/=Requires==
wiring among them, and nothing reported it. Regenerating would not have been
enough, because the generated units themselves encode only part of each
service's dependencies:

#+begin_example
ores.iam.service:  After=nats-server,            Requires=nats-server
ores.dq.service:   After=nats-server ores.iam,   Requires=nats-server ores.iam
#+end_example

compass checks both: that the units in the tree match what the registry
generates, and that each unit orders itself after, and requires, every
service it depends on.

* Acceptance

- *Wiring.* A check reads each generated unit and the project's data on what
  a service depends on (its registry: messaging, database or pooler, other
  services it calls) and reports a unit whose =After== or =Requires== lacks
  one of them, naming the missing unit. On ORE Studio it reports the gap in
  the units above.
- *Generated units are current.* Units the project generates are outputs
  compass checks for drift like any other, so a change to the registry or the
  template that is not regenerated fails the gate.
- *Deployed units are current.* A command reports, per environment, each
  deployed unit that differs from what the environment would deploy now, or
  that no service names any more, with its age, as =compass env status= does
  for =.env=. It is read-only; deploying stays the project's tool.
- The dependency data is the project's, in a check document or its
  registry; compass names no ORE Studio service.
