* Acceptance

- The parser handles every construct found in the ORE Studio corpus, and its tests cover each one.

* Plan

- The parser lives in =compass.ingest=, the component of readers that fill the
  =compass.org= tables, in its =org= facet. It reads a mapped document and
  fills one document's tables; it allocates per table, not per node.
- org-element is the oracle. A batch Emacs script dumps org-element's tree for
  a file as one line per element and object: type, begin, end, contents begin
  and end, post-blank, and the key properties per type. A =compass-bench=
  stage dumps the parser's tables in the same format. A differential run over
  the whole ORE Studio corpus counts files that match exactly and lists the
  first difference of each file that does not.
- Constructs are added in census order, most frequent first, each with unit
  tests built from the smallest input that shows it.
- =compass-bench= gains an =org= stage that parses every org file on all cores
  and reports time and MB/s against the baseline.

* Result

- =compass.ingest= parses a document's bytes into one document's =compass.org=
  tables with per-table allocation and no regex, honouring each document's
  =#+todo:= keywords.
- org-element is the oracle: =build/scripts/org_element_dump.el= and
  =compass-bench org-dump= print the same line format, and
  =build/scripts/org_diff.py= compares them over a tree. Every ORE Studio org
  file and every org file in this repository matches exactly.
- Parsing all of ORE Studio's org takes about 130 ms on 8 threads, far inside
  the 5 s cold budget, so the org side of the pipeline is cheap.
- Not recognised, by design: citations, radio links, inlinetasks,
  =#+setupfile:=, and =#+link:= abbreviations, which need the expansion that is
  not in the source. None occurs in ORE Studio.
- Constructs absent from the corpus (planning lines, dynamic blocks, macros,
  inline source, line breaks, =table.el=) rest on unit tests and the fuzz run.
- No table column changed. =compass.org= gained an =io= facet with the dump,
  and the headers now state three semantics: affiliated names are
  org-element's translated names, the =file= link variants are all =file=, and
  link paths are the text as written.
