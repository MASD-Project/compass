* Acceptance

- The tables are documented, and each org construct the HTML export needs has a home in them.

* Plan

- Count first: a census script, =build/scripts/org_census.py=, counts every
  org construct across the ORE Studio corpus (headings, keywords, drawers,
  property drawers, blocks by kind, tables, lists, links by type, emphasis,
  timestamps, footnotes, macros, babel calls, LaTeX). The counts rank what the
  tables must hold and, later, the order of the HTML export work.
- The tables live in a new domain component, =compass.org=, in its =types=
  facet: one header per table, plain aggregates in struct-of-arrays form,
  dense 32-bit handles, byte offsets into the source instead of copied text,
  interned strings for keys and tags. Every handle type is distinct, so a
  heading handle cannot index the block table.
- The design is written as the story's =design.org= and lands in the
  =compass.org= component overview, which is the durable description.
- The headers compile and carry =static_assert= checks on row sizes. There is
  no parser yet; that is Write the org parser.
- =projects/modeling/system_model.org= gains =compass.org=.

* Result

- =compass.org= holds the tables as thirteen struct-of-arrays tables: an
  =elements= tree in pre-order with parents and subtree ends, =objects=
  nested the same way, detail tables for headings, tags, keywords,
  properties, affiliated keywords, blocks, lists, items and links, per-document
  interned =names=, and =documents= laying a corpus end to end. Plain text has
  no rows; it is the source between objects.
- Positions follow org-element's =:begin=, =:end=, =:contents-*= and
  =:post-blank=, so the HTML exporter can follow ox-html's logic. Rare
  constructs (timestamps, macros, entities, footnote labels) are a kind and a
  range read from the source.
- Every table has its own handle type, and a column can be indexed only by its
  own handle; the tests pin this, the row sizes and a hand-built document.
- The ORE Studio corpus should take about 59 MB of tables on top of 70 MB of
  mapped source. This is census counts times row sizes, not a measurement.
- Open for the parser task: names are interned per document, so cross-document
  comparison needs a load-time index; element rows carry no index into their
  detail table, so random access is a binary search; the columns are
  =std::vector= until the pack work maps them.
