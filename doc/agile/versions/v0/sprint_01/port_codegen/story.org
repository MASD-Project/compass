* Goal

compass regenerates all of ORE Studio's generated code byte-for-byte identical to ores.codegen, in less than 30 seconds for a full run, touching only files whose content changes.

* Acceptance

- Every ORE Studio component regenerates byte-for-byte identical to ores.codegen at the same commit.
- A full regeneration of ORE Studio takes less than 30 seconds on 8 cores, measured against the baseline.
- clang-format and prettier run only for outputs whose raw render changed, through a cache keyed by the raw output hash and formatter version.
- Templates are tangled from their org sources by compass, with no Emacs process.

* Decisions

- Every step is checked against an oracle dumped from ores.codegen itself:
  models, then render contexts, then raw renders, then formatted output.
  Matching contexts first made every render difference traceable to one
  field.
- Templates are tangled by concatenation, without Emacs.
- Formatting is cached by raw bytes, output path, formatter identity and style
  hash, so an unchanged regeneration runs no formatter.
- Codegen is a codec in =compass.codec='s runtime, configured from
  =.compass.org=, and shares the store, dependency record and result cache
  with the other codecs.

* Result

compass reproduces all of ORE Studio's generated code. =compass generate=
writes 26,212 outputs byte-identical to ores.codegen's own formatted output; a
warm run takes under 3 s and a cold run 23 to 31 s, against about 7 minutes
for ores.codegen's entity outputs and 432 s for its formatting alone. The 24
files that differ from ORE Studio's checked-in tree are drift there: 22 never
regenerated after the system-tenant shared-read change, and 2 hand edits.

Open threads, recorded in the task results: context build costs about 1.8 s
from deep copies; the dependency record's 185 MB SHA-1 limits the warm run;
formatted results survive gc only for its grace period; ORE Studio needs a
=.compass.org= before compass can run there.
