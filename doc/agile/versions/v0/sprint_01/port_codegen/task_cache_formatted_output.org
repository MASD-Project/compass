* Acceptance

- A full regeneration with no template change runs no formatter.

* Plan

- Find out first how ores.codegen formats each output after rendering: which
  formatter, version and style file for each output kind (C++, TypeScript,
  SQL, CMake, org), and how it calls them. Measure what formatting costs on
  the full regeneration.
- Format a raw output only when its formatted form is not in the store yet.
  The key is the raw output's hash, the formatter's identity and version,
  and the style file's hash. The raw outputs are already exact, so the
  formatted form is a pure function of that key.
- Run formatters once per batch, or through the clang-format library, not
  once per file.
- Check the formatted outputs against what ores.codegen writes for the same
  archive, and measure a cold run and a warm run.

* Result

A regeneration with no template change starts no formatter: every formatted
output comes from the result store. The formatted outputs are byte-identical
to what ores.codegen's own format step produces from the same raw renders.

How ORE formats: =generate.py= runs, per model, =clang-format -i= twice over
C++ outputs with the repository's =.clang-format=, and =prettier --write= over
TypeScript with =.prettierrc.yaml= (prettier pinned to 3.9.8). SQL, org and
text outputs are not formatted. Formatting takes most of a regeneration's
time, and prettier's cost is mostly the start-up of one process per model.

- =compass.platform= gains =run_program=, which replaces two copies of the
  spawn code in =compass.cli= and =compass.bench=.
- =compass.codec= caches formatted outputs in the result store. The key is the
  raw bytes, the output path (clang-format and prettier both depend on the file
  name), the formatter program's identity and the style file's hash. Misses
  run in batches, one process per pass per batch.
- =compass-bench render --format= measures it with ORE's formatter table.

The 24 differences from the checked-in tree are not formatting. 22 come from
the system-tenant shared-read change that was never regenerated, and 2 are
hand edits: =ores.marketdata.service/config/options.hpp= and
=ores.ore/core/tests/CMakeLists.txt=. Match the existing output should list
them.

Decisions to revisit:

- ORE's formatter table lives in =compass.bench=. It moves to
  =compass.codegen= when codegen becomes a codec.
- No record names the formatted results, so gc keeps them only for its grace
  period, and a gc can make the next regeneration cold.
- The program's identity is its resolved path, size and modification time, so
  the warm path never runs =--version=. Changing node alone does not change
  prettier's key.
- Everything ran with clang-format 21.1.8. ORE's CI uses clang-format 18,
  which is not tested here; its key differs, so it reformats rather than
  reusing results.
