* Acceptance

- A full regeneration with no template change runs no formatter.

* Plan

- Find out first how ores.codegen formats each output after rendering: which
  formatter, version and style file for each output kind (C++, TypeScript,
  SQL, CMake, org), and how it calls them. Measure what formatting costs on
  the full regeneration.
- Format a raw output only when its formatted form is not in the store yet.
  The key is the raw output's hash, the formatter's identity and version,
  and the style file's hash. The raw outputs are already exact, so the
  formatted form is a pure function of that key.
- Run formatters once per batch, or through the clang-format library, not
  once per file.
- Check the formatted outputs against what ores.codegen writes for the same
  archive, and measure a cold run and a warm run.
