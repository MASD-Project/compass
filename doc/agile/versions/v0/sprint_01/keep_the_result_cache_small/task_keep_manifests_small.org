* Goal

An edit writes manifests of kilobytes, not megabytes. A manifest names
each of its input sets by the keys of its chunks: content-addressed runs
of about 128 inputs, cut where the hash of an input's kind and key says,
so an edit to one file changes one chunk, and every set, manifest and
worktree that reads the same files shares the rest.

* Acceptance

- A manifest holds, per set, its result key and its chunk keys; a chunk
  holds the inputs in the order the unit read them.
- A run from the cache records what a call would, byte for byte, as before.
- An edit to one of many files a scan read writes one chunk and a
  manifest a fraction of the size of the scan's inputs.
- A damaged chunk is a miss and is written again by the next run.
- Collection keeps the chunks of every set a worktree's record names.

* Plan

- =ops::chunk_input_set= cuts a unit's inputs, in read order, after an
  input whose kind-and-key hash is zero modulo 128, or after 1,024 inputs.
  Each chunk is a result object keyed by the SHA-1 of its body ("INP1").
  Read order and not sorted order, because a hit must record what the
  call would.
- The manifest names sets by result key and chunk keys; =add_input_set=
  compares sets by those keys alone.
- =io::store_actions= writes each chunk the store does not hold intact,
  even when the manifest is unchanged, so a damaged chunk heals.
- =look_up= reads each chunk once per manifest and checks a set's inputs
  as before.
- =io::action_keys= cuts each recorded unit's inputs again for the keys.
- =action_format_version= goes to 6: every key changes, which a new build
  causes anyway through the code hash.

* Notes

- Wall times were not compared. The load average was 12 to 17 during the
  runs: edit runs took 5.7 to 6.2 s against 5.3 to 5.4 s measured on a
  quieter machine for the previous task. The chunking probe bounds what
  this task adds to an edit, which re-chunks only the units it runs, at a
  few milliseconds.
- A document unit's set is one small chunk, so a cold run writes about
  90,000 chunks; they are 44 MB of the 598 MB it writes.
