* Goal

The result cache a repository's worktrees share stays a few times the size
of what they use now, however long they run. On 2026-11-20 ORE Studio's
cache was 19.8 GB after three days, 88% of it named by no worktree, and it
filled the SSD: [[id:EDCF07F7-7981-4BF8-B908-8DD4E6D9121F][Why the result cache grows]]. What is the same across
worktrees and runs is stored once, and the cache keeps each worktree's last
two or three runs, not every result ever written.

* Acceptance

- An edit to one file writes that file's scan facts, not every file's.
- Worktrees on the same content share the facts and findings of their
  scans.
- No run leaves the cache holding more than each worktree's last two or
  three results of a unit and what they share.
- ORE Studio's cache, measured as the investigation measured it, after a
  day of normal use across its worktrees.

* Decisions

- A scan's per-file facts are result objects keyed by codec, version,
  configuration, path and content, so worktrees on the same content share
  them (#123).
- A manifest names each input set by content-addressed chunks of about 128
  inputs, cut by the hash of each input's kind and key, in read order, so
  an edit changes one chunk and a hit records what a call would (#124).
- Retention follows what each run retired rather than old records, which
  are 300 MB on ORE Studio; three runs per worktree (#125).
- A run collects when the store has doubled since the last collection and
  holds 256 MB, never waiting for the lock, so collecting copies no more
  over time than runs write and never fails a run (#125).

* Result

The result cache stays bounded. Over the day after v0.0.4, ORE Studio's ten
worktrees moved from compass v0.0.4 to v0.0.12, and each new build
reruns every unit, about 90,000. The store grew from 2.88 GB to twice that,
one run collected it to 3.27 GB, and it stood at 3.71 GB with 17% of it
unreferenced. Before this story it was 19.8 GB after three days, 88% of it
unreferenced. Manifests fell from 1.88 GB to 0.25 GB.

Open beyond this story: each worktree's dependency record is still about
317 MB, 3.17 GB for ten worktrees, as large as the store. The investigation
left finding why for later.
