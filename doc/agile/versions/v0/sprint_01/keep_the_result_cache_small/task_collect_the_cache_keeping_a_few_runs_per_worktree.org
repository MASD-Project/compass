* Goal

The result cache stops growing without bound. Each worktree keeps its last
three runs, the one its record names and the two before it, and a run
collects the store when it has doubled since the last collection, so no
one has to remember to run =compass gc=.

* Acceptance

- A run that writes a new record records the keys it retired; a worktree's
  retired file keeps two runs, so collection keeps three.
- A run collects the store when its packs hold at least 256 MB and twice
  what the last collection left, or none is recorded, and not otherwise.
- A collection a run starts does not wait for the lock, and one that
  fails is reported and fails nothing.
- =compass gc= keeps working as before and also records what it left.

* Plan

- Retention by what a run retired rather than by keeping old records: a
  record is 300 MB on ORE Studio, while what one edit retires is a few
  hundred keys. =ops::retired_keys= takes the units of the previous record
  whose result the new record no longer names, and drops the keys their
  replacements, the fresh units, still need. Over-keeping a key another
  unit still needs is harmless; collection only keeps.
- =io::retire_keys= writes =compass/retired= under the worktree's git
  directory, newest run first, two runs; =io::action_keys= adds them.
- Collection when grown rather than on a timer or every run: rewriting
  the live set once per doubling bounds the copying by what runs wrote,
  as the geometric repack does for merging. The floor keeps small stores
  from ever paying for it.
- =collect= takes the lock first, and gives up at once when asked not to
  wait, so two runs never queue behind each other's collection.
- After a code change every unit runs again, so the run before it, a
  whole build's results, is retired and kept: the store holds two builds
  until the third run.

* Result

Merged in #125 and released in v0.0.4. Each worktree keeps its last three
runs, through the keys each run retired, and a run collects the store once
its packs reach 256 MB and have doubled since the last collection. On ORE
Studio, after the store moved back to the SSD, the first run of v0.0.4
collected the 20.3 GB the cache had grown to since 2026-11-17 down to 2.88
GB, nearly all of it the other worktrees' v0.0.3 results their records
still name. Those go once each worktree has run v0.0.4 three times, at the
next collection, when the store reaches twice 2.88 GB.
