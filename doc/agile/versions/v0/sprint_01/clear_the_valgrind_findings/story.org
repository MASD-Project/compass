* Goal

The debug nightly runs every test under valgrind's memcheck and submits
what it finds to CDash. Its findings should mean something: zero on a
clean tree, so a new one is a defect someone introduced. Today it reports
1,722, and almost none of them are compass's. ORE Studio solved the same
problem with a suppression file whose every entry says why it is there,
and a script that checks the file against a run. This story brings that
over, keeps the programs the tests start out of memcheck, and fixes
whatever is left that is compass's own.

* Baseline

The debug nightly of 2026-11-18, build 4571451 on CDash, ran each suite
as one test, before tests were reported case by case. Defects by test:
memory leak, potential leak, uninitialised conditional, uninitialised
read.

| Test | Leak | Potential | Cond. | Read |
|------+------+-----------+-------+------|
| compass.cli.end_to_end | 1 | 502 | 0 | 0 |
| compass.cli.install | 1 | 514 | 0 | 0 |
| compass.cpp.tests | 0 | 0 | 153 | 190 |
| compass.crosscheck.tests | 0 | 0 | 44 | 107 |
| compass.cli.tests | 0 | 45 | 0 | 0 |
| compass.store.tests | 0 | 44 | 0 | 0 |
| compass.bench.tests | 0 | 40 | 0 | 0 |
| compass.codec.tests | 1 | 27 | 0 | 0 |
| compass.docs.tests | 0 | 0 | 14 | 8 |
| compass.codegen.tests | 0 | 0 | 8 | 5 |
| compass.sql.tests | 0 | 0 | 0 | 12 |
| compass.platform.tests | 0 | 6 | 0 | 0 |
| Total | 3 | 1,178 | 219 | 322 |

compass.store.tests and compass.platform.tests failed under memcheck.
compass's =build/valgrind/custom.supp= holds 4 suppressions; ORE
Studio's holds 204. ORE Studio's memcheck options add =--demangle=yes=
and =--gen-suppressions=all=, which compass's =CTest.cmake= lacks.

Source: =https://my.cdash.org/api/v1/viewDynamicAnalysis.php?buildid=4571451=.

Guesses, to be settled by the triage. The potential leaks of the
end-to-end and install tests are the shells and git the scripts start,
traced because of =--trace-children=yes=. The uninitialised reads in the
regex-heavy suites (cpp, crosscheck, docs, codegen, sql) are PCRE2's JIT,
which valgrind cannot follow.
