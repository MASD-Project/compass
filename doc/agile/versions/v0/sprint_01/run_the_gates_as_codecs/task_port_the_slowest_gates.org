* Result

One =compass check= now does the work of ORE Studio's three drift gates and
its four slowest scans, about 1,457 s of gates, in under 3 s warm. Every port
gives its original's verdict on ORE Studio at 545cafca45, both as it is and
with planted violations.

- =compass check= plans the codec outputs as =diff= does and reports each file
  =generate= would change as a =codec/drift= finding, so it fails on drift.
- A finding can name any checkout file, not only a document.
- New domain components: =compass.cpp= (exported-types, enum-attributes,
  test_case_reachability) and =compass.sql= (sql-hygiene). They read files
  only through the codec runtime, so an unchanged tree hits the record.

Decisions to revisit:

- Check fails on drift for every codec that emits files. In this repository
  =document_index= and =tangle= outputs are not committed, so =compass check=
  here reports them as drift until =compass generate= runs.
- Messages leave out counts (comment depth, "defined N times"), following the
  codec rule; verdicts were compared on file, line and kind.
- Scanning is over UTF-8 bytes, so Unicode whitespace and case folding could
  differ from Python; nothing on ORE Studio does.
- =exported_types= depends on the listing of every path, so adding any file
  reruns it (about 2.5 s).
- The warm run spends about 0.9 s reading the 185 MB dependency record.
