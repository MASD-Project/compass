* Result

=model_rules= is one per-model scan over each model's parsed outline (the
view compass.model's loaders read). It holds money_decimal_columns,
http_areas, model_drift, subject_conformance's model half and protocol_twins'
opt-out; an edited model maps alone, and the rules keep their names under
=model_rules/=. The three floors the regexes needed are gone, because a
parsed outline cannot go blind. curve_column_guards is folded into
curve_sections_wiring, which computes the wiring once for all seven files;
convention_kind_terms is folded into ore_value_sets.

The pilot's defect is fixed here: curve_sections_wiring now writes
=curve_section_wiring.hpp= and =.cpp= as the generator does, through
clang-format, byte-identical on the pilot's tree.

Left for [[id:7EFC3933-2682-4BB7-89E4-64C78CE1E5BB][Finish the model rules pass]]: generated_column_refs,
entity_binary_types, open_reads, marketdata_identity_columns and route_units
still read regexes, and the curve wiring and convention terms are still
derived by more than one codec until the runtime can share prepared state.

An install needs ORE Studio's =.compass.org= to drop the rows for
money_decimal_columns, http_areas, model_drift, curve_column_guards and
convention_kind_terms, add =model_rules=, and set =clang_format= on
curve_sections_wiring.
