* Acceptance

- Each of xml-bindings-drift, file-types-seed, ore-parameters-seed, ore-element-map, ore-parameter-value-sets and parameter-value-sets-only has a written decision: what it protects, whether that still needs a gate, and how compass does it.
- Where the Python's output depends on accidents (object identity, directory walk order, dict order), the decision fixes the intended order and says what changes in ORE Studio's committed files.
- Every gate kept is a compass codec at a fraction of the original's time.

* Plan

- For each of the six gates, read the generator and what consumes its output,
  and write down what it is trying to achieve: the invariant it protects and
  the artefact it produces.
- Judge whether the gate makes sense as it is: whether the artefact needs to
  be committed, whether the check duplicates another gate or a codec compass
  already has, and where the Python's output rests on accidents (object
  identity, dict order, directory walk order, comprehension-built tables).
- Design the compass version for the intent, not the script: a fixed,
  documented order; one pass over the data shared with gates that read the
  same inputs; and the cheapest representation of the check.
- Record each decision in an evidence file, port the gates kept, and list
  the changes the intended order makes to ORE Studio's committed files.
