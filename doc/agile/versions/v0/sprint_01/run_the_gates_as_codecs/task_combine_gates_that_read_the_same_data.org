* Acceptance

- A table groups every ported gate by the data it reads (C++ sources, headers, SQL, org documents, models, generated outputs) and how it tokenises it.
- Gates over the same data share one pass: each file is read and tokenised once per run, with every gate's findings and identical verdicts.
- The warm and cold =compass check= on ORE Studio, and the hook's edit times, are measured before and after.

* Plan

The gate review (=evidence/gate_review/=) grouped the gates by the data they
read. The work was split into four tasks, one per kind of data, in the order
the product owner chose: SQL, C++, org documents, models.

* Measurements

Every number this task claims about a tree, with the command that produced it
and the commit it was measured at. A number without both is not a measurement,
because a clean-up record describes a tree and trunk moves under a branch: a
consumer count, a gate's component count and a suite's size all change with no
code changing, and the reader of a bare number cannot tell which tree it came
from. Where the raw output matters, put it in an =evidence/= file beside the
