* Result

21 of the 25 C++ and SQL gates are compass check codecs, each matching its
original's verdict on ORE Studio, and together they add about 0.75 s to a
warm check, inside the 2 s budget.

=compass.platform= gains a =text= facet: Python-compatible regular
expressions over PCRE2 (a new vcpkg dependency) and Python's text decoding,
so each gate's rules are copied nearly line for line.

Baselines moved to inline exceptions: forward-declarable-includes (1),
core-link-edges (37 live edges; its 2 dead entries are why the original fails
today) and rls-widenings (13 policies). Data that CMake reads, pattern-shaped
exemptions and ceilings stay as data or codec options.

Not ported:

- boost-deps reads files inside the vcpkg submodule, which compass's listing
  shows as one entry.
- xml-benchmark-recorded compares files at commits named in =history.tsv=;
  it needs a runtime input for a file at a named commit.
- format would format every C++ file on a first run (about 99 s) and needs a
  formatter in a check codec; whole-tree format with ratchet would match it.
- parameter-value-sets-only imports ORE's value-set generator; it moves to
  the generator gates task.

Decisions to revisit:

- PCRE2 and text handling live in =compass.platform=, which held only OS code.
- bff-list-requests reproduces prettier's array layout instead of running
  prettier; it matches the committed table byte for byte.
- Path and ceiling defaults are ORE's values as codec options.
