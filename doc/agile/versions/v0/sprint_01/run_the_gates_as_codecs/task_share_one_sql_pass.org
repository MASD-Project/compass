* Acceptance

- One SQL lexer and one per-file model (tables, columns, keys, policies, functions and their calls, includes) serve every SQL gate: sql_hygiene, sql_reachability, populate_refs, rls_widenings, rls_coverage, handler_permissions, entity_writes' SQL half and er_diagram.
- Every SQL gate gives the same findings on ORE Studio as before, except where a copied regex was wrong, each such change stated.
- populate_refs is a scan, and checks that a definition runs before its use in sql_reachability's include order.
- A SQL edit in the hook costs at least 300 ms less than today on the ORE copy, measured at a stated load.

* Plan

- Follow section 3 of =evidence/gate_review/plan.md= and the SQL part of

- Start from sql_hygiene's lexer and =er_model_of=; build the per-file model
  as a scan fact; move each gate onto it one at a time, comparing findings on
  the ORE copy after each.
