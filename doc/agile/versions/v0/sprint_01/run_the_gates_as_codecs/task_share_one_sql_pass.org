* Result

One SQL lexer (=ops::lex=) and one per-file model (=ops::model_of=:
statements, includes in order, tables, columns, keys, indexes, RLS, policies,
functions with their writes and =*_fn= calls) serve sql_hygiene,
sql_reachability, populate_refs, rls_widenings, rls_coverage,
handler_permissions and entity_writes' SQL half; =ops::walk_includes= gives
psql's run order. populate_refs is a scan and checks that a definition runs
before its use: ORE Studio is in order today, and reversing two includes gives
105 findings the old gate missed. No rule was renamed; the new
=populate_refs/unread_function= enforces the =*_fn= naming the facts rely on.

The one new finding on ORE Studio, =ores_mq_queues_tbl= under
missing_party_isolation, is real: the old column regex, like the Python one,
skipped a line with a comment after its comma.

er_diagram keeps its own parse, because its diagrams must stay byte-identical
to the Python's; its quadratic loop is fixed (331 to 88 ms). The gates remain
separate codecs, so a cold run still lexes each file once per gate; one fact
shared across codecs needs runtime support.
