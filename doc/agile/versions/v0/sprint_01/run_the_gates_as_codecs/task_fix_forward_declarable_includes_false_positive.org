* Result

The false positive came from ORE Studio policy compiled into compass, not
from the C++ model. The gate's default =types= was ORE's
=forward_declarable_types.list= as it stood at 545cafca45, where
=pq/transaction.hpp= defined =session_context=; ORE has since moved that type
into its own header. Given the pilot's own list, compass reports nothing, and
ORE's Python script given the old list reports the same finding; the model
sees every use of =transaction= (a test proves it).

- The default now places =session_context= in its own header.
- =forward_declarable_includes/stale_type_list= reports, on ORE's list file,
  any difference between that file (option =list_file=, by default
  =build/scripts/forward_declarable_types.list=) and the =types= in effect,
  naming each row and giving the exact =types== value to set, so the next
  edit to ORE's list is loud rather than silent.
- =forward_declarable_includes/type_not_defined= reports a listed defining
  header that no longer defines its type.
