* Acceptance

- A change to a codec's code, or to code it calls, changes the key of its stored results, with no hand-bumped version; a test proves a changed codec does not replay an older result.
- A commit that changes no codec code leaves every key, and every build artefact, unchanged.
- Shipping a new compass to the shared store re-runs only the codecs whose code changed.

* Plan

- Today a codec's results are keyed by a version set by hand, so a build that
  changes a codec without bumping it replays stale results, and every ORE
  Studio environment now shares one store.
- At build time, hash the sources each codec component compiles from (and the
  components it links), and compile the hash into that component only, through
  a generated file copied only when it changes, so a commit that touches no
  source of the component rebuilds nothing.
- Make the codec key the hand version plus that hash; keep the hand version
  for deliberate invalidation.
- Measure what a codec change re-runs on the ORE copy, and prove with
  =-d explain= that an unrelated commit rebuilds nothing.
