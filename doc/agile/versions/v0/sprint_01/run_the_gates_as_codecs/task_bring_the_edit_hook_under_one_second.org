* Acceptance

- =compass hook= reports in under one second warm for every single-file edit kind in ORE Studio, including codegen models and templates, C++ headers and new files.
- The hook still matches a full check on every edit of the comparison set, and =compass check= still reports the same 24 codegen drift files.

* Plan

- Make code generation incremental: a model edit re-renders only that model's
  outputs and those of the models that read it, and a template edit only that
  template's outputs. Each model's contexts and outputs are cached under a key
  of its recorded reads, including reads served from the shared load cache,
  and of the derived prework it uses (entity registry, checkout registry,
  template graph, catalogue).
- Cut the C++ and SQL scans that still cost most on an edit (stream_coverage,
  forward_declarable_includes, exported_types, populate_refs,
  test_case_reachability) and the cost of a new file, which joins listings.
- Keep the 24 codegen drift files and the hook-versus-check comparison exact.

* Result

Code generation is incremental, and the hook checks almost every edit kind in
under a second on a quiet machine. Under load, edits that change codegen
models or C++ facts and new files still take 1.4-1.7 s.

- Staged codecs: a prepare unit publishes facts (a name and the hash of a
  derived value), and each part is a unit whose inputs include the facts it
  read. Codegen is one part per model, 826 units on ORE. The entity and
  checkout registries record every lookup as a fact read, so a model edit
  re-renders only the models that read it, and a template edit re-renders only
  that template's outputs. A changed model stores about 230 KB instead of 193
  MB.
- SHA-1 is about two and a half times faster; it was half the instructions of
  a header edit.
- A scan whose facts are unchanged skips its reduce; component_docs and
  test_case_reachability scan file by file.
- The record is version 6 and the action format 5, so the first check after
  upgrading runs everything once.

Left open:

- populate_refs is not a scan (about 410 ms on SQL edits): its second pass
  builds a regex from the first pass's results.
- exported_types lists every file, so a new file runs its reduce (about 290
  ms); stream_coverage and forward_declarable_includes reduces cost about 510
  and 310 ms when facts change.
- Codegen's prepare step runs serially, about 140 ms.

Decisions to revisit:

- Skipping a reduce relies on the contract that a reduce is a function of its
  facts and what it reads through the view.
- A template edit keeps a part's other outputs from its last call; codegen
  uses this only when every changed input is a template fact.
- The agent's commits carry a =Co-Authored-By: Claude Fable 5.2= trailer,
  the model that wrote them.
