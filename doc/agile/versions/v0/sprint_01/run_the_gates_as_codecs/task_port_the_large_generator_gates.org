* Result

Four of the ten large gates are compass codecs: lint (a diagnostics scan in
=compass.docs=), er-diagram (the DDL parsing in =compass.sql=),
conventions-dataset and conventions-coverage. A warm check of ORE Studio with
every ported gate stays well inside the story's 10 s budget.

The check found one more piece of real drift in ORE Studio:
=ores_schema.dq_datasets.puml= predates a reworded table description.

The other six were not ported as copies: xml-bindings-drift depends on Python
object identity and dict order, file-types-seed on the unsorted order of
=os.walk=, ore-parameters-seed on about 7,800 lines of row and release logic,
and the three value-set gates on about 4,000 lines of value-set code. Copying
what the Python does is the wrong goal for them; [[id:E2B7B4B6-3097-4FFA-9EE1-E0ABDA80ECE4][Rethink the remaining generator gates]]
decides what each protects and the best way to do it. Separately, many ported
gates read the same files; [[id:F51A1EEB-55D4-4AC4-8119-360BF85EB570][Combine gates that read the same data]] merges
them into shared passes.

Decisions to revisit:

- A codec whose code changes under an unchanged version replays stale stored
  results; the verification scripts use a store of their own for that reason.
- lint reports durable-link advice only with =strict_links=true=, as the gate
  itself only advises.
- One full ctest run failed 1 of 14 suites once and passed six reruns; the
  failing test was not identified. An earlier unexplained single failure is
  recorded in the CLI story.
