* Acceptance

- A check runs against a past commit without a checkout, using cached parses where blobs are known.

* Plan

- Read a commit's tree and blobs from git's object store: loose objects and
  pack files, with their index, delta chains and zlib. A blob's ID is its git
  object ID, which is already the store's key, so a blob the store has parsed
  is never read again.
- Give the codec runtime a checkout source backed by a commit instead of the
  working tree, and add =compass check --commit <rev>=.
- Check that =compass check --commit= on a past ORE Studio commit gives the
  same diagnostics as a check of a checkout of that commit, and measure it
  cold and warm. Ratchet mode builds on this.

* Result

=compass check --commit <rev>= runs the configured checks against any commit
without a checkout, and gives the same diagnostics as a check of a worktree of
that commit. On ORE Studio a warm run takes about 2.1 s.

- =compass.store= reads git's object database itself: loose objects, version 2
  pack indexes, offset and reference delta chains and alternates, with zlib
  (a new vcpkg dependency). Only resolving =<rev>= starts git
  (=git rev-parse=).
- =.compass.org= and the contract pages come from the commit. A document whose
  ID the store knows is never parsed again; other files are read only when a
  codec asks for them.
- Ratchet mode gets the diagnostics of any commit by setting =options::commit=
  and calling =app::check=.

Decisions to revisit:

- Org blobs are always read, even when their parse is cached, because parsed
  objects hold byte ranges into the source. That costs 34 ms on ORE.
- Formatter programs and style files come from the checkout, not the commit,
  so ratchet against an old merge base could format with a newer style.
- Objects parsed for a past commit are named by no worktree index, so gc keeps
  them only for its grace period.
- Version 1 pack indexes and SHA-256 repositories are not supported.
