* Acceptance

- A branch that adds one violation to a file with existing violations fails on the new one only.

* Plan

- Add =compass check --ratchet [<base>]=: compute the merge base with the
  base (default the upstream, else =origin/main=), get its diagnostics with
  =app::check= at that commit, and fail only on diagnostics that are new.
- Match a diagnostic to its old self by file, rule and message, not by line,
  counting occurrences, so a violation that moves because lines were added
  above it is not new, and a second copy of an existing one is.
- Follow renames the merge base to HEAD diff reports, so a moved file keeps
  its old diagnostics.
- Prove the acceptance on a test repository and on the ORE copy: add one
  violation to a file that already has some, and only that one fails.

* Result

=compass check --ratchet [<base>]= fails only on diagnostics that are new
relative to the merge base of HEAD and the base (default the upstream, else
=origin/main=). Exit 1 means a new diagnostic, 2 a failed check or an
unresolvable base.

- A finding matches an old one by path, rule and message, counting
  occurrences, so a moved violation is excused and a second copy is new.
- Renames from the merge base to HEAD are followed, by identical blob first
  and by git's similarity detection only when that leaves a file unexplained.
- Drift at the merge base excuses drift now only when neither the file nor
  what the codec generates for it changed, compared by blob ID. Otherwise
  every ORE branch would fail on its 24 standing drift files, or a branch that
  changes a template behind an already-drifting file would pass.

Decisions to revisit:

- The merge base is checked with the working tree's =.compass.org=, so a gate
  a branch enables excuses violations that already existed.
- Each warm ratchet reads the 185 MB dependency record twice, about 1.6 s.
- Renames not yet committed are not followed.
