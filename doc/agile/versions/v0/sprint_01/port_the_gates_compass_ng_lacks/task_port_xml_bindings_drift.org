* Goal

ORE Studio's XML bindings generator runs as a compass-ng generator codec
whose output is byte-identical to the committed codec tables, so the
drift rule every generator codec has replaces =xml-bindings-drift=. The
gates-as-codecs story decided to keep the drift check and drop the
script's second, determinism run.

* Acceptance

- On ORE Studio's main, =compass check --codec xml_bindings= reports
  nothing and =compass diff= leaves every generated file unchanged.
- An edit to a generated file is reported as drift.
- The cases of =test_generate_xml_bindings_derivation.py= pass as Catch2
  tests.

* Plan

- Ported by a subagent; reviewed, rebased onto the single-writer merge
  and verified again here.
- =ops::xml_bindings= is the generator, a port of
  =generate_xml_bindings.py=: it reads the XSDs through the corpus view
  with compass's expat wrapper, and keeps the script's in-place edits to
  the schema tree and its tables keyed by node, because the output
  depends on them. =codecs::xml_bindings= runs it per family and formats
  with clang-format through the format cache, with the same options as
  =ore_output_catalogue=.
- The 13 families of =regenerate_xml_bindings.sh= are a table in the
  codec, each row its stem, root element and type, schemas and
  exact-decimal elements; the accessor, namespace, include and paths
  follow from the stem.
- A family whose schemas are missing, or that the generator refuses, is a
  =refused= finding and writes nothing; the others are still written.
- The script's second, determinism run is dropped, as the gates-as-codecs
  story decided.
