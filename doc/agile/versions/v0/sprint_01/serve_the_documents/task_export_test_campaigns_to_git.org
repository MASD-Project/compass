* Goal

Testers have no git. What they record in compass's service, runs, step
results, screenshots and notes, reaches git when a developer runs =compass
test export --environment <env> [--story <id>]=: each campaign becomes a
=test_campaign= page in its story's folder, with its screenshots beside it,
ready to commit. Exporting again rewrites the same files and leaves an
unchanged campaign untouched. The type gets its contract page, drafted in
compass for ORE Studio's contract, which compass's mirrors.

* Acceptance

- =compass test export --environment <env> [--story <id>]= writes, for each
  campaign of the environment, or the one of that story, a =test_campaign=
  page at =<story folder>/test_campaign_<id>.org=:
  - a heading per scenario, linking the scenario page, and under it a
    heading per run with the tester, the times, the definition's version
    and the outcome, a table of step results with their notes, and the
    screenshots, linked;
  - the campaign's notes grouped by kind, each a heading, =TODO= while open
    and =DONE= once addressed, naming its scenario or step and its author,
    with the reply when there is one.
- Screenshots are files in =test_campaign_<id>/= beside the page, named by
  the blob ID of their bytes. A PNG is a =.png=; JPEG, GIF and WebP are
  written as attached, with their own extension, and the command says so.
- The page's =:ID:= and file name come from the campaign's id, and each run's
  and note's =:ID:= from theirs, so a second export rewrites the same files
  and duplicates nothing. Files are written through
  =platform::filesystem::update_file=, so an unchanged campaign touches
  nothing. =exported_at= is set.
- Scenario pages are not modified.
- Text a tester typed cannot become org structure: a line org would read as
  a heading or keyword is escaped in an example block, a =|= in a table
  cell is written =\vert{}=, and a =[[=, a =]]= or the colon of a plain
  link such as =id:X= in a cell, a caption or a link's description is
  broken by a zero-width space, so it forms no link.
- The export's input is the campaign's rows and its output (path, bytes)
  files; the rendering is a pure function of the rows, tested without a
  database. No JSON.
- =doc/meta/document_type_test_campaign.org= is the type's contract, and
  =required_sections= holds exported pages to it; exported pages pass it.
  The same page and a handoff note are left for ORE Studio.
- Catch2 covers the renderer (runs, steps, notes open and addressed,
  screenshots, escaping), IDs stable across exports, and an unchanged
  campaign writing nothing; injected faults make them fail.

* Plan

The data shape comes first. The input is =types::campaign_rows=
(=compass.db/types/campaign_export.hpp=): the campaign, its story's page and
sprint, each scenario it ran or a note names with its runs, each run's steps
from the definition it followed and their results, its screenshots, the
notes, and each screenshot's bytes once. The output is a list of
=types::exported_file=, a path relative to the checkout and its bytes.

1. =query::read_campaigns= reads the rows of every campaign of an
   environment, or of one story, in one =REPEATABLE READ, READ ONLY=
   transaction, so a page is never a mix of two moments. A campaign whose
   story the environment no longer holds comes back with an empty path; the
   command skips it with a warning and exits 1.
2. =ops::render_campaign= renders the page and lists the screenshots. It is
   pure. =#+created:= is the day the campaign opened and =#+updated:= the
   day of its latest run or note, never the day of the export, or an
   unchanged campaign would be rewritten every day. =ops::derived_id= lays
   the SHA-1 of a name out as a version 5 UUID; the names are =compass
   test_campaign <environment> <story :ID:> <campaign id>=, with = run <id>=
   or = note <id>= after it.
3. =app::export_campaigns= writes each file through =update_file= and then
   sets =exported_at=. A crash part way leaves whole files, and a rerun
   converges.
4. =compass test export= parses as =db= and =sync= do, with =--story= its own.
5. The contract page, =doc/meta/document_type_test_campaign.org=, follows
   the other =document_type_*.org= pages, so the type registry reads its
   folder, level, TODO vocabulary and the three required sections.
6. =compass-bench campaign= gains =campaign <id> <tester>=, to add a note to
   a campaign whose runs are done, and takes an attached image's type from
   its extension, so the evidence can attach a JPEG.

No schema change: =activity.campaign.exported_at= is in migration 1.

* Notes

- Which environment a story's folder is read from: the exported
  environment's placement of the story page. The files are written into the
  checkout given with =-C=, so a developer exports a tester's environment
  into their own worktree.
- The screenshot bytes are written as the tester attached them. Nothing
  shrinks a large PNG; the service could refuse or downscale one at attach
  time if that matters.
- A screenshot file is never deleted by the export: the service has no way to
  remove an attachment, so nothing goes stale.
