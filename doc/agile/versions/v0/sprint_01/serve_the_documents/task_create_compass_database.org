* Goal

compass has a PostgreSQL database of its own for each repository, which every
environment of the repository shares. A developer names it once per machine
with =compass db init --database <connection string>=, and every compass
command that touches it finds it in the repository's local settings, refuses
a schema newer than it knows, and migrates an older one only when asked.

* Acceptance

- =compass.db= is a component of its own, in the domain layer, over libpq
  from vcpkg behind a small RAII wrapper: a connection, statements with
  parameters, result rows, transactions and =COPY=.
- The connection string is =#+database:= of the repository's local
  settings, =compass/local.org= under the git directory every worktree
  shares, written owner-only by =compass db init --database=.
- Versioned migrations create the =corpus=, =test= and =activity= schemas
  from the design's tables; =compass.migration= records them.
- =compass db init=, =compass db migrate= and =compass db status= work
  against a fresh database and an initialised one, and running either
  again changes nothing.
- A schema newer than the binary knows is refused by every command,
  =migrate= and =init= included; an older one is refused by every command
  but =migrate=, =init= and =status=.
- The text search configuration is chosen at init, =english= by default,
  and kept in the database, so every =tsvector= in it is computed the same
  way.
- Tests run against a throwaway cluster that =compass.testing= makes with
  =initdb= and =pg_ctl= on a Unix socket in a temporary directory, with no
  TCP port, and skip with a message where the server programs are missing.
  The Linux CI image installs them.

* Plan

- Local settings did not exist before this task: =.compass.org= is
  committed, and the =compass/local.org= of the design of Let projects
  define their checks was never built. A connection is per machine and per
  repository, and a worktree made tomorrow must find it, so it goes under
  the git common directory, beside the store, rather than in the checkout.
  Each worktree's own git directory may hold a =local.org= too, which wins;
  that is where a worktree's =#+environment:= goes.
- Bookkeeping is a fourth, small schema, =compass=: =migration= and
  =setting=. It belongs to none of the three data schemas.
- libpq is built without its default features (OpenSSL, lz4, zlib). The
  database is reached on a Unix socket or a private network; a server that
  requires TLS needs the =openssl= feature turned on.
- Each migration runs in its own transaction under an advisory lock, and
  re-reads the version under the lock, so two migrates apply each one once.
