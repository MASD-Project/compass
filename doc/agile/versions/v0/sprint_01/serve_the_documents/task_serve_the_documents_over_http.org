* Goal

=compass serve= answers the design's routes on Boost.Beast with ORE
Studio's router, moved into MASD. Every route declares its tool, area, entity,
whether it writes and its typed body, as ORE Studio's do. The caller is read
from the gateway's =Compass-View=, =Compass-Subject= and =Compass-Actor=
headers, or locally from the =team= view and the developer's git user name,
and every write records its subject and actor in =activity.action=. See
[[id:AF30B206-2FAB-435F-819F-9EC652D4E40D][Design: aligning the document service with ORE Studio's HTTP and MCP]], sections 3 and 4.

* Acceptance

- Every route in the alignment design's table answers, under
  =/v1/{environment}=, and the router's start-up gates accept every route.
- A request without a view is refused, and a write without a subject; a
  request body never names the tester.
- The six campaign writes take a =caller= and record one =activity.action=
  row each, with the subject and the actor, in their own transaction; a
  migration creates the table.
- =GET /v1/catalogue= answers every route's declaration and input schema.
- With a gateway secret configured, a request without it is refused.
