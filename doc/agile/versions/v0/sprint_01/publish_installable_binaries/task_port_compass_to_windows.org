* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

Give each operating-system facility one seam in =compass.platform=, with a
POSIX and a Win32 implementation side by side in the seam's source file, as
ORE Studio's =ores.platform= does. Callers in the store, the codecs, the CLI
and the bench use the seam and include no OS header. Where standard C++ does
the same work at no cost on Linux, use it instead of a seam.

- Seams. =filesystem/file_status= (=lstat=, =fstat= and read, the coarse
  file clock), =filesystem/new_file= (=O_EXCL= create and write),
  =filesystem/file_lock= (=flock=), =process/environment= (=getpid=,
  =setenv=, the home directory as git finds it),
  =process/standard_streams= (binary standard streams on Windows),
  =process/executable= gains =find_program=, moved from =compass.codec=, and
  =compiler/always_inline= replaces the GNU attribute in the SHA-1 rounds.
  =mapped_file=, =run_program= and =executable_path= gain Win32 bodies.
- Standard C++ instead of POSIX: =std::chrono::system_clock= for
  =clock_gettime(CLOCK_REALTIME)=, =std::filesystem= for =unlink=, =rename=
  and the bench's and CLI's =stat= and =lstat= checks, which are not on the
  hot path.
- Hot paths. =stat_of= and =hash_file= keep one =lstat= or one open, =fstat=
  and read on Linux; =mapped_file= keeps =mmap=. Measure warm
  =compass check= on an ORE Studio export before and after.
- Tests. Shell commands run through =run_program= with =sh -c=, which Git for
  Windows provides, instead of =std::system= and =popen=. Test cases that
  need what only POSIX has carry the =[posix]= tag, which the Windows runs
  filter out; the multi-process pack store test forks, so it is built on
  POSIX only.
- CI. Check out with LF line endings. Iterate on the branch with
  nightly-windows until both legs build, test and package.

* Notes

- Seams. =compass.platform= gained =filesystem/file_status= (status,
  whole-file read, set the modification time, the file clock),
  =filesystem/new_file= (exclusive create, write, and =replace_file=),
  =filesystem/file_lock=, =process/environment= (process ID, set a
  variable, home directory), =process/standard_streams=,
  =compiler/always_inline=, and =find_program=, moved from
  =compass.codec=. =mapped_file=, =run_program= and =executable_path= have
  Win32 bodies; the POSIX bodies have macOS spellings where Linux names
  differ (=pipe2=, =st_mtim=, =CLOCK_REALTIME_COARSE=, =addchdir_np=).
- On Windows =mapped_file= reads the bytes instead of mapping them:
  Windows will not delete a file with a mapped view, and the store deletes
  packs that other processes read. =replace_file= renames with POSIX
  semantics, since =MoveFileEx= fails while a reader holds the target.
- Paths. Windows joins paths with backslashes, so every path compass
  prints or keys on is =generic_string()=; on POSIX that is the same
  string. Paths in exceptions rows and codec outputs with a root, a drive
  letter or a backslash are refused.
- Left to POSIX, by the =[posix]= tag the Windows suites filter out: the
  format cache tests and three codegen CLI tests, whose fake formatter is
  a shell script Windows cannot run; the worktree index's inode test; and
  the two tests that expect a rewrite to change ctime, which git for
  Windows does not record (it stores the creation time), so compass, like
  git, trusts size and mtime there. The multi-process pack store test
  forks and is built on POSIX only; the install test lays compass out in a
  POSIX home and is registered on POSIX only.
- CI. The Windows checkout keeps LF; the clang leg installs LLVM 22.1.8,
  because MSVC 14.52's library refuses older Clang.
- Hot paths. =stat_of=, =hash_file= and =mapped_file= keep one =lstat=,
  or one open, =fstat= and read, and one =mmap= on Linux. =strace -c= of
  a warm =compass check= on an ORE Studio export counts the same system
  calls for the base and the port (newfstatat 336747 both, openat 55010
  both, read 66112 against 66121). Callgrind counts 47,083,678,080
  instructions for the base and 47,138,044,963 for the port in a warm
  single-threaded check, 0.12% more. Timed runs cannot resolve that on
  the shared machine: at a load of 16 to 21, fifteen alternated warm runs
  took a median 6.85 s (base) and 7.13 s (port) of CPU, and wall times
  ran 6 to 37 s.
