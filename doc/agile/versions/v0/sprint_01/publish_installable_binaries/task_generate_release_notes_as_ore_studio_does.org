* Goal

At sprint close, a maintainer runs five =compass release-notes= verbs and
gets what ORE Studio gets: the sprint's release notes rendered from its
stories and merged PRs, health charts, a GitHub-flavoured Markdown body
whose images and links resolve on GitHub, and a draft GitHub release
titled =<tag>, "<Codename>"=. The first compass release, which has no
earlier tag, works the same way.

* Notes

** Departures from ORE Studio

- *Location.* The verbs live in =projects/compass.legacy/src/=, the
  tool =compass.sh= forwards to, not =projects/ores.compass/src/=. The
  exporter lives in =projects/compass.legacy/lisp/= beside
  =ores-org-ids.el=, which it loads; compass has no =ores.lisp=. It
  keeps its ORE name, =ores-build-release-notes.el=, and the =ores/=
  prefix, as the other files in that directory do.
- *Sections.* =TAG_SECTIONS= and =KEYWORD_SECTIONS= are replaced by
  sections drawn from the filetags of sprint 1's stories: Parsing &
  Data Model, Pipeline & Store, Codegen, Gates & Checks, Documents &
  Search, CLI & Tooling, Code Analysis, Build, CI & Release, Agile &
  Documentation. ORE's sections (Financial Features, Market Data, and
  so on) name nothing compass builds. The scoring is unchanged.
- *id: links.* ORE Studio exports an =id:= link to its published site.
  compass publishes no site, so the link becomes the github.com blob URL
  of the linked =.org= file, which GitHub renders.
- *First release.* ORE's collector exits when no =v*= tag exists.
  compass has no tag yet, so the collector falls back to the first
  commit, and the time summary says "since the first commit".
- *Sprint duration.* ORE derives it from the stories' dates, which a
  carried story stretches back into an earlier sprint; ORE Studio's
  capture "Release notes Sprint duration uses carried-over story dates"
  records the bug. compass reads the sprint's =#+start_date= and
  =#+end_date= first (then the Status table), and falls back to story
  dates only while the sprint has no end.
- *Names.* The title reads =compass-ng Sprint N – Release Notes=; the
  screenshot convention is =compass-v<tag>.png=; pystache comes from the
  compass.legacy venv. The recipe makes the screenshot optional: compass
  is a command-line tool, and the readme does not show one.
- *PR step.* ORE's =commit= tells the user to run =compass pr create=;
  compass.legacy has no =pr= command, so it says =gh pr create=, and the
  recipe and skill link [[id:CC928252-E0C5-4C3C-A7A8-D613593E4E37][How do I create a PR?]] where ORE names its
  PR Manager skill.
- *Template.* Unchanged. compass's copy differs from ORE's only in the PR
  cycle legend: ORE changed its chart to a log-scale dot plot, and
  compass's chart, in =doc/agile/sprint_charts.org=, is still one bar
  per PR, which compass's text describes.
- *Chart scripts.* ORE commits =scripts/sprint_*.gnuplot=; compass never
  tangled them from =doc/agile/sprint_charts.org=, so =sprint charts=
  skipped every chart. They are tangled and committed.
- *Ignored files.* =/tmp/= (the collector's PR data) and
  =/.org-id-locations-file= (written by the exporter and by
  =compass index --org-ids=) are added to =.gitignore=.
- *Docs.* The pipeline design is ported with its ORE id, so the recipe's
  and skill's links, which pointed at a placeholder id, resolve. The
  recipe's link to "How do I bump the project version?" is dropped:
  compass has no such recipe. Sprint closure step 4 now names the verbs.
- *Tests.* ORE has none for this pipeline. =test_release_notes.py= runs
  =draft= in a temporary repository whose origin is a local bare
  repository, with =gh= a PATH stub that records its arguments; it also
  tests the collector's first-release fallback, the sprint duration and
  the section grouping.
- *Not taken.* ORE Studio's capture "Merge release notes collector
  script into compass" would fold the collector into a compass verb.
  This task copies first; the collector stays a script.

** Proof on sprint 1

=create=, =charts= and =export= ran on sprint 1 at its real path. The
generated =release_notes.org=, =release_notes.md=, the four PNGs and the
link =create= appends to =sprint.org= were then removed, because sprint 1
is not closed. The Markdown groups the stories as listed in Measurements;
its chart images point at
=https://raw.githubusercontent.com/MASD-Project/compass/main/doc/agile/versions/v0/sprint_01/=;
a =proj:= link and an =id:= link added to the notes by hand exported to
=github.com/MASD-Project/compass/blob/main/...= URLs; =data_model=
stayed literal rather than becoming a subscript. =commit= and =draft=
were not run against GitHub.

sprint 1 records its =End=, the window covers the sprint.
