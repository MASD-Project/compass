* Goal

A reader of the store on Windows does not fail because another thread or
process is replacing the file it opens. The MSVC nightly of 2026-11-20
failed =concurrent writers of one object all succeed and leave it whole=,
which counted a failed read as a torn one.

* Acceptance

- The test tells a read that fails from one that returns other bytes, and
  says the first failure's error.
- On the MSVC release build, the test passes every run of a batch that
  failed about one in ten before.

* Plan

- Measure: run the test 30 times under =windows-test-debugger.yml=.
- Instrument the test to name the failure, and run it again.
- Retry the one error seen, in the one open both readers share.

* Notes

- The replace itself is sound: a reader never saw other bytes. Windows
  refuses an open of the name, as access denied, for a moment around the
  replacing rename. Git for Windows retries the same error.
- =open_existing= (=compass.platform/src/filesystem/open_existing.hpp=)
  tries access denied ten times over about 45 ms; =read_file= and
  =mapped_file= open through it. A file that is really denied costs those
  45 ms and fails as before.
