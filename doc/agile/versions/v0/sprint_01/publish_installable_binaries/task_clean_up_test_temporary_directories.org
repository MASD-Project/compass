* Goal

A test run leaves nothing in the temporary directory, whether its tests
pass, fail, throw or are killed.

* Acceptance

- A =compass.testing= component, laid out as ORE Studio's =ores.testing= and
  per =component_architecture.org=, holds one =scoped_directory=.
- Every test fixture that makes a temporary directory (31 today, found with
  =grep temp_directory_path projects/*/tests=) uses it, holding it as its first
  member so a later throw in the fixture's constructor still removes it.
- Constructing one removes leftover directories with its prefix whose process
  is no longer running, so a killed or crashed run is cleaned by the next one.
- With =git= made to fail, =compass.cli.tests= leaves no directory behind;
  today it leaves 67.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

Replace the suites' own temporary-directory classes with one
=scoped_directory= in a new =compass.testing= component, and make it clean up
after processes that died, not just after itself.

- Seam. =compass.platform= gains =process/liveness=: =is_running(pid)=, which
  is =kill(pid, 0)= on POSIX, where =EPERM= still means running, and
  =OpenProcess= with =GetExitCodeProcess= on Windows, where access denied
  still means running. IDs 0 and those past =pid_t= are never running, since
  =kill= reads them as process groups.
- Component. =compass.testing=, laid out as =component_architecture.org=
  says: =include/compass.testing/filesystem/scoped_directory.hpp=, its
  source, its tests and =modeling/component_overview.org=. It sits in the
  tooling layer and depends only on =compass.platform=.
- Shape. =scoped_directory(prefix)= creates
  =<temp>/<prefix>.<pid>.<n>= with =create_directory=, taking the next =n=
  until one is new, and removes it on destruction, ignoring a failure the
  next run will clean up. Before creating it, it removes every
  =<prefix>.<pid>.<n>= whose =pid= is neither this process nor running. The
  name must have exactly that shape, so another suite's prefix that starts
  with this one is left alone. The temporary directory is canonical, as the
  store's tests already made it, because Windows may give its 8.3 name and
  git prints the long one.
- Fixtures. A fixture with more to it than a directory holds the
  =scoped_directory= as its first member, so a throw later in its
  constructor still removes it; a class that only made and removed a
  directory is deleted and its tests declare a =scoped_directory=. Two
  migration scripts do the mechanical part and the rest is by hand. Each
  fixture keeps its prefix, except =run_after_edit= in the =cpp=, =sql= and
  =crosscheck= suites, which shared =compass.tests.edit= and now name their
  suite.

* Notes

Two leak paths were found on 2026-11-18. =scoped_git_repo= in
=compass.cli/tests= runs =git= through =REQUIRE= in its constructor, so a failing
=git= throws before the object exists and its destructor never runs: with a
=git= that exits 1, one run of =compass.cli.tests= left 67 directories. A test
process that is killed, crashes or times out leaves its directories too; a
=compass.store.tests= directory was found that way. A passing run leaves
nothing (three full =ctest= runs).

- Fixtures moved. All 31: =compass.store= (its =scoped_directory=, which
  =git_repository= held), =compass.cli= (=scoped_git_repo=, =scoped_bin=),
  =compass.bench= (=scoped_git_repo= and eight fixtures of its own),
  =compass.codec= (eleven, =git_diff= among them), =compass.codegen=
  (=scoped_bin=), =compass.platform= (four, the mapped file tests' file among
  them), and =run_after_edit= in =compass.cpp=, =compass.sql= and
  =compass.crosscheck=. A file fixture keeps its file in a =scoped_directory=
  of its own, so the sweep covers it too.
- Left alone. The two =temp_directory_path= uses in the =mapped_file= tests
  make nothing: one names a path that must not exist, the other is the
  temporary directory itself. =end_to_end.sh= and =install_compass.sh= take
  =mktemp -d= and remove it on =EXIT=; a =SIGKILL= still leaves that
  directory, but its =tmp.*= name says nothing of its owner and a sweep needs
  one.
- What a sweep cannot see. A directory whose process ID has been reused by a
  running process stays until that process ends. A directory another user
  owns stays, since the sweep cannot remove it. Neither is this run's.
- The first leak path was not the CLI's alone. =scoped_git_repo= and the
  =ids= stage fixture in =compass.bench= ran =git init= through =REQUIRE= in
  their constructors as the CLI's did. =git_repository= in =compass.store=
  did not leak: it already held its directory as a member, which is
  destroyed when the constructor throws.
- Two CI legs needed a second attempt. The macOS debug leg was cancelled
  after 15 minutes in the queue without a runner, and passed when rerun.
  The MSVC leg's first attempt failed one check in =compass.store.tests=:
  "concurrent writers of one object all succeed and leave it whole" saw a
  torn read (=torn == 1=, =io_object_file_tests.cpp= line 122), and the
  rerun passed. That test races a reader against writers that replace the
  file; the change here only renames its directory, so the failure is the
  store's on Windows. A likely cause, not yet confirmed, is that opening a
  file while a POSIX-semantics rename replaces it can fail on Windows, which
  =read_file= reports as no file. It needs its own task.

* Result

compass.testing holds one =scoped_directory=, and all 31 fixtures that made a
temporary directory use it, holding it first so a throwing constructor still
cleans up. It sweeps leftovers of dead processes through a new
=compass.platform= liveness seam. With a failing =git=, =compass.cli.tests= went
from 67 leaked directories to 0 (bench from 19 to 0); a test binary killed with
SIGKILL is cleaned by its next run. Windows 44349586854 and macOS 44349592992
pass with 0 warnings. The torn read one MSVC attempt hit is a store race, filed
as Read store objects while Windows replaces them.
