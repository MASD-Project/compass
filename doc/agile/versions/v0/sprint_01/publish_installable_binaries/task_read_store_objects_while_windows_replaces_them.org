* Goal

On every platform, a process reading a store object never sees it missing or
torn while another process replaces it with the same content.

* Acceptance

- The cause of the torn read is found and recorded: the failing call and its
  Windows error, not a guess.

- The concurrent-writers test in =io_object_file_tests.cpp= passes on MSVC and
  Windows clang over many repeated runs, recorded under Measurements.

* Notes

Nightly Windows run 44349586854's MSVC leg (first attempt) failed
"concurrent writers of one object all succeed and leave it whole" with
=torn == 1= at =io_object_file_tests.cpp:122=; the rerun passed. The test races a
reader against writers that replace the file. The guess, not confirmed, is that
opening the file while =replace_file= renames over it fails with a sharing
violation, which =read_file= reports as no file. Found by Clean up the tests'
temporary directories, whose change only renamed the test's directory.
