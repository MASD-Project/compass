* Notes

- The cause is MSVC's, in =store_range=: [[file:evidence/msvc_store_stage_fault.txt][evidence/msvc_store_stage_fault.txt]].
  Windows passes the 8-byte =file_range= in =r9=, begin in the low half and
  end in the high. MSVC copies it to =rbx=, compares =ebx= with the end and
  zero-extends it into =edi= correctly, then loads =ids[row]= with
  =mov ecx, [rax+rbx*4]=: the whole =rbx=, so the end is the index's upper
  32 bits. With the range {2, 3} the index was =0x0000000300000002=.
- The crash came and went because it depends on the process: run under a
  debugger with its debug heap, all four in one process, none faulted.
- Counting in =std::size_t= leaves no 32-bit counter to widen. The ids,
  parse, org, types and read stages had the same loop and take the same
  change.
- The =concurrent writers of one object= store test failed once in the same
  run: a reader saw the object torn. It is a separate failure.
