#+title: How do I check edits as Claude Code makes them?
#+description: Add compass hook as a Claude Code PostToolUse hook on Edit, Write and MultiEdit, so the agent sees the findings on each file it edits right after the edit.
#+type: recipe
#+level: cross
#+filetags: :compass:cli:claude_code:hooks:
#+created: 2026-11-17
#+updated: 2026-11-17

=compass hook= is the edit hook of
[[id:45FA67C9-60BC-420D-BB66-8A272CB1106C][compass.cli]]. It checks one
edited file with the units of the dependency record that read it, and
answers Claude Code in the form its hooks expect.

* Question

How do I make Claude Code see compass's findings on a file right after it
edits the file, without waiting for a full =compass check=?

* Answer

Run =compass check= once in the checkout, so it has a dependency record.
Then add this to the =hooks= object of the Claude Code settings the checkout
uses, such as its =.claude/settings.local.json=. Change the path to where
your =compass= executable is:

#+begin_src json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "/path/to/compass-ng/build/output/linux-clang-release/publish/bin/compass hook",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
#+end_src

In a repository whose settings are tangled from an org page, such as this
one's [[id:2D83251F-0E24-4B97-B736-08F710316634][Claude Code Settings]],
add the entry to that page instead. Neither this repository nor ORE Studio
installs the hook yet.

After each Edit, Write or MultiEdit, Claude Code writes a JSON payload to
the hook's standard input. The hook reads =tool_input.file_path=, takes a
relative path against =cwd=, and checks that file in the checkout that
holds it, whatever the working directory. It prints one of three things
and always exits 0:

- Nothing, when the file is in no checkout, git ignores it, no codec reads
  or reports on it, or it has no findings.
- ={"decision": "block", "reason": "..."}= when it has findings. Claude
  Code shows the reason next to the result of the edit. The edit has
  already happened; =block= only makes the agent read the reason. The
  reason counts the findings and lists each one as =compass check= prints
  it:

  #+begin_example
  compass found 1 finding on or caused by the edit to sql/a.sql:
  sql/a.sql:2:1: sql_hygiene/not_re_runnable: create table without `if not exists`; a second run would fail (fix: make the statement idempotent)
  #+end_example

- ={"hookSpecificOutput": {"hookEventName": "PostToolUse",
  "additionalContext": "compass hook: ..."}}= when it could not check the
  file, with the reason: no record yet, a damaged record, a configuration
  error, an edit to =.compass.org= or a contract page (which changes what
  every codec sees), or a failure. The agent is never blocked by compass
  failing.

The findings are those a full =compass check= reports on the file, and
those it reports on other files that the edit caused, such as a SQL file
another edit left unreachable, or drift of an output whose generated bytes
the edit changed. Findings on other files that were there before the edit
are left out. Inline exceptions apply as they do for =compass check=, and
=--today= sets the date their expiry is judged against.

The hook writes nothing: not the store, the dependency record nor the
result cache. It takes the record as describing the checkout before the
edit, so run =compass check= now and then; until you do, a finding an
earlier edit caused on another file can be reported again.

=--timings= prints each step and each codec's running time to standard
error, which Claude Code does not show the agent:

#+begin_src sh :results verbatim
echo '{"tool_name": "Edit", "cwd": "'"$PWD"'", "tool_input": {"file_path": "sql/a.sql"}}' \
  | build/output/linux-clang-release/publish/bin/compass hook --timings
#+end_src

On ORE Studio, warm, an edit to a CMakeLists.txt or a file no codec reads
returns in well under a second, and an org document in about one second.
An edit to C++, SQL, a codegen model or a template takes 3 to 5 seconds,
because the gates that scan every C++ or SQL file, and codegen, run whole
again; [[id:45FA67C9-60BC-420D-BB66-8A272CB1106C][compass.cli]] has the
breakdown.

* Script

=compass hook= (=projects/compass.cli=, =app::hook=, with the payload read
by =io::parse_hook_payload= and the units found by
=codec::ops::units_touching=).

* Tested by

=compass.cli.tests= (=[hook]=): a finding on the edited file, a file left
unreachable by an edit to another, drift of an output a document feeds and
of an edited output, a new document, inline exceptions, a file no codec
reads or outside any checkout, a relative path, and each way the hook fails
open, each compared with what =compass check= reports.
=compass.codec.tests= (=[unit_index]=) checks, for an edit to every file of
a test checkout, that each unit a full run calls again is one the index
names.
