This page is the component overview for =compass.testing=, a simple component
in the tooling layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.testing= is the shared infrastructure compass-ng's test suites build
on, as =ores.testing= is for ORE Studio. Its consumers are the test binaries of
the other components, never production code. It holds two facets.
=filesystem= has =scoped_directory=: a new directory under the system
temporary directory, named =<prefix>.<process ID>.<number>=, removed with
everything in it when it is destroyed. The caller gives the prefix, such as
=compass.store.tests=, so a directory left behind names its suite.
=database= has =scoped_cluster=: a PostgreSQL cluster that =initdb= makes in
a =scoped_directory= and =pg_ctl= starts, listening on a Unix socket in that
directory and on no TCP port, so it never meets a server the machine already
runs. It is stopped and removed when it is destroyed.

A test run must leave nothing in the temporary directory whether its tests
pass, fail, throw or are killed. A fixture holds its =scoped_directory= as its
first member, so a throw later in the fixture's constructor, such as a failing
=git init=, still removes the directory. A process that is killed, crashes or
times out runs no destructor, so constructing a =scoped_directory= first
removes each directory with the same prefix whose process is no longer
running: the next run of the suite cleans up after the last.

* Inputs

- A prefix naming the suite.
- For a cluster, the PostgreSQL server programs: the directory that
  =COMPASS_TEST_POSTGRES_BIN= names, else the directory of =initdb= on
  =PATH=, else the newest =/usr/lib/postgresql/<version>/bin=, where Debian
  and Ubuntu install them.
- The system temporary directory, as =std::filesystem::temp_directory_path=
  gives it.

* Outputs

- =scoped_directory=: =path()= is the directory's absolute path, by its long
  name on Windows, where the temporary directory may be named by its short
  8.3 name and git prints the long one.
- On construction, every =<prefix>.<process ID>.<number>= in the temporary
  directory whose process is not running is removed. A name that does not
  have that exact shape, or that names this process or a running one, is
  left alone, as is one this user may not remove.
- On destruction the directory is removed. A failure to remove it, such as
  a file still open on Windows, is not reported; the next run removes it.

- =scoped_cluster=: =create_database()= makes a new, empty database and
  returns its libpq connection string. The superuser is =compass=, every
  local connection is trusted, and =fsync= is off. Run as root, as in the
  CI container, the server programs run as the =postgres= user through
  =runuser=, since =initdb= refuses root, and the directory is given to that
  user. =shared_cluster= starts one cluster per test process on first use.
  When no server programs are found it returns none and says why, and the
  test skips with that message, so a macOS or Windows machine without
  PostgreSQL passes.
