This page is the component overview for =compass.sql=, a simple component in
the domain layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.sql= runs ORE Studio's SQL gates as corpus codecs: =sql-hygiene=
(=projects/ores.sql/utility/check_sql_hygiene.py=), =populate-refs=,
=sql-reachability=, =rls-widenings=, =handler-permissions= and
=curve-parameter-paths=. Each script reread its files on every run; a codec
reads them through its view, so a run in which none of them changed reuses
its findings without reading any. =sql_hygiene= and =sql_reachability=
are scans: a file's findings, or its =\i= and =\ir= lines, are kept per
content ID, so a run after an edit reads the edited file alone.

The gates after =sql_hygiene= take their scripts' regular expressions
verbatim through =compass.platform='s =text::regex=; =ops::scripts= holds
the helpers they share: comment blanking, top-level splitting and pathlib's
order.

The scanner is a port, not a parser: it reproduces the script's rules,
including what they get wrong, such as reporting =create  table  if not
exists= with two spaces before =if=, because the acceptance of the port is
the same verdict on the same commit. It works on bytes: a byte of 0x80 or
more counts as a word character, and the non-ASCII spaces Python's =\s=
matches are not spaces. tree-sitter is not used: its SQL grammar does not
read psql scripts (see
[[id:E2DCD7CE-4CFC-47D8-A65D-E05A4CA48EB6][Measure tree-sitter parsing]]).

The codecs are off by default, and =codecs::catalogue= lists them.

* Inputs

- The =.sql= files under each directory of the option =roots=,
  comma-separated, default =projects/ores.sql=, through =list_files= and
  =read_file= of the corpus view.

* Outputs

- *=sql_hygiene=.* One finding per defect, under four rules.
  - =unterminated_block_comment=: a block comment is still open at the end
    of the file. Block comments nest, as in PostgreSQL; =--= comments,
    dollar-quoted bodies and both quote styles hide the markers. The finding
    is at the outermost comment still open.
  - =duplicate_index=: =create [unique] index if not exists= appears more
    than once with the same name, table and columns, compared lower-cased
    with the columns' spaces collapsed. The finding is at the first.
  - =comment_splits_literals=: a comment stands between two string literals,
    which PostgreSQL joins only across whitespace; dollar-quoted bodies are
    scanned too. The finding is at the comment.
  - =not_re_runnable=: in the text with comments, literals and bodies
    masked (=ops::mask_non_code=), =create table=, =sequence=, =extension=,
    =schema= or =materialized view= without =if not exists=; =create
    trigger=, =rule=, =view=, =function= or =procedure= without =or
    replace=; =create index= without =if not exists=; =create policy= with
    no =drop policy if exists= of the same name and table in the file; and
    =create type= or =domain= with no =drop ... if exists= of the same name.
  A message holds no count: the script's depth of an open comment and the
  number of times an index is created are left out.

- *=populate_refs=.* =populate-refs=
  (=projects/ores.codegen/scripts/check_populate_references.py=). Rule
  =unresolved_reference=: a populate call passes literal names to a function
  whose body raises =not found= on a lookup, and no populate call to a
  function that inserts that row passes the same names. Rule
  =unbalanced_parentheses=: a definition or call the check reads does not
  close, where the script stops with a traceback.
- *=sql_reachability=.* =sql-reachability= (=check_sql_reachability.py=).
  Rule =unreachable_file=: a file under =create=, =populate= or =drop= that
  no =\i= or =\ir= walk from the root scripts and the four declared entry
  points reaches. Rule =missing_include=: an include or entry point names
  no file.
- *=rls_widenings=.* =rls-widenings=
  (=check_rls_system_tenant_widenings.py=). Rule =system_tenant_widening=:
  a =create policy= under =create= compares the current tenant with the
  system tenant. The script's table of excused policies is replaced by
  inline exceptions on their =create policy= lines.
- *=handler_permissions=.* =handler-permissions=
  (=check_handler_permissions.py=). Rule =unseeded_permission=: a handler of
  a component of the =components= option checks a code the =seeds= script
  does not seed.
- *=curve_parameter_paths=.* =curve-parameter-paths=
  (=projects/ores.sql/utility/check_curve_parameter_paths.py=). Rule
  =undeclared_path=: a quoted =/CurveConfiguration/= path of the artefact
  that the ORE curve schema does not declare and no exemption explains.
  Rule =stale_exemption=: an exemption no path needs. The exemptions file
  stays, because a rule is a pattern over paths, not a line.

- *ER model.* =ops::er_model_of= reads the create scripts, in the order
  given, as =projects/ores.codegen/src/plantuml_er_parse_sql.py= does: the
  =create table if not exists= statements by regular expression, their
  columns line by line with the script's type shortening, the primary key,
  the description in the =-- ===== = block or the =/** */= comment above the
  table, the unique indexes, and the foreign keys a script states (a
  =soft FK= comment, =references= on a column, a =foreign key= constraint),
  each kept only when one table of that script owns the column. It returns
  the model as the diagram draws it: the packages in the order of their
  component, the data quality tables split into four groups by the shape of
  their names, each table's classification, key columns and other columns
  with the temporal ones last, and the relationships from parent to child
  with the script's labels. The script's tables, its component prefixes,
  the columns it takes as keys by name and the styles, are parameters
  (=ops::er_conventions=), because the caller reads them from the script's
  source. The parser's convention warnings are not ported.

* Dependencies

- =compass.codec= for the descriptor, the corpus view and the diagnostic
  table.
- =compass.platform= for regular expressions and Python's decoding.
- The C++23 standard library.
- =compass.store= and Catch2, for the tests only.
