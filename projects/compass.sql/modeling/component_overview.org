This page is the component overview for =compass.sql=, a simple component in
the domain layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.sql= runs ORE Studio's SQL gates as corpus codecs: =sql-hygiene=
(=projects/ores.sql/utility/check_sql_hygiene.py=), =populate-refs=,
=sql-reachability=, =rls-widenings=, =handler-permissions= and
=curve-parameter-paths=. Each script reread its files on every run; a codec
reads them through its view, so a run in which none of them changed reuses
its findings without reading any. Every gate but =curve_parameter_paths=
is a scan: what a file says is kept per content ID as its findings and its
/fact/, so a run after an edit reads the edited file alone and joins the
stored facts.

Every SQL gate reads its files through one lexer and one model.
=ops::lex= tokenises a file once, as PostgreSQL does where the gates need
it; =ops::model_of= reads the file's statements from the tokens, and each
gate keeps in its fact the part of the model it needs. A rule over the
model reads code only: a comment or a literal states no table, policy,
include or call. The gates were first ported regular expression for
regular expression; where the model reads a file differently, the
regular expression was wrong, and each such case is listed with its
codec below. =ops::scripts= keeps pathlib's order and the helpers
=er_model_of= and =curve_parameter_paths= use.

The lexer works on bytes: a byte of 0x80 or more counts as a word
character, and the non-ASCII spaces Python's =\s= matches are not spaces.
tree-sitter is not used: its SQL grammar does not read psql scripts (see
[[id:E2DCD7CE-4CFC-47D8-A65D-E05A4CA48EB6][Measure tree-sitter parsing]]).

The gates are separate codecs, so a cold run still reads and lexes a file
once per gate that scans it: a fact belongs to the codec that made it.
Sharing one fact between codecs needs the runtime support of the
[[id:F51A1EEB-55D4-4AC4-8119-360BF85EB570][Combine gates that read the same data]]
task.

* SQL model

- *Lexer.* =ops::lex= returns the tokens of a text without the spaces
  between them: words, quoted names, ='...'= literals with =''=, dollar
  bodies from =$tag$= to the same tag, =--= and nested =/* */= comments,
  psql meta-commands from a backslash that starts a line to the end of
  it, and single-byte symbols. It also says where the outermost block
  comment still open at the end begins. A body is lexed again when a gate
  reads inside it, with meta-commands off.
- *Model.* =ops::model_of= splits the code tokens into statements at each
  =;= and meta-command, at the top level and in every dollar body, and
  reads from them, lower-cased and without schema or quotes:
  - the includes, =\i=, =\ir=, =\include= and =\include_relative=, in
    order (=ops::includes_of= gives them alone);
  - each =create table= with its columns, their types and its primary key;
  - each =create index= with its name, table, the text between its
    parentheses and whether it says =if not exists=;
  - the tables that =alter table= enables row-level security on;
  - each =create policy= with its table, whether it is restrictive, names
    =party_id= or compares the current tenant with the system tenant;
  - each =create function= with its parameters, and from its body the
    lookups it guards (a =select ... from T where col = p_x= followed by a
    =raise exception= whose message says =not found=), the rows it inserts
    and the =ores_*_tbl= tables it writes, in code or in the SQL of the
    literals it executes;
  - each call of a function named =*_fn= with at least one literal
    argument, and the value of each argument that is one literal;
  - each call or function whose parentheses do not close.
  DDL inside a PL/pgSQL body is read where its keyword stands, after
  =begin= or =then=.
- *Includes.* =ops::walk_includes= walks the includes depth first in
  include order from the scripts directly under =projects/ores.sql= and
  the four entry points nothing includes, as psql runs them. It reports
  each include and entry point that names no file, and numbers the runs
  of each file between its includes, so =when= says which of two
  statements psql runs first. A file psql reaches twice runs where it is
  first reached; both branches of a =\if= count.

The codecs are off by default, and =codecs::catalogue= lists them.

* Inputs

- The =.sql= files under each directory of the option =roots=,
  comma-separated, default =projects/ores.sql=, through =list_files= and
  =read_file= of the corpus view.

* Outputs

- *=sql_hygiene=.* One finding per defect, under four rules.
  - =unterminated_block_comment=: a block comment is still open at the end
    of the file. Block comments nest, as in PostgreSQL; =--= comments,
    dollar-quoted bodies and both quote styles hide the markers. The finding
    is at the outermost comment still open.
  - =duplicate_index=: =create [unique] index if not exists= appears more
    than once with the same name, table and columns, as the model reads
    them. The finding is at the first.
  - =comment_splits_literals=: a comment stands between two string literals,
    which PostgreSQL joins only across whitespace; dollar-quoted bodies are
    scanned too. The finding is at the comment.
  - =not_re_runnable=: in the top-level code tokens, =create table=,
    =sequence=, =extension=, =schema= or =materialized view= without =if
    not exists=; =create trigger=, =rule=, =view=, =function= or
    =procedure= without =or replace=; =create index= without =if not
    exists=; =create policy= with no =drop policy if exists= of the same
    name and table in the file; and =create type= or =domain= with no
    =drop ... if exists= of the same name.
  A message holds no count: the script's depth of an open comment and the
  number of times an index is created are left out. The script's regular
  expressions reported =create  table  if not exists= with two spaces
  before =if= and =create index if  not exists=, and counted an index in
  a comment toward a duplicate; the tokens do not.

- *=populate_refs=.* =populate-refs=
  (=projects/ores.codegen/scripts/check_populate_references.py=). A scan
  of every =.sql= under =projects/ores.sql=: a create script's fact is
  its functions with their guards and inserts, a populate script's its
  =*_fn= calls with literal arguments, and every file's its includes.
  Rule =unresolved_reference=: a populate call passes literal names to a
  function whose body raises =not found= on a lookup, and no populate call
  to a function that inserts that row passes the same names, or only
  calls that psql runs after it do, in the order =ops::walk_includes=
  gives; the script never checked the order its fix text names. A call in
  a file no entry point reaches is not checked for order. Rule
  =unbalanced_parentheses=: a definition or call the check reads does not
  close, where the script stops with a traceback; the codec reports it and
  goes on. Rule =unread_function=: a function a lookup involves is not
  named =*_fn=, so the facts hold none of its calls. The script built a
  regular expression of the names the create scripts define to find the
  calls; every one is named =*_fn=, so the facts need no create script.
- *=sql_reachability=.* =sql-reachability= (=check_sql_reachability.py=).
  A scan whose fact is a file's includes. Rule =unreachable_file=: a file
  under =create=, =populate= or =drop= that =ops::walk_includes= does not
  reach. Rule =missing_include=: an include or entry point names no file.
  The script's regular expression also followed an =\i= in a block
  comment or a literal.
- *=rls_widenings=.* =rls-widenings=
  (=check_rls_system_tenant_widenings.py=). A scan with no reduce. Rule
  =system_tenant_widening=: a =create policy= under =create= compares the
  current tenant with the system tenant. The script's table of excused
  policies is replaced by inline exceptions on their =create policy=
  lines. The script's regular expression skipped a policy on a quoted
  table name and read one in a block comment.
- *=rls_coverage=.* The row-level security half of =er-diagram=
  (=plantuml_er_parse_sql.py --strict=, =validate_rls_policies=). A scan
  of every =*_create.sql=. Rule =missing_rls= (RLS_001): a table the
  create scripts define has a =tenant_id= column and no script under
  =create= enables row-level security on it. Rule
  =missing_party_isolation= (RLS_002): it also has =party_id= and no
  restrictive policy on it names =party_id=. The script's ignore file
  (=projects/ores.sql/utility/validation_ignore.txt=, option
  =ignore_file=) is read as the script reads it: a line names a code and
  a table pattern, matched as =fnmatch= matches them. A finding is on the
  line that creates the table, in the script that defines it last, in
  pathlib's order. RLS_003, the reachability of each
  =*_rls_policies_create.sql= from =rls/rls_create.sql=, is not ported.
  The script reads columns line by line and drops a line with a comment
  after its comma; the model does not, so on ORE Studio at =545cafca45=
  the codec reports one table the script does not: =ores_mq_queues_tbl=,
  whose =tenant_id= and =party_id= carry such comments, under RLS_002.
- *=handler_permissions=.* =handler-permissions=
  (=check_handler_permissions.py=). A scan of the seeds script and the
  handlers. Rule =unseeded_permission=: a handler of a component of the
  =components= option checks a code the =seeds= script does not seed. A
  seed is a string literal of the script's code, in a dollar body too,
  that has the shape of a code; the script also took one in a comment.
- *=curve_parameter_paths=.* =curve-parameter-paths=
  (=projects/ores.sql/utility/check_curve_parameter_paths.py=). Rule
  =undeclared_path=: a quoted =/CurveConfiguration/= path of the artefact
  that the ORE curve schema does not declare and no exemption explains.
  Rule =stale_exemption=: an exemption no path needs. The exemptions file
  stays, because a rule is a pattern over paths, not a line.

- *ER model.* =ops::er_model_of= reads the create scripts, in the order
  given, as =projects/ores.codegen/src/plantuml_er_parse_sql.py= does: the
  =create table if not exists= statements by regular expression, their
  columns line by line with the script's type shortening, the primary key,
  the description in the =-- ===== = block or the =/** */= comment above the
  table, the unique indexes, and the foreign keys a script states (a
  =soft FK= comment, =references= on a column, a =foreign key= constraint),
  each kept only when one table of that script owns the column. It returns
  the model as the diagram draws it: the packages in the order of their
  component, the data quality tables split into four groups by the shape of
  their names, each table's classification, key columns and other columns
  with the temporal ones last, and the relationships from parent to child
  with the script's labels. The script's tables, its component prefixes,
  the columns it takes as keys by name and the styles, are parameters
  (=ops::er_conventions=), because the caller reads them from the script's
  source. The parser's convention warnings are not ported. It keeps its
  regular expressions rather than the shared model, because the diagram
  it feeds is committed and must stay byte for byte what the script
  draws, quirks included: it drops a column whose line has a comment
  after its comma. On ORE Studio's 1,470 create scripts it takes about
  90 ms.
