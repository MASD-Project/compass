This page is the component overview for =compass.platform=, a simple component
in the foundation layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.platform= is the single home for operating-system code in compass-ng.
Other components call it instead of including raw OS headers. Each facility
is one seam with a POSIX and a Windows implementation, chosen by the
preprocessor inside the seam's source file, so no other component tests for
the system. It holds five facets. =filesystem= has =mapped_file=: a
read-only, memory-mapped view of a whole file. The pipeline reads org
documents, C++ and SQL through it, so loading a file costs one =mmap= and no
copy. On Windows the bytes are read into memory instead, because Windows
refuses to delete a file while a view of it is mapped, and the store deletes
packs other processes are reading. =file_status= gives the status of a
regular file in the fields git's index keeps, reads a whole file with the
status of what it read, and gives the time as the file system stamps a file.
=new_file= creates a file that must not exist and writes it, readable by
its owner alone when asked, as a file of secrets must be from the moment it
exists, and
=file_lock= is an exclusive lock on a file that the system releases when its
holder dies; the store's packs are written and repacked through them.
=process= has =run_program=,
which runs a program in a given directory, optionally with a file as standard
input, and returns its exit code and standard output; git and the formatters
run through it. It also has =executable_path=, the running binary's own path
with symbolic links resolved; =compass --version= reads the build manifest
beside it, so it finds the manifest even when it runs through a link, and
=find_program=, which finds a program on PATH as a shell does.
=environment= gives the process ID, sets environment variables for the
process and the programs it runs, and finds the home directory as git does.
=liveness= tells whether a process is running, which =compass.testing= asks
of the process that left a temporary directory behind.
=random= has =fill_secure_random=, bytes from the system's
cryptographically secure generator (=getentropy= on POSIX,
=BCryptGenRandom= on Windows), and =secure_random_string=, characters
drawn uniformly from an alphabet with it, by rejection; =compass env
generate= makes its secrets with it.
=standard_streams= makes the standard streams carry bytes unchanged, which
on Windows stops LF being written as CRLF. =compiler= holds
=COMPASS_ALWAYS_INLINE=, the inlining request MSVC has no spelling for.
=text= holds what the ports of ORE Studio's Python gates
share: =regex=, regular expressions with Python's =re= syntax and Unicode
classes over UTF-8 bytes, through PCRE2 with JIT; =decoding=, how
=read_text()= turns bytes into text (strict, ignoring or replacing invalid
UTF-8, and universal newlines); and =xml=, an XML document read into the
element tree Python's =xml.etree.ElementTree= builds. It supports POSIX
systems and Windows.

* Inputs

- A filesystem path to a regular file.

* Outputs

- =mapped_file=: a move-only owner of the mapping. =bytes()= returns a
  =std::span<const std::byte>= and =text()= returns a =std::string_view= over
  the same bytes. =size()= and =empty()= report the length.
- An empty file yields an empty view and no mapping.
- A failed =open=, =fstat= or =mmap=, or a path that is not a regular file,
  throws =std::system_error= with the errno code and the path in the message.

- =executable_path=: the absolute path =/proc/self/exe= links to, or on
  Windows the module file name, or an empty path when it cannot be read.
- =regular_file_status=: size, modification and change times, device,
  inode, user and group of a regular file, without following a symbolic
  link; nothing for anything else. On Windows the change time is the
  creation time and the identities are zero, as git for Windows records
  them.

- =regex=: =search=, =match=, =fullmatch=, =find_all= and =substitute=,
  with byte offsets and named groups. A subject may hold invalid UTF-8,
  which matches nothing. A pattern that does not compile throws
  =std::invalid_argument=. Matching allocates nothing: each thread keeps its
  match data and a JIT stack that grows to 64 MiB.
- =xml_document=: =parse= gives the root element, or nothing where
  =ET.fromstring= raises. Each element holds its tag, attributes in order,
  text, tail and children, as ElementTree's TreeBuilder fills them; =find=,
  =find_all=, =find_text= and =iter= follow =find=, =findall= with a path
  of tag names, =findtext= and =iter=. A path is split at each '/', so a
  namespaced tag, whose URI holds slashes, cannot be a step of one; =iter=
  takes a whole tag, and a caller matches a namespaced child by its tag.

* Dependencies

- The C++23 standard library, and POSIX (=open=, =fstat=, =mmap=,
  =flock=, =posix_spawnp=, =kill=) or the Win32 API (=CreateFileW=,
  =LockFileEx=, =CreateProcessW=, =OpenProcess=, =BCryptGenRandom=).
- PCRE2 (8-bit, with JIT), for =text::regex=.
- expat, for =text::xml_document=. ElementTree runs on expat, so the text
  of CDATA, references and line ends is what the ported scripts read; a
  DOM library such as pugixml keeps CDATA as separate nodes.
- Catch2, for the tests only.
