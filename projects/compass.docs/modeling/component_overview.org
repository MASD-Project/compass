This page is the component overview for =compass.docs=, a simple component
in the domain layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.docs= runs the ORE Studio gates that read its org documents and the
plain files of the repository, and no model and no source language. Each
gate was a script that walked the tree and read every page again; here a
gate that judges one page at a time is a document codec, so an edit re-runs
it for that page alone, and a gate that relates pages is a scan of
documents: each page's map reads its parsed tables into a small fact, and
the reduce relates the facts, so an edit maps one page and the reduce runs
only when that page's fact changed.

The ports follow their scripts rule for rule, but they read the page as org
parses it, from its =compass.org= tables, where a script re-lexed the text
with regular expressions: headings, keywords, property drawers, links and
comments are those org-element finds. A script's regex was the one that
went wrong on an indented or upper-case block, a link that wraps a line, an
=:ID:= or a link inside a block, or a heading after an unclosed block, and
those verdicts change; on ORE Studio the findings are the same. This holds
for =lint=, =heading_numbers=, =component_docs= and =org_links=. The
generators still read the text of the pages they rewrite, which they must
reproduce byte for byte, and so do =prototypes= and =rule_identifiers=,
which read three to ten pages each.

One scan, =lint=, holds the id-link graph of the org pages: per page its
=:ID:= properties, its type, title and filetags, its id links with the
level-1 section each sits in, and its generated-region markers
(=ops::fact_of=, =ops::page_of=). Its reduce resolves the links, checks the
service architecture patterns and their uses, and checks that every page a
structure note orders links the note back, where =pattern-uses= and
=link_structure_notes.py= were two more passes over every page.

A gate or rule that another check covers, or that guards work that is
finished, is not ported:

- =skill-recipes= (=link_skill_recipes.py=). It applied a reviewed table of
  skill-to-recipe links once; the links are in the skill pages now, and
  =lint/dangling_link= reports one that no longer resolves. A link someone
  removes is a change reviewed in the skill page's diff.
- The page half of =skill-levels= (=apply_skill_levels.py --check=). It
  compared each skill page's =#+level:= with a copy of the script's table
  compiled into compass, two sources of one fact. A level change is
  reviewed in the skill page's diff. A skill the table lacks, or an entry
  with no skill, still stops =skill_levels=, whose refusal names each.
- The =react_tree= and =no_discovery= rules of =prototypes=. They guarded
  the move of the prototypes out of the React tree, finished on
  2026-10-06. =no_discovery= looked for the string
  =ores-deploy-prototypes= anywhere in the site build, so the function's
  own definition passed it with the call removed.

* Inputs

- The documents of the corpus, every one whether it has a type or not:
  their paths, sources and =compass.org= tables.
- The files of the checkout, through =types::corpus_view=, for the gates
  that read the tree's listing or a file that is not a document.

* Outputs

- *=org_links=.* ORE Studio's =org-links= gate
  (=projects/ores.lisp/src/ores-check-org-links.el=). A document codec over
  every page outside a =.packages=, =vcpkg=, =build= or =tmp= directory or
  =.claude/worktrees=. Rule =colon_link=: a bracket link whose raw target
  begins with a colon, which no link type does; it is what a verbatim span
  closed early leaves behind, as in =[[:space:]]=. The script parses only
  pages that hold =[[:=; here every page's parse is in the corpus already.
- *=heading_numbers=.* =heading-numbers=
  (=build/scripts/check_heading_numbers.py=). A document codec over every
  page under =doc/= or =projects/= outside =build=, =external=, =venv=,
  =node_modules=, =.git= and =.cache= directories, read from its headings
  table. Rule =numbered_heading=: a heading whose title, after its TODO
  keyword and priority, starts with a number such as =2.1.= or =3)=. A
  heading is one where org parses one: a heading line ends the block it
  stands in, which is why org-src escapes one with a comma, and an
  unclosed block hides nothing; the script's count of open blocks hid
  both, and missed =* TODO 1. Foo=. Rule
  =unreadable_document=: a page that is not UTF-8, which the script fails
  on.
- *=component_docs=.* =component-docs=
  (=projects/ores.codegen/validate_docs.py=). Every component
  =projects/ores.*= and every part with =include/= and =src/= has a
  =modeling/component_overview.org= with an =:ID:=, =#+type: component=, a
  =#+description:= and the six sections, and a =.puml= beside it; no
  top-level name extends another's; no page under =doc/= holds a bare
  bracket link inside one backtick span. It is a scan of the documents
  under =doc/=: a page's fact is each backtick span on a line that holds a
  bare bracket link org parses whose target has no colon, dot or leading
  star, so a link in a block or a verbatim span is not one; the reduce
  step checks the components and applies the exceptions, so an edit to a
  page maps that page. The overview's =:ID:= property, its first
  =#+type:= and =#+description:= keywords and its level-1 headings come
  from its tables. The directories come from the
  listing of the checkout, so a directory that holds no tracked file is not
  one. The =exceptions= option names the script's own file of =CODE
  component= lines, which stays as data: it excuses a rule for a
  component, and a component that lacks an overview has no file for an
  inline exception to sit in.
- *=shell_recipe_provenance=.* The CI gate =shell-recipe-provenance=
  (=projects/ores.codegen/scripts/check_shell_recipe_sources.py=). Rule
  =orphan_recipe=: a recipe one directory under
  =projects/ores.shell/scripts/library/= whose =# GENERATED from ...= line
  is missing or names no file, =..= going up only from a directory that
  exists, as the operating system resolves it.
- *=skill_namespace=.* =skill-namespace=
  (=rename_skills_to_compass_namespace.py --check=). Rule
  =outside_namespace=: a skill directory under =doc/llm/skills= not named
  =compass-...=.
- *=no_pr_triggers=.* =no-pr-triggers= (=check_no_pr_triggers.py=). Rule
  =pull_request_trigger=: a workflow directly under =.github/workflows=
  whose top-level =on= names =pull_request= or =pull_request_target=, as a
  scalar (=on: pull_request=), a flow sequence or mapping (=on: [push,
  pull_request]=) or a key or item of its block at any indentation;
  =pull_request_review= and a deeper key are other things. Rule
  =no_workflows=: there is no workflow file.
- *=prototypes=.* =prototypes= (=check_prototype_inventory.py=). The
  prototypes under =doc/prototypes/<group>/<name>/=, the group pages and
  the top page agree; each review directory has its index and each row its
  review cell; the files the =trades= and =conventions= groups share by
  copy, which the script lists in code, are identical.
- *=rule_identifiers=.* =rule-identifiers= (=check_rule_identifiers.py=).
  The two UX pages key the bullets of the level-two sections the script
  lists in code, each with one identifier of the page's code; the screen
  review checklist cites only identifiers a page carries, with two digits,
  or a page that has none yet. The pages and their section codes are the
  script's own table, kept in the codec.
- *=lint=.* =lint= (=./compass.sh lint=, =cmd_lint= of
  =projects/ores.compass/src/compass.py=), with =pattern-uses=
  (=build/scripts/check_pattern_uses.py=) and the check half of
  =structure-notes= (=link_structure_notes.py=). A scan of documents over
  every =.org= page under =doc/= or =projects/= and every other =.org= file
  the gate lints: all of the checkout but those under =build=, =venv=,
  =.packages=, =vcpkg= or =external= at the root, under a =.git=,
  =.claude=, =node_modules= or =__pycache__= directory, or whose name
  starts with a dot. A linted page's map reports its own defects from its
  tables: =bad_filetag=, a tag of its first =#+filetags:= keyword that is
  not lowercase; =unclosed_marker=, a =# BEGIN generated X= comment with no
  =# END generated X= comment after it; =malformed_link=, a bracket id link
  whose target has a hyphen and is not a UUID. A marker, a keyword or a
  link inside a block is text, as it is to org. The map's fact is the page
  in the id-link graph (=ops::fact_of=): whether it is UTF-8, the first
  word of its =#+type:=, its =#+title:=, whether its first =#+filetags:=
  holds the tag =structure_note=, its level-1 headings and its =See also=
  heading, every =:ID:= property of its drawers, the scripts its markers
  name, and each bracket id link whose target is shaped like an ID, with
  its line, its label, the level-1 section it sits in, whether it comes
  before the page's =What this cluster does not cover= or =See also=
  section, and whether its own section holds an =# aside= comment. The
  reduce step reads the facts and reports:
  - =marker_without_writer=: the script a marker names does not exist, or
    its source does not mention the page's file name, or a =SKILL.org='s
    directory; or a marker naming =compass generate: <codec>= names a
    codec this component does not ship. Such a marker needs no script:
    the codec's drift check holds the region.
  - =dangling_link=: no linted page holds the ID, a later page's ID
    winning in pathlib's order.
  - =durable_link=, a page under =doc/llm=, =doc/meta=, =doc/knowledge= or
    =doc/recipes= that links an agile page, advisory in the gate and
    reported only with the option =strict_links=true=; with it, the 549
    links over 215 files the gate lists with =--strict-links= at
    545cafca45.
  - =pattern_unknown_use=, =pattern_one_way=, =pattern_not_a_pattern=
    and =pattern_shared_id=, over the UTF-8 pages under =doc/= or
    =projects/=, outside =build= and =vcpkg=, keyed by their first =:ID:=:
    a service architecture pattern lists its uses in its =In ORE Studio=
    section and a use lists its patterns under =Patterns used=, a link
    with or without a label; a use under =doc/plans/=,
    =doc/knowledge/external/= or =doc/agile/= need not link back.
  - =missing_backlink=, over the UTF-8 pages under =doc/= or
    =projects/modeling/=: a page tagged =structure_note= is a note, and
    each page it links before those sections, that is not a note itself,
    links it back; the finding sits on the page's =See also= heading, and
    its fix is the line =link_structure_notes.py= wrote, which differs for
    a page in a section marked =# aside=.
  An edit to one page maps that page; the reduce runs again only when the
  page's fact changed, which an edit that moves a link does.

Generators. Each of these writes the artefact an ORE Studio generator
writes, so =compass generate= replaces the script and =compass check='s
drift findings replace the gate that regenerated it and ran =git diff=.
They are off by default.

- *=shell_recipe_library=.* =tangle-shell=
  (=projects/ores.lisp/src/ores-build-recipe-scripts.el=). A document
  codec over the recipes under =doc/recipes/shell=. Through
  =ops::tangle= with the language =ores-shell=: a recipe whose blocks name
  targets gives one script per target, named by its file name; any other
  recipe with an =ores-shell= block tangles to =<recipe>.ores=, as
  =TARGET-FILE=. A script lands in
  =projects/ores.shell/scripts/library/<category>/=, the category from the
  =:recipe:shell:<category>:= filetag or =general=, loses a trailing =exit=
  line and gains the banner: the section heading, or the title and a
  description that differs from it, then the =GENERATED from= and
  =Regenerate with= lines. It writes all 5,015 scripts byte for byte as
  Emacs 30.2 does.
- *=http_recipe_library=.* =tangle-http=
  (=projects/ores.lisp/src/ores-build-http-recipes.el=). The same for the
  =hurl= blocks under =doc/recipes/http=, into
  =projects/ores.http/scripts/library=; a recipe that names no target gives
  nothing, nothing is stripped and the banner carries no description. It
  writes all 414 files as Emacs does.
- *=skill_catalogue=.* =skill-catalogue= (=generate_skills_catalogue.py=).
  A corpus codec that rewrites the first region between its markers in
  =doc/llm/skills/claude_code_skills.org=: per domain of the
  script's table, the skills named =compass-<domain>-...= in name order,
  each with its =:ID:=, title and description, the description cut to 110
  characters.
- *=skill_type_tables=.* =skill-type-tables=
  (=generate_skill_type_tables.py=). Rewrites every region between its
  markers in =compass-doc-add= and =compass-doc-show=: the document types
  read from the =doc_*.org.mustache= templates and from
  =_STATIC_PARENT= and =_DEFAULTABLE_PARENT= in =compass.py=, and the
  read-only commands with the help =compass.py= gives each.
- *=skill_levels=.* The inventory half of =skill-levels=
  (=apply_skill_levels.py=): the region between its markers in
  =doc/llm/skills/skill_systems_levels.org=, the count of skills each
  System sees by the script's =LEVELS= table, copied into the codec. A
  skill the table lacks, or an entry with no skill, writes nothing and is
  refused, the refusal naming each.
- *=recipe_inventories=.* =recipe-inventories=
  (=regenerate_shell_recipe_inventory.py= and
  =regenerate_http_recipe_inventory.py=): =doc/recipes/shell/shell.org=,
  its head and prose kept and each link list rebuilt from the recipes
  under it, and =doc/recipes/http/generated_recipes.org=, rewritten whole
  from the recipes one directory under it. Recipes are walked in pathlib's
  order, by component, and titles compared as =str.lower()= compares
  ASCII.
- *=backlog_indexes=.* =backlog-indexes= (=regenerate_backlog_indexes.py=):
  the index page of each of the four backlog buckets, its table padded in
  characters, not bytes. The committed =inbox.org= of ORE Studio
  =545cafca45= is stale: it lacks a capture filed on 2026-11-16, which the
  script and the codec both add.
- *=physical_inventory=.* =physical-inventory=
  (=regenerate_physical_space_inventories.py=): the child tables of the
  physical-space pages in the template library.
- *=trade_type_coverage=.* =trade-type-coverage=
  (=generate_trade_type_coverage.py --write=): the generated block of
  =doc/knowledge/domain/ore_trade_type_coverage.org= from ORE's mined
  trade types, the catalogue, the recorded trades and the coverage
  story's tasks; where the script refuses, nothing is written and the
  codec refuses with the script's reason.

A generator that edits pages emits every page it may edit, edited or not:
the sink removes a file a complete codec wrote before and no longer emits,
so a page emitted only while it needed an edit would be deleted once it
had it. The back-links of the structure notes are not generated: a page
that lacks one is a =lint/missing_backlink= finding, so no generator
shares the skill pages with another. Where a script would stop, =skill_catalogue=, =skill_type_tables=,
=skill_levels=, =recipe_inventories= and =trade_type_coverage= refuse
instead: a =refused= finding on the page, with the reason (a page or
region that is missing, a skill without its =:ID:=, title or description,
a merge conflict in a recipe index, a coverage source the script
rejects), and the page a good run wrote is kept.

=ops::replace_region= replaces the first region between two markers, or
every one, as the scripts do with =re.search= or =re.sub=. A
=generated_region= names its kind and its codec: its BEGIN marker is
=# BEGIN generated <kind> (compass generate: <codec>)=, and the region is
also found under the BEGIN markers that named the scripts the codec
replaced, so one =compass generate= moves a page onto the marker naming
compass. The regions of =skill_catalogue=, =skill_type_tables= and
=skill_levels= are written so, and the head of the HTTP recipe inventory
names =compass generate=, not a script. The generators that keep hand-written text around a generated region emit the whole file,
reading the file they write.

* Dependencies

- =compass.codec= for the descriptor, the corpus view the codecs read
  through and the diagnostic table they fill.
- =compass.org= for the tables of a parsed page.
- =compass.cpp= for its text helpers: Python's lines, spaces and pathlib
  order, and the finding on a byte of a file.
- =compass.platform= for regular expressions and Python's decoding.
- The C++23 standard library.
- =compass.ingest=, =compass.store= and Catch2, for the tests only.
