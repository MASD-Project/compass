#+title: compass.serve.document_queries
#+description: Codegen operation model for the document service's reads of the corpus: search, facets, the document list, one document, its backlinks, the environments and the version, and the sync tool.
#+type: masd.codegen.operation
#+component: serve
#+namespace: compass::db::types
#+entity_singular: document_queries
#+brief: The document service's reads of the corpus.
#+filetags: :model:operation:serve:
#+created: 2026-11-23
#+updated: 2026-11-23

The questions an agent, a page or a gateway asks of an environment's
documents, over HTTP and MCP. Each request message states its route, its
place in the catalogue (tool, area, entity and whether it writes) and where
each of its fields comes from. Every read is
answered inside the caller's view, which the gateway names in a header and
which is not a field of any message.

* Notes

- The messages that have a hand-written C++ struct today match it in name,
  member names, types, optionality and default: =metadata_match=,
  =document_filter=, =search_request=, =search_hit=, =search_response=,
  =facets_request=, =facet_count=, =named_facet= and =facets_response= of
  =compass.db/types/search.hpp=, and =environment_summary= of
  =compass.db/types/environment.hpp=. =#+namespace:= names where they live.
  The others are new: =document_summary=, =list_documents_*=,
  =get_document_*=, =backlink=, =backlinks_*=, =list_environments_*=,
  =version_*= and =sync_*=. No query function answers them yet.
- =view_filter= and =ranking= of =types/search.hpp= are not messages: the
  view comes from the gateway's =Compass-View= header, and the ranking is
  the server's configuration.
- =sync_request= is not =compass::cli::app::sync_request=, which carries a
  checkout path, a commit and a thread count and never crosses the wire. The
  tool takes an environment; the service finds its checkout. The design
  makes sync an MCP tool only; it has a route, =POST /v1/{environment}/sync=,
  because in ORE Studio a tool is a route's catalogue name.
- =facets_request.q= is a plain =std::string= with no default, so the struct
  stays as it is, and =:required: false= lets a call leave it out.
- =document_filter= binds from the query string by the overview's rules: one
  parameter per member, a vector as a repeated parameter, and =keyword= and
  =property= split at the first colon.
- =GET /v1/catalogue= (=get_catalogue=) is not modelled here. Its answer is
  the copied =route_catalogue= of every route, which the copied route family
  writes with its own codec.
