#+title: compass.serve.campaign_writes
#+description: Codegen operation model for the document service's test campaign writes: start a run, record a step, finish the run, attach a screenshot, add a note and address it.
#+type: masd.codegen.operation
#+component: serve
#+namespace: compass::serve::messages
#+entity_singular: campaign_writes
#+brief: The document service's test campaign writes.
#+filetags: :model:operation:serve:
#+created: 2026-11-23
#+updated: 2026-11-23

How a tester records a test campaign over HTTP and MCP. Every write is made
by the caller the gateway names in its =Compass-View=, =Compass-Subject= and
=Compass-Actor= headers, and a write without a subject is refused. No request
names who writes: the query function takes the caller beside the request and
records its subject and actor in =activity.action=. Each write runs in one
transaction and is refused, with nothing written, when it is invalid, names a
row that is not in its environment or conflicts with the row's state.

* Notes

- Every message but =add_note_response= matches its struct in
  =compass.db/types/campaign.hpp= in name, member names, types, optionality
  and default, except the two changes the alignment design makes to the six
  requests. Each request loses =tester=, because the caller is never a body
  field; and the five that name a row gain =environment= as their first
  member, because every route starts at =/v1/{environment}=. The structs
  follow in [[id:186C4AF8-CAB4-4754-B8AC-76D571B1B3E9][Serve the documents over HTTP]],
  where the caller first exists; until then the struct check pins both
  changes, and fails when either stops holding.
- =step_outcome= and =run_outcome= are the enumerations =:values:= names.
  =query::add_note= answers a bare =std::int64_t=; =add_note_response= wraps
  it so the answer is a JSON object.
- =step_result_request= and =address_note_request= answer nothing: 204 over
  HTTP.
- A request that names a run, a campaign or a note in another environment is
  refused as =not_found=, as one naming no row is.
- =note_kinds= of =types/campaign.hpp= is not a message: it is the project's
  configuration, which =query::add_note= takes beside the request.
- =bytes= is base64 in JSON, so one route is one tool with one schema.
  =:max_body_size:= raises the route's limit to 16 MiB, about 12 MiB of
  image; every other route keeps the server's default.
