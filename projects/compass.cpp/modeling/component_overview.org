This page is the component overview for =compass.cpp=, a simple component in
the domain layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.cpp= runs ORE Studio's C++ gates as codecs. Each gate was a Python
script that read the whole tree on every run; here each is a corpus codec
that reads the files of the checkout through its view, so the runtime
records every file it read and a run in which none of them changed reuses
the findings without reading anything. The gates that read every C++ file
(=unique_type_names=, =unity_collisions=, =exported_types=,
=forward_declarable_includes=, =stream_coverage= and =handler_registrars=) are scans: each file is mapped to a fact once per
content ID and a run after an edit maps only the edited file, then reduces
the stored facts with it. A fact holds what the gate decides from, not the
file, so an edit that changes none of it leaves the fact as it was and the
reduce is not called. =stream_coverage= keeps, of a file that names a
stream call, a subject or a string constant, its constants, subject
members, arrays and stream calls with their arguments, and of every file
the names it calls; it reads a file only as a caller of a function whose
parameter names a service. =forward_declarable_includes= decides each
header in its map, from the types of its option, and its reduce compares
that option with the tree's own list file and defining headers.

The C++ gates read code through one lexer, =ops::lex=: the source, byte
for byte, with its comments and literals blanked. It knows raw strings
with delimiters and encoding prefixes, a quote inside a number as a digit
separator, line splices, and the lines an =#if 0=, or an =#elif= or
=#else= after a taken =#if 1=, excludes. =ops::model_of= reads the live
code of one file into its model: the include directives, the macro
definitions, the declarations at namespace scope (scope, name, kind,
linkage specifiers, the macro between a class key and its name, and a
function's parameters), the class and enum heads at any scope, and the
names the code writes, joined by =::=. A gate asks for the parts it reads;
the includes and macros come from the directives alone, and the rest walk
the tokens. =ops::without_comments= gives the code with its literals put
back, for the shell gates, which match what a literal holds.

The model is not a parser: it reads declarations at namespace scope and
skips every body, which is what the gates need. The other scanners are
ports. Each reproduces the rules of one script, because the acceptance of
the port is the same verdict on the same commit. =stream_coverage=,
=route_auth=, =bff_list_requests=, the registrar gates and
=xml_family_census= take the scripts' regular expressions verbatim through
=compass.platform='s =text::regex=, which has Python's syntax and Unicode
classes, and read a file as Python's =read_text()= does, with its decoding
errors and line ends (=text::decoding=). tree-sitter is not used: it was
measured too slow for the always-on path (see
[[id:E2DCD7CE-4CFC-47D8-A65D-E05A4CA48EB6][Measure tree-sitter parsing]]).

A script that kept a baseline of excused findings is ported without it
where the baseline is line- or file-shaped: each entry becomes an inline
exception on the line it excused (=forward_declarable_includes=,
=core_link_edges=). A table that is the gate's configuration rather than a
list of excuses becomes an option with ORE Studio's values as its default
(=translation_unit_budget=, =xml_family_census=).

Every codec is off by default; a repository enables the ones whose rules it
keeps in its =.compass.org=.

* Inputs

- The files of the checkout, through =types::corpus_view=: =list_files=
  for the paths each gate walks and =read_file= for the bytes. No codec
  reads a document.

* Outputs

- *=exported_types=.* ORE Studio's =exported-types= gate
  (=build/scripts/check_exported_types_are_compiled.py=). A library is the
  directory two levels above a
  =projects/<component>/<part>/include/<name>/export.hpp= that defines an
  =ORES_..._EXPORT= macro as =BOOST_SYMBOL...= at the start of a line and has
  an =#ifdef ORES_..._LIBRARY= guard, and that has a =src/= directory. Its
  translation units are the =.cpp= files under =src/=. A file reaches every
  file its =#include "..."= directives name (=ops::quoted_includes=), not
  one in a comment, a literal or a branch an =#if 0= or an earlier =#if 1=
  excludes; a condition it cannot decide counts both ways. Each is resolved first
  against the file's own directory and then against every
  =projects/<component>/<part>/include= in pathlib order; =..= goes up only
  from a directory that exists, as the operating system resolves it. Rule
  =uncompiled_exported_type=: a header under the library's =include/=, not
  marked =AUTO-GENERATED FILE=, has a class or struct head =class MACRO
  name= or =struct MACRO name=, attributes allowed before the macro, and no
  translation unit reaches it. One finding per header, at the line of its
  first such head. Includes resolve among the C++ files the codec scans, so
  the codec depends on their listings, not on every path of the checkout.
  The same pass is ORE Studio's =enum-attributes= gate
  (=build/scripts/check_enum_export_attributes.py=), so that the export
  macros are read once. A visibility macro is =BOOST_SYMBOL_EXPORT=,
  =BOOST_SYMBOL_IMPORT=, or an object-like macro a scanned file
  =#define=s with a body holding one of them, =__declspec(dllimport)=,
  =__declspec(dllexport)= or =__attribute__((visibility=. Rule
  =visibility_macro_on_enum=: an enum head, =enum=, an optional =class= or
  =struct=, a visibility macro, a name and =:=, ={= or =;=, not after
  =using=. One finding per head, at its keyword. Before this pass it was
  the =enum_attributes= codec, and the rule was
  =enum_attributes/visibility_macro_on_enum=.
- *=test_case_reachability=.* ORE Studio's =reachability= gate
  (=projects/ores.codegen/scripts/check_test_case_reachability.py=). It
  is a scan whose fact is the number of cases a test source declares. It
  reads every test source under =projects/=: a file with a C++ source or
  fragment suffix (=.cpp=, =.cc=, =.cxx=, =.c++=, =.hpp=, =.h=, =.hxx=,
  =.ipp=, =.inc=, in any case) under a =tests= directory or whose stem ends
  in =_tests=, outside any =node_modules=, =venv=, =.venv=, =build= or
  =external= directory (=ops::is_test_source=). =ops::scan_source= reads
  the code =ops::lex= gives, with the backslash-newline splices joined, and
  the
  logical lines: =#if=, =#ifdef= and =#ifndef= open a block, =#endif= closes
  one, and a Catch2 test macro, or a name the file's own =#define= binds to
  one, followed by =(= declares a case. Rule =case_in_conditional=: a case
  declared inside a block, once per line and block, naming the directive
  that opened the innermost block. Rule =unbalanced_conditional=: an
  =#endif= that closes nothing, or a block still open at the end of the
  file. Rule =raw_string_moves=: a raw string begins or ends elsewhere once
  the splices are removed; the file's cases are left out. Rule
  =no_test_case=: no test source, or no case in any readable one, reported
  on =projects=.

- *=unity_collisions=.* ORE Studio's =unity-collisions= gate
  (=build/scripts/check_unity_collisions.py=). Rule =unrecorded_collision=:
  two =.cpp= files under =projects/ores.*= with the same nearest
  =CMakeLists.txt= define the same name with internal linkage in the same
  named namespace, and =cmake/unity_exclusions.cmake=, a build input that
  stays, keeps at most one of them out of the unity build. Rule
  =missing_recorded_file=: the exclusions name a file that does not exist.
  The names are the model's declarations at namespace scope
  (=ops::internal_names=): a function or variable in an anonymous
  namespace, =static=, or =const= or =constexpr= and not =inline=, however
  many lines it spans. A function's name carries its parameter types, so
  overloads a unity build compiles do not collide.
- *=unique_type_names=.* =unique-type-names=
  (=build/scripts/check_unique_type_names.py=). Rule =type_defined_twice=:
  two headers that can meet in one binary define the same qualified class,
  struct, union or scoped enum, as the model's namespace-scope declarations
  give them (=ops::defined_types=).
- *=forward_declarable_includes=.* =forward-declarable-includes=
  (=build/scripts/check_forward_declarable_includes.py=). Rule
  =includes_definition_it_only_names=: a header includes the defining
  header of a type of the =types= option only to name it, decided in the
  map step from the header's lexed code, literals and include lines
  blanked. The option holds the types of
  =build/scripts/forward_declarable_types.list= at =f8b71f178a= as its
  default, each =name;key;defining header;forwarding header or -=,
  comma-separated; the map reads only its own header, so a tree whose
  list differs sets the option. A header that names no
  defining header is not lexed. Rule =bad_type_list=: the option is
  malformed or empty, reported on =.compass.org=. The reduce makes the
  copy's drift loud. Rule =stale_type_list=: the file the =list_file=
  option names (by default =build/scripts/forward_declarable_types.list=;
  empty turns the rule off) exists and lists other rows than the option,
  read as the script reads it; the finding is on the file, names each
  row that differs, and its fix gives the exact =types= value to set. A
  file that cannot be read or parsed is reported the same way. Rule
  =type_not_defined=: a header of the tree whose include path is a listed
  defining header does not define its type at namespace scope, as
  =ops::defined_types= reads it; a tree that lacks the header is not
  judged. The reduce reads the list file and those headers through the
  view, so they are inputs: an edit to either calls the reduce again,
  and an edit to any other header still costs one map. The script's
  baseline is replaced by inline exceptions.
- *=handler_registrars=, =event_registrars=, =history_registrars=.* The
  three registrar composition gates
  (=check_handler_registrar_composition.py=,
  =check_event_registrar_composition.py=,
  =check_history_registrar_composition.py=): every generated registrar of
  the named components is called from its composition file, or, for a
  handler registrar, its subjects are answered by hand. A call in a
  comment is not a call.
- *=shell_command_units=, =shell_menus=, =shell_command_composition=.* The
  shell gates (=check_shell_command_units.py=,
  =check_shell_menu_collisions.py=, =check_shell_command_composition.py=):
  a menu is built once, by one file, from its name alone; a unit is
  registered once; every generated command unit is registered. A root
  command is =root_menu.Insert("name"=, on one line or across several.
  They read =ops::without_comments=, so a call in a comment is not one.
- *=route_auth=.* =route-auth= (=check_route_auth_declarations.py=). Rule
  =route_without_auth=: an =add_route= of =ores.http= whose builder chain,
  followed through =auto= locals, states no authentication position. Rule
  =too_few_routes=: fewer than 20 routes found.
- *=bff_list_requests=.* =bff-list-requests=
  (=check_bff_list_requests.py=). A hand-written BFF list request states
  what the C++ protocol decodes (=missing_member=, =filter_mismatch=,
  =wrong_rows=).
- *=list_request_table=.* Writes the generated =list_requests.ts=, the
  table of the list requests the protocol headers declare, which
  =regenerate_list_request_descriptors.py= wrote until ORE Studio deleted
  it. Its drift rule replaces the =stale_table= rule =bff_list_requests=
  had while only the script could write the table: a generator codec
  that reported findings would refuse, and keep the table it wrote
  before. The script ran prettier; the codec lays out each array as
  prettier does at the width =.prettierrc.yaml= sets, which reproduces the
  committed table but for the two header lines that name the generator.
- *=translation_unit_budget=.* =translation-unit-budget=. Rule
  =over_budget=: a unit with an =#include= of
  =conventions_family_pack.hpp= names more convention families than one or
  its recorded ceiling, counted as the distinct =domain::family= names its
  model writes. Rule
  =below_ceiling=: a ceiling above what its unit names. The ceilings are an
  option, since each holds a number an exception cannot.
- *=xml_family_census=.* =xml-family-census=
  (=check_xml_family_coverage.py=). The =families= option is the census;
  the rules report a corpus root it does not classify, a family no document
  has, a state the generated tables contradict and a suite that names an
  unused family.
- *=stream_coverage=.* =stream-coverage=
  (=build/scripts/check_stream_coverage.py=). It reads the stream and
  durable consumer declarations of the tree (=ensure_stream=,
  =serve_step_commands=, =js_queue_subscribe=), resolving names through
  constants, =nats_subject= members, arrays and the arguments callers pass,
  and applies NATS's two rules: every durable subject has exactly one
  stream, and no two streams overlap. A declaration it cannot read is a
  finding, not a skip.
- *=core_link_edges=.* =core-link-edges= (=check_core_link_edges.py=). Rule
  =forbidden_edge=: a core's =target_link_libraries= names another
  component's core or service library. The JSON baseline is replaced by
  inline exceptions above the CMake lines.

* Dependencies

- =compass.codec= for the descriptor, the corpus view the codecs read
  through and the diagnostic table they fill.
- =compass.platform= for regular expressions and Python's decoding.
- The C++23 standard library.
- =compass.store= and Catch2, for the tests only.
