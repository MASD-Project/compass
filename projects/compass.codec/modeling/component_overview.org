This page is the component overview for =compass.codec=, a simple component in
the domain layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

Every output and every check of compass-ng is a /codec/: a function that reads
the corpus in memory and emits either files or diagnostics; a codec of files
also reports each output it refuses to produce. =compass.codec=
defines what a codec is and runs codecs. It does not load the corpus. A host
loads the documents, calls the runner and decides what happens to the result:
write it, diff it, cache it or report it. A codec never writes a file; when the
host chooses to write, the output sink puts the files under an output root and
touches only those whose content changed. The sink decides first and acts
second, so a host that only wants to see what would change prints the same
decision as a diff and writes nothing.

A codec is a =descriptor=, which is constant data, and one function. Nothing
in the runtime knows a codec by name. What a codec does differently from the
others is in its descriptor, so adding a codec adds a row to a list.

* Inputs

- A =types::corpus=: one row per document with its path, the git blob ID of
  its source, the source bytes, the =compass.org= tables of its parse and its
  registered type. The corpus owns nothing; the host keeps the sources and
  the objects mapped.
- Optionally, =types::checkout_files=: every file of the checkout, documents
  or not, in byte order of the paths, with a function that gives a file's
  content ID as the host resolves IDs and one that reads its bytes. The
  corpus points at it; with none, every file input is a miss. The host
  may back it with a checkout on disk or with a commit's trees and blobs:
  the runtime sees only paths, IDs and bytes, so a check of a past commit
  runs every codec unchanged, and a unit whose recorded inputs have the
  same IDs in the commit is reused without reading a blob.
- The type registry of =compass.org=, which the input types of a codec are
  resolved against.
- A span of descriptors. =codecs::catalogue()= lists the ones this component
  ships; a host appends those of other components.
- A =types::configuration=: rows of codec, key and value. The key =enabled=
  takes =true= or =false=. Any other key must be an option the codec declares.
- The dependency record of the previous run, if any: =<git dir>/compass/deps=
  of the checkout, read by =io::read_dependency_file=.
- The result cache of the repository, if any: the action objects in the
  packs under =<git common dir>/compass/packs=, read through the
  =types::action_source= that =io::action_source_of= returns, which maps
  the packs once when it is made.
- To write outputs: an absolute output root and the record of what the sink
  wrote last time, =<git dir>/compass/outputs= of the checkout, read by
  =io::read_written_outputs=.

* Outputs

- *Descriptor.* =types::descriptor= holds the name, the version, the code
  hash, a summary, the documents the codec reads, its options with their
  defaults, the rules it enforces, whether it runs by default, and its
  function. The version is bumped by hand to discard every stored result of
  the codec. The code hash names the code that computes the codec, so a
  build that changes that code replays none of the results an older build
  stored, with no bump; see /Code hash/ below. The function
  is one of four types, and its type is the only statement of two facts: a
  =document_function= is called once per document and a =corpus_function=
  once over all of them, and each emits a =file_output= or a
  =diagnostic_table=. A =file_output= is a =file_table= and the
  /refusals/ of the call (see /Refusal/). A =scan_function= is a corpus function of
  diagnostics in two steps (see /Scan/), and a =staged_function= a corpus
  function of files in a prepare step and parts (see /Staged codec/).
  =unit_of= and =output_of= read both facts back.
- *Refusal.* A codec of files that cannot produce an output, because an
  input is missing or does not parse, adds a finding to the refusals of
  its =file_output= saying why, under a rule it declares, and emits the
  files it can. The finding is recorded with the unit, as any other, and
  =compass check= reports it, so a generator that cannot run fails the
  check where its script would have failed. A codec that refused in a run
  is not complete (see /Output set/), so the sink removes none of its
  files: the file a good run wrote stays on disk, unchanged, until a run
  that does not refuse writes it again. The hook takes the same rule.
- *Rules.* =types::rule= is one rule a diagnostics codec enforces, or one
  reason a codec of files refuses an output: its
  name, unique within the codec, so that =codec/rule= names it in a finding
  and in an inline exception; a one-line statement of what it enforces;
  and =enforces=, the =:ID:= of each memory or document that states the
  rule in prose, as uppercase UUIDs, empty when none does; and =blame=,
  the =types::blame_method= compass blame traces a finding of the rule
  with: =line=, =added=, =drift= or, by default, =bisect=. =drift_rule=
  declares =drift=. The rules the
  runtime reports without a codec declaring them are constants beside
  =ops::excuse=: =ops::exception_rules=, under =ops::exception_codec=, and
  =ops::drift_rule= and =ops::names_missing_file_rule=, which every files
  codec declares besides its own. =names_missing_file= reads the header of
  each generated file, its first =ops::generated_header_lines= lines, where
  a codec says what generated the file and how to regenerate it, and
  reports a script, a word ending in =.py= or =.sh=, that the checkout does
  not hold: a banner must not send its reader to a deleted script. Text a
  codec copies from its inputs further down is the inputs' own. The descriptors
  are the one source of this metadata, and the rule table is generated
  from it.
- *Rule table.* =ops::rules_of= lists every rule of a catalogue: the
  rules each codec declares, by codec name, each codec's in the
  order it declares them, then the exception rules, then drift once for
  all files codecs. =ops::rule_table= renders them as an org knowledge
  page, one table row per rule with its codec, name, statement and a link
  to each page it cites (the bare ID when the corpus lacks that page),
  then the documents of type =memory= that no rule cites, by path. The
  page states its counts: rules, rules that cite a page, memories and
  memories no rule cites. Those memories are listed, not reported as
  findings: a memory no check enforces is work not yet done, not a defect
  of the tree, and a finding would fail or clutter every check until
  someone wrote the check. =ops::rule_table_version= hashes the format and
  every row, so a codec built on it reruns whenever a rule, a statement
  or a citation changes. The host binds the renderer to its catalogue
  as the =rule_table= codec.
- *Scan.* =types::scan_function= splits a gate that reads many files into
  =files=, which lists through the view the paths to map, =map=, which
  turns one file's path, bytes and the codec's options into its findings
  on that file and a /fact/ (=types::file_scan=), and =reduce=, optional,
  which reads every fact (=types::scanned_file=), in the order =files=
  gave, and may read more through the view. =map= reads nothing else, so
  its result depends on those alone. The findings of a call are those of
  the maps, file by file, then the reduce's. A /scan of documents/ sets
  =map_document= instead of =map=: it is given the corpus document at each
  path, with its parsed tables, whatever its type, so a gate over org pages
  reads the parse and not the text; the document's content ID is the
  file input, as reading it would be, and a listed path that is no
  document gets an empty fact. A scan is one corpus unit
  with the same inputs as before: a listing per pattern and a =file= input
  per file. When the unit is called, =ops::run= starts from the /scan
  table/ in the result object its previous record row names, under the
  same version and options: per file the content ID it mapped, its fact
  and its encoded findings (=ops::put_scan_entry=, =ops::decode_scan=). A
  file whose content ID is unchanged is taken from the table, as a =file=
  input with that ID, without being read; any other is read and mapped.
  The new table goes into the unit's result object, carried by
  =run_result::scans= row for row with =fresh=. An edit to one file so
  maps one file, and the reduce combines the stored facts with it.
  =types::fact_writer= and =fact_reader= encode a fact's fields. A codec
  that becomes a scan, or whose fact changes shape, bumps its version, so
  its next run stores a table. The table (=ops::encode_scan=,
  =ops::scan_table=) also keeps the reduce step's findings and, per file,
  whether the reduce step read the file itself through the view; the
  reduce step runs with a log of its own, which says so. When every file
  mapped again has the fact the table held for it and was not read by
  the reduce step, no file came or went, and every other input of the
  last call holds, the reduce step would see what it saw, so it is not
  called: its findings are the table's and the unit inherits the inputs
  that call recorded. An edit that leaves a file's fact as it was, as
  most edits do for most gates, so costs one map. A scan the record
  holds is not looked up in the cache: mapping the changed files costs
  less than reading every chunk of every set of its manifest.
- *Staged codec.* =types::staged_function= splits a corpus codec of files
  into =prepare= and =run=. =prepare= reads through the view what every
  part shares, and returns a state with a =types::stage=: the key of each
  part, in the order their files are joined, and /facts/, each a name and
  the hash of a value prepare derived. It is a unit of its own with an
  empty document that emits nothing, and its stage is kept in its result
  object where a scan keeps its table (=ops::encode_stage=). =run= is
  called with the state and a run of parts, on as many threads as a
  document codec; each part is a unit named by its key, begun through a
  =types::part_sink=. Its inputs are what it read through the view and
  the facts it told the sink it read, each a =fact= input whose answer is
  the hash prepare published, or a miss. A part is called again when one
  of them has another answer, so an edit that changes one fact calls only
  the parts that read it. The sink also lists the inputs of the part that
  changed since its last call (=changed=) and emits a file of that call
  unchanged (=keep=); a part that keeps a file inherits the inputs that
  call recorded, so it may skip the work the file took when no changed
  input could alter it. A path two parts emit is the later part's, in the
  run's files and in the output set. When the record or the cache stands
  in for prepare and a part must run, prepare is called again for its
  state alone. Code generation is the one staged codec: a part per model.
- *Inputs of a codec.* =types::inputs= is a list of =#+type:= values, every
  registered type, or every document including those with no registered type.
  =with_evidence()= adds the evidence documents of that scope, which no
  other codec reads.
- *Evidence.* A document whose first =#+filetags:= holds =evidence= is a
  record, not a live document (=org::ops::is_evidence=).
  =ops::index_corpus= flags each such row in =corpus_index::evidence= and
  gives an ID to a live document before an evidence one, whatever their
  order. For a codec that did not ask for evidence, an evidence document is
  not visible, no lookup finds it and =list_files= leaves its path out; the
  runner answers a recorded listing the same way, so tagging a listed
  document runs the codec again once.
- *View.* =types::corpus_view= is all a codec can read. It numbers the
  documents of the declared types from zero, so a codec cannot name a document
  of another type. =operator[]= returns a =types::document=: corpus row, path,
  content ID, type, source and tables. =find_id= and =find_path= return the
  visible document with that ID property or at that path, or nothing; a
  document of an undeclared type is not found. The view also gives the type
  registry and =option(key)=, the configured value or the default.
- *Recording.* The runner gives each call a =types::read_log= through the
  view, so a codec records what it reads by reading, with no code of its own.
  Every document handed out is an input keyed by its path, with its content
  ID, so the path is part of every document read. Every lookup is an input
  with its answer: for =find_id= the blob ID of the path found, for
  =find_path= the content ID, and a miss when nothing answered. A read of the
  type registry is an input with the SHA-1 of its tables. The view also
  reads the files of the checkout that are not documents: =read_file= is a
  =file= input with the content ID of the bytes read, =file_exists= a
  =file_exists= input whose answer is only found or missing, and
  =list_files(prefix, suffix)= a =listing= input keyed =prefix*suffix= whose
  value is the SHA-1 of the matching paths. A part of a staged codec also
  records the facts it read, as =fact= inputs. A corpus unit is recorded read
  by read, as a document unit is, until it enumerates the documents through
  =size()= or =operator[]=; from then on it depends on all of them, as one
  =type_set= input, the SHA-1 of the sorted paths and content IDs of every
  document it may read, and lookups after that are not listed. =types::corpus_index=, built by =ops::index_corpus=, finds documents
  by path and ID for the view and for selection alike.
- *Dependency record.* =types::dependency_record= has one row per unit: one
  call of a document codec, for one document, or the call of a corpus codec.
  A unit is keyed by codec name and document path, and carries the codec's
  version, the SHA-1 of its code hash and option values
  (=ops::configuration_hash=), its
  inputs (kind, key, found, value), its outputs (each file with its path,
  blob ID and bytes, or the count, SHA-1 and encoded bytes of its findings)
  and the keys of its manifest and result in the result cache.
  An encoded finding names its document by path, not by corpus row, so a
  record outlives the corpus it was made from; a byte before the path says
  whether it names a document or a file.
- *Record file.* =io::dependency_file_path= is =compass/deps= under the
  checkout's own git directory, beside the worktree index, so each worktree
  keeps its own. =ops::encode_dependency_record= lays out version 7
  little-endian: a 16-byte header (magic =CMPSDEP\n=, version, unit count);
  the head of each unit (its codec, version, configuration hash, document,
  inputs, the path, blob ID and size of each output, its findings and its
  cache keys); the contents of every output, unit by unit; the unit index;
  and a 28-byte footer with the offset of the index and the SHA-1 of the
  header and the index. The index (=types::unit_index=) holds the offset
  and SHA-1 of each head, the offset of each unit's contents, and the
  subjects: per kind and key, the units that name it. The kinds are a path
  a unit reads (a document, a file or an existence test), an ID it looked
  up, a listing pattern, the type set, the type registry, an output path,
  a path a finding names, and, keyed by codec, the units of a staged codec
  that read facts and the prepare step that published them. A full read checks every head against its
  SHA-1 and every output against its blob ID, so the record is hashed once,
  as before. =io::read_dependency_file= reads a missing file as an empty
  record and a damaged one, or one of another version, as an empty record
  with the reason, so every unit runs.
- *Reading one unit.* =io::read_unit_index= reads the header, the footer and
  the index and nothing else: about 11 MB and 60 ms on ORE Studio, whose
  record is 268 MB. =ops::units_touching= names the units an edit to one
  file may change, given an =ops::edited_file=: those that read it, report
  on it or produced it (looked up by its path under the output root), those
  that list a pattern it matches when it may be new, and for a document,
  those that enumerate documents or looked up an ID it holds. A lookup by
  ID that found a document also read its path, so a document whose ID
  changes is found by path. A unit of a staged codec brings every unit of
  that codec: a part is checked against the facts prepare published, any
  of which may change when prepare runs again, and which part a shared
  path belongs to is known only with all of them. =io::read_record_units= reads the heads of those
  units alone, each checked against its SHA-1, with the contents of their
  outputs left empty; =io::read_recorded_file= reads one output, checked
  against its blob ID. Codegen's 826 units are 193 MB with their outputs and
  about 3 MB as heads. A file replaced since the index was read fails the
  checks, and the caller says so. =io::write_dependency_file= writes through a
  temporary file and a rename, and only when the bytes differ from the
  file's. A run whose previous record stood in for every unit, and held no
  other, sets =same_record=, and a host need not encode or write it.
- *Files.* =types::file_table= has a path and the bytes of each file. Paths
  are relative to the checkout root.
- *Diagnostics.* =types::diagnostic_table= has, per finding, the document
  (its corpus row), a source range, the rule (an index into the descriptor's
  rules), a severity, a message, a fix and a file. A finding about a file of
  the checkout that is not a document, such as a C++ or SQL source, has no
  row: its document is none and its file is the path, relative to the
  checkout, that its range points into. A message holds no line number and
  no count, so the same finding has the same message after an unrelated edit.
  A finding may name a =subject=, the path of the file whose addition
  created what it requires, and a =subject_text=, the text the requirement
  is about in it; compass blame follows them, and nothing else reads them.
- *Registry.* =ops::make_registry= resolves each descriptor against the type
  registry and applies the configuration. =types::registry= holds, per codec,
  whether it runs, its option values, and one flag per registered type saying
  whether the codec reads it. =problems= lists what did not fit: a duplicate
  name, an unregistered input type, a setting nobody declared.
- *Run.* =ops::run= runs the enabled codecs on up to N threads. No codec reads
  what another emits, so all run at once. A corpus codec is one piece of work.
  A document codec is split into runs of documents, four per thread. Each
  piece fills its own tables and the tables of a codec are joined in document
  order, so the result is the same on any thread count. =types::run_result=
  holds, per codec, the documents given, the units run, skipped and cached,
  the files, the diagnostics and the time summed over threads, the record
  of the run and =fresh=, the units of the record that were called. An
  exception from a codec is rethrown after every thread has stopped. Given
  an =ops::unit_filter=, a run takes only the units it allows: the others
  are neither called, reused nor recorded, and a codec with no unit taken
  costs nothing, so the edit hook runs the few units an edit touches. A
  staged codec is taken only when its prepare step is. Given =edited=, the
  path of a file thought to have changed, the inputs with that key are
  checked first, so a unit that read it is known to need calling without
  checking the inputs before it; it changes no result.
- *Selection.* Given the previous record, =ops::run= calls a unit only when
  it is new, its codec's version or configuration hash changed, or one of
  its inputs has another answer now: a document's content ID changed, an ID
  now names another document, a lookup that missed now finds one, the type
  set of a corpus unit that enumerated changed, the type registry changed, a
  file read has another content ID or appeared or went, a file tested
  appeared or went, or a listing matches other paths. A unit that is
  not called is skipped: its recorded outputs go into the result where the
  call's would have, so a run with a record returns what a run without one
  does, and its row is copied into the new record. The record of a run holds
  only the units of enabled codecs.
- *Result cache.* A unit the record does not stand in for is looked up in
  the cache before it is called, in two levels, as ccache's direct mode
  does, so a unit never runs only to learn its inputs.
  =ops::manifest_key= is computed before the run: the format version, the
  codec's name, version and configuration hash, which holds its code hash,
  and the unit's identity, its
  document's path and content ID, or an empty path and an all-zero ID for a
  corpus unit, whose reads are known only from its input sets. The manifest (=types::action_manifest=) under that key
  lists up to =ops::manifest_capacity= (8) input sets, newest first, each
  the inputs a call read, in its record's order, with the key of the result
  it produced. A set is held as the keys of its chunks
  (=ops::chunk_input_set=): runs of its inputs, each a result object keyed
  by the SHA-1 of its bytes, cut after an input when the hash of its kind
  and key is zero modulo =ops::chunk_spacing= (128), or after
  =ops::chunk_limit= (1024) inputs. A cut depends on the input alone, so
  an edit to one file a corpus unit read changes one chunk, the sets of a
  manifest and of every worktree share the rest, and a manifest names a
  set in tens of bytes per hundred inputs rather than listing them. The
  first set whose every input has the same answer now,
  misses included, by the test selection uses, names the result object:
  =ops::result_key= is the SHA-1 of the manifest key and the inputs sorted
  by kind and key. The result (=ops::action_result=) holds the unit's files
  and its encoded findings. Its outputs go into the run's result and its
  row into the record exactly as a call's would, so a run from the cache
  returns what a run with no cache does, byte for byte. Format 6 ends the
  result with the unit's scan table or, for the prepare step of a staged
  codec, its stage; it is empty for any other unit. Each starts with a
  magic number, so neither is read as the other.
  A unit with 256 files or more hashes them on the run's threads as the
  record is assembled. A manifest or result
  that does not load, or whose findings name a document the corpus lacks, is
  a miss and the unit is called. =ops::run= only reads the cache;
  =io::store_actions= writes, for the units in =fresh=, the result object,
  the chunks of the unit's set the store does not hold intact, and the
  manifest with that set put first, all in one pack it
  publishes when every unit is written. =io::format_files= puts the
  formatted files it formatted in a pack of their own. The record names both keys
  of every unit, which is what keeps them through the store's collection;
  =io::action_keys= reads them from a worktree's record for the collector,
  with the keys of the chunks of each unit's inputs, cut again from the
  record. A chunk only a superseded set names is collected, and that set
  is then a miss.
- *A few runs per worktree.* Collection keeps the last =ops::kept_runs=
  (3) runs of each worktree, not only the one its record names. When a
  run writes a new record, =io::retire_keys= puts first in the worktree's
  =compass/retired= file the keys the units it replaced needed and their
  replacements do not (=ops::retired_keys=, by =ops::unit_keys=), and
  keeps two such runs; =io::action_keys= names those keys too. A
  worktree switched back to a recent branch so finds its results.
- *Code hash.* Every stored result, in the record and in the cache, is keyed
  by the code that computed it, so every environment can share one store
  through one installed compass and never replay what an older build
  stored. A component that defines codecs calls =compass_code_hash= in its
  =src/CMakeLists.txt=, and its =catalogue()= stamps each of its descriptors
  with its =code_hash()=. On every build =cmake/generate_code_hash.cmake=
  computes the SHA-256 of: every file under =include/= and =src/= of the
  component and of each component it links, directly or not, named by its
  path in the checkout; the bytes of each third-party library it links
  (PCRE2, expat, zlib), so a vcpkg upgrade counts; and the compiler's
  identity and version. Which components and libraries are hashed follows
  =target_link_libraries=, walked when the build is configured. The hash
  is written to a source compiled only into that component, through a
  temporary copied only when its content changes, so a build after a commit
  that touches none of those inputs recompiles and relinks nothing, and an
  edit to one component changes the keys of its codecs and of the
  components that link it, and of no other. =code_hash.cpp.inputs= beside
  the generated source lists what was hashed. The granularity is the
  component: a codec's own file and its includes would be finer, but a
  codec calls the operations of its component and the components below
  it, so its true inputs are a link closure, not an include closure. The
  hand-set version stays, to discard a codec's results deliberately. Not
  covered: the shared C++ and C runtime libraries, which an OS upgrade can
  replace under an unchanged binary.
- *Format cache.* =io::format_files= formats a =types::file_table= with the
  =types::formatter= its extension selects (an external program, its
  arguments, its passes and its style file) and returns the table formatted,
  row for row. A formatted form is an action result keyed by
  =ops::formatted_key=: the file's path, since clang-format and prettier read
  the file name, the blob ID of the raw bytes and =ops::formatter_key=,
  the formatter's name, its =--version= text, its arguments with the style
  path left as a placeholder, its passes and the blob ID of the style file.
  The version text is itself an action result keyed by =ops::program_key=,
  the program file's resolved path, size and modification time, so a run in
  which every key is found starts no process. Misses are written at their own
  paths under a temporary directory and formatted in batches of
  =io::format_batch= files, one process per pass per batch; rows of one key
  are formatted once. No record names
  these keys yet, so the collector keeps them only within its grace period.
- *Formatted outputs.* A files codec may name, in its descriptor, a
  =types::formatters_function=: given its =types::option_values= and the
  root of the checkout, it returns the formatters its files go through.
  =io::format_outputs= formats, in place, the files a =run_result= holds
  for each enabled codec that has one, through =io::format_files=, and
  sets the codec's =formatted_ids=, the blob ID of each formatted file,
  hashed on as many threads as formatting. =ops::outputs_of= takes such a
  codec's files from the run, not from its record. The record keeps the
  bytes the codec emitted, so a unit is reused whatever the formatters
  are, and a change of formatter or style file costs only the
  formatting.
- *Origin of a file.* A files codec may also name a
  =types::origin_function=: given its =types::option_values= and the bytes
  of one of its files, it returns the input that file was rendered from,
  such as its template, relative to the checkout, or nothing. The record
  keeps what a unit read, and one unit may render many files from many
  inputs, so this names the one input behind one file. No run calls it;
  =compass generate= and =compass diff= do, to say what produced each file
  they change and to take the files of =--scope=.
- *Output set.* =types::output_set= is what a run asks to have on disk: per
  file its codec, its path relative to the output root, its bytes and its
  blob ID, and the names of the /complete/ codecs, whose every unit ran or
  was reused. =ops::outputs_of= builds it from a =run_result=, from the
  record but for formatted codecs; a path two parts of a staged codec
  emit is taken once, from the later part; every enabled codec is
  complete but one that refused an output (=ops::refused=).
  =ops::check_outputs= lists a path that is not plain
  relative (absolute, empty, or with an empty, =.= or =..= component) and a
  path two rows produce, naming both codecs.
- *Output sink.* The sink is a plan and an apply. =io::plan_outputs= reads
  the root and decides, changing nothing; =io::apply_outputs= performs the
  plan; =io::write_outputs= is the two in turn. Nothing is planned when
  =check_outputs= finds a problem. An output whose recorded entry has the
  same blob ID and whose file has the recorded stat data is unchanged without
  being read. Any other output whose file exists is hashed and unchanged when
  it already holds the bytes; a lost or damaged record therefore costs a read
  of each file, not a write. Only then is the file written, through
  =platform::filesystem::update_file=, and its stat data recorded.
- *Untouched unless changed.* No output whose content is unchanged is
  opened for writing: it keeps its modification time, inode and mode, on
  every path the sink takes, whatever the plan says, because
  =update_file= compares before it writes. A file that is written keeps its
  mode. Each write goes to a temporary named for the file, =<name>.compass-new=,
  that replaces it in one rename, so a run killed partway leaves every file
  whole, old or new, and the files it had not reached untouched; a temporary
  it leaves is cleared by the next write of the same file. The test
  =app_untouched_tests.cpp= of =compass.cli= holds every generator to this.
- *Plan.* =io::output_plan= is an action table, one row per file: its path,
  its codec, its =io::output_action= (write, restore, unchanged, remove or
  keep) and its new bytes, which are views into the output set. It carries
  the record for the next run, complete but for the stat data of files still
  to be written. =io::summarise= counts a plan as applying it would.
  =io::sink_result= counts each output once:
  written (new bytes for the path), restored (bytes compass wrote before, put
  back after a hand edit or a deletion) or unchanged. A recorded file of a
  complete codec that no output names is removed when it still holds what
  compass wrote, with the directories that removal empties, up to the root;
  one edited since is kept in place and forgotten. Files of other codecs are
  carried over, and a file compass never recorded is never touched.
- *Diff.* =io::diff_outputs= prints the unified diff of each action of a
  plan that changes a file (write, restore, remove) against the file on
  disk, and =/dev/null= for a file that is absent or removed. It only reads.
  =ops::unified_diff= is the diff of two texts in git's format: a ---/+++
  header naming =a/= and =b/= paths, hunks with three lines of context
  merged when six or fewer lines apart, and the no-newline marker. It
  finds a shortest edit script with Myers' O(ND) algorithm in linear space,
  in process. A text with a NUL byte in its first 8000 bytes is binary, as
  git decides it, and gets git's one-line notice.
- *Hand edits.* =io::find_hand_edits= names each file a plan writes or
  restores that may hold code written by hand which the write deletes.
  It reads only a file that is on disk and is not what compass last wrote
  there, by the record the plan was made from, so a file compass wrote and
  nobody touched costs nothing. =ops::dropped_hand_lines= judges one file:
  it diffs it against the new output with no context, and weighs each hunk
  by the non-blank lines it removes that the output holds nowhere, less
  the non-blank lines it adds, all trimmed of white space. A hunk weighing
  =ops::dropped_block_minimum= (3) or more is reported, the heaviest with
  its first counted line: a function written into a generated file is
  dropped whole and weighs its length, while a block a template change
  rewrites with as many lines of its own, a move and a reindent weigh
  nothing. Two lines, or a rewrite that shrinks a block by two, are not
  reported; that is the price of not warning on every template change.
- *Written-outputs record.* =types::written_outputs= holds the absolute root
  and, sorted by path, each file's codec, blob ID and stat data after the
  write. A record of another root is ignored. Its =written= time is the start
  of the run that last changed it; an entry modified in that second or later
  is racily clean and is compared by content, as git treats its index. The
  file is =compass/outputs= beside the dependency record:
  =ops::encode_written_outputs= writes magic =CMPSOUT\n=, version, entry
  count, written time, root, the entries and a SHA-1 trailer.
  =io::read_written_outputs= reads a missing, damaged or other-version file
  as an empty record, with the reason when there was a file.
  =io::write_written_outputs= writes by temporary file and rename, and only
  when the bytes differ.
- *Exceptions.* An exception is a comment
  =compass:except(<codec>/<rule>) expires=<YYYY-MM-DD> approver=<name>
  reason=<text>=, or =compass:except-file(= for one that covers a whole
  file, or a row of the exceptions table of =.compass.org=. Both land in
  one =types::exception_set=: per exception (=types::exception=) the file
  it is written in and its line there, the file whose findings it
  excuses and the line it covers, its scope, rule, reason, approver and
  expiry, and per one that does not parse (=types::malformed_exception=)
  where it is written and why. =ops::parse_exceptions= reads the comments
  of a file, each written in and excusing that file. The marker counts
  only right after a comment opener (=//=, =/*=, =--=, =#=, =;=, =<!--=),
  and in an org file only on an org comment line outside any
  =#+begin_= ... =#+end_= block, so prose, examples and the lines a block
  renders into another file are not exceptions of the org file. One after
  code covers its own line; one alone covers the next line that is not
  itself an exception comment, so exceptions stack.
  =ops::add_exception_row= reads the cells of a table row (path, line or
  empty for the whole file, rule, expires, approver, reason), written in
  the configuration file, with the checks a comment gets: a path inside
  the checkout, normalised as findings name it; a positive line; a rule
  name; a date. =ops::append= joins sets. =ops::excuse= takes the sites
  of the findings (path, line, rule), the set, the registry and today's
  date, and returns which sites are excused and the findings about the
  exceptions, in the file each is written in: =exception/malformed= (did
  not parse, unknown rule, or an =exception/= rule),
  =exception/incomplete= (no reason, approver or expiry),
  =exception/expired= (valid through its expiry date; on the line a
  comment covers, on its own line for a file-scope comment or a row) and
  =exception/stale= (valid, of an enabled codec, excuses nothing). A row
  that names a line covers that line only, so a finding that moves leaves
  the row stale and is reported again. =ops::status_of= says whether a rule is one an
  enabled codec declares; a files codec declares =drift= and
  =names_missing_file=. The runtime
  applies exceptions after a run, not inside a unit, so a result from the
  record or the cache never hides an expiry.
- *Unmarked record.* =io::unmarked_file_path= is =compass/unmarked= under
  the checkout's git directory: magic =CMPSUNM\n=, the marker, the sorted
  content IDs known to hold no marker and a SHA-1 trailer.
  =io::read_unmarked_file= reads a missing or damaged file as empty, and
  =io::write_unmarked_file= writes by temporary file and rename, only when
  the bytes differ. A host reads only the files whose IDs it lacks.
- *Document type.* =ops::document_type= gives the registered type the first
  =#+type:= keyword of a document names.
- *=document_index=.* A corpus codec that emits one tab-separated file: a
  header, then the ID, title, type and path of every document, evidence
  included, in byte order of the paths. The option =path= names the file and
  defaults to =doc/document_index.tsv=.
- *=evidence_location=.* A document codec over every document, evidence
  included. It reports an evidence document whose path has no =evidence/=
  directory, under the rule =outside_evidence_directory=, on its
  =#+filetags:= value.
- *=required_sections=.* A document codec over every typed document. It
  reports each section the type requires and no heading of level 1 of the
  document carries, under the rule =missing_section=; a heading nested in
  another section is not the section. The fix names the heading to add.
- *Tangling.* =ops::tangle= does what org-babel-tangle-file does under
  =emacs -Q=, without Emacs. It reads the block table of one document and
  returns the files its source blocks tangle to and the blocks it cannot
  tangle. A block with a language and =:tangle <path>= is tangled. A block
  with =:tangle no= or without =:tangle=, or under a =COMMENT= heading or a
  heading tagged =ARCHIVE=, is not. The path is resolved against the
  document's directory and is relative to the checkout root. The blocks of
  one target are joined in document order: each body is followed by a
  newline, with an empty line between two blocks (Emacs's default
  =:padline yes=). A body is the block's text with the escaping comma
  removed from lines that are blanks, commas, then =*= or =#+=
  (=org-unescape-code-in-string=). Its last newline is dropped and the
  indentation common to its non-blank lines is removed as
  =org-remove-indentation= removes it: a tab counts to the next multiple of
  eight, a tab that crosses the cut stays, and nothing is removed when a
  non-blank line is at column 0. Last, blanks and line ends at both ends
  are trimmed (=org-trim=), because =org-src-preserve-indentation= is nil.
  These rules come from Org 9.7's =ob-tangle.el=, =ob-core.el= and
  =org-macs.el=. Header arguments that leave the bytes alone are accepted:
  =:results=, =:exports=, =:eval=, =:cache=, =:session=, =:mkdirp=,
  =:noweb-ref=, =:padline yes=, =:comments no= and =:noweb no=. Any other
  argument, a switch, a =:tangle= value that is not a plain path, a
  =#+header:= line, and =header-args= set by =#+property:= or a property
  drawer are problems. A target with a problem block is not written.
  =build/scripts/tangle_diff.py= compares the files the codec writes with
  the files Emacs wrote. =ops::tangle_options= carries what a caller of
  =org-babel-tangle-file= may pass besides the file: a language, as a
  =LANG-RE= naming one language does, a default target, as =TARGET-FILE=
  is, which a block without =:tangle= tangles to, and whether =:var= is
  inert for the language, in which case a document may set it in
  =header-args=.
- *=tangle=.* A document codec over every document that emits the targets
  of =ops::tangle=. It is off by default. The option =directory= limits it,
  and =tangle_check=, to the documents directly in one directory, as ORE
  Studio's =tangle-templates= generator tangles
  =projects/ores.codegen/library/templates/*.org=; set so, it writes all 171
  templates byte for byte as Emacs 30.2 does. =ops::check_outputs= refuses two
  documents that tangle to one path, and names the path.
- *=tangle_check=.* A document codec over every document that reports each
  problem of =ops::tangle=, under the rules =unsupported_header_argument=
  and =target_outside_checkout=. It is still a codec of its own; now that
  a codec of files reports its refusals, it can become =tangle='s.
  Enable it with =tangle=.

* Dependencies

- =compass.org= for the tables, the type registry and the document lookups.
- =compass.store= for =blob_id=, the content ID of a document, for SHA-1, for
  =write_object=, which puts the record files and the outputs in place by
  rename, for the action objects of the result cache and their directories,
  and for =stat_of=, =hash_file= and =is_unchanged=, which decide
  whether an output on disk still holds what compass wrote.
- The C++23 standard library and threads.
- =compass.ingest= and Catch2, for the tests only: the tests parse their
  documents and build their registry from contract pages.
