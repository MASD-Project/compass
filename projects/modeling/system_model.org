#+title: System Model
#+description: compass-ng's layered architecture (foundation / infrastructure / domain / application / tooling) and the components proposed for each layer.
#+type: knowledge
#+level: cross
#+filetags: :modeling:architecture:system_model:masd:
#+created: 2026-10-27
#+updated: 2026-11-16

compass-ng follows the ORE Studio system model: components grouped into layers,
with one invariant --- *a layer depends only on layers below it*. In MASD terms
the layers and components are physical-space instances of the meta-layer and
meta-component concepts (see ORE Studio =projects/modeling/applied_masd.org=).
Component layout rules live in [[id:8A0E6F32-C4BC-4667-88E8-7F80CA25437C][Component architecture]].

Every component below exists or has an agreed story. A component is added
when a story needs it, never in advance; in particular there is no server
until a measured use case needs one (see
[[id:2F71292F-CDB0-4E2E-B50F-4F02E10597C4][Product identity]]).

* Runtime shape
One process per command. =compass= lists the files of a checkout, resolves
their content IDs from git's index, maps the parsed objects it already holds
from the store shared by every worktree, parses only what is missing, runs the
enabled codecs whose inputs changed, and writes only the outputs whose content
changed, or prints them as a diff.

#+begin_example
 files ──▶ ids (git index) ──▶ store (mapped objects) ──▶ codecs ──▶ sink / diff
             compass.store       compass.store, .org        .codec     .codec
#+end_example

* Foundation layer
No compass-ng dependency. Generic, reusable code.

| Component          | Role                                                    |
|--------------------+---------------------------------------------------------|
| =compass.platform= | OS abstraction: memory-mapped files.                    |

* Infrastructure layer
| Component       | Role                                                                                                                       |
|-----------------+----------------------------------------------------------------------------------------------------------------------------|
| =compass.store= | Content-addressed store shared by the worktrees of a repository: git blob IDs as keys, loose objects, the git and worktree indexes, action objects, collection by reachability. |

The store holds what is derived from files and can be computed again. It does
not know what an object holds: =compass.org= lays out the object of a parsed
document, so the store stays below the domain layer.

* Domain layer
| Component        | Role                                                                                                                                                                       |
|------------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| =compass.org=    | The tables an org-mode document becomes: element tree, objects, headings, keywords, properties, blocks, lists, links and interned names, with byte ranges into the source; and the document type registry. |
| =compass.ingest= | Readers that fill the =compass.org= tables: the org-mode parser and the type registry builder first, then the C++ and SQL fact extractors.                                   |
| =compass.codec=  | The codec runtime: descriptors, the recorded view of the corpus, file and diagnostic tables, the registry and runner, dependency records, the output sink, diff mode and the result cache; and the codecs that need only the org tables. |

=compass.codec= is in the domain layer because a codec is defined in terms of
the document model: its inputs are document types and its diagnostics name
documents and source ranges. It depends on =compass.org= for the tables and
the type registry, and on =compass.store= for content IDs. It does not depend
on =compass.ingest=, so it runs the same over a fresh parse, a mapped store and
the blobs of a past commit. A component that adds codecs, such as code
generation or the HTML export, depends on =compass.codec= and nothing depends
on it in return; each is added by the story that needs it.

Work management (stories, tasks, sprints) is not a separate component: a unit
of work is a document with a lifecycle state, read through the same tables.

* Application layer
| Component     | Role                                                                                                                                 |
|---------------+--------------------------------------------------------------------------------------------------------------------------------------|
| =compass.cli= | The =compass= executable: loads the corpus, runs codecs, writes outputs or prints diffs, collects the store. The one host of the pipeline. |

* Tooling layer
| Component       | Role                                                                                   |
|-----------------+----------------------------------------------------------------------------------------|
| =compass.bench= | The frozen measurement harness: wall time, bytes and counts per stage of the pipeline. |

=compass.bench= hosts the pipeline until =compass.cli= exists; after that it
only measures.
