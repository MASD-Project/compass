This page is the component overview for =compass.crosscheck=, a simple
component in the domain layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.crosscheck= runs the ORE Studio gates that read more than one kind
of artefact: a generated row and the SQL that creates its table, the
generated output and the model it came from. Each gate was a Python script that read
the tree on every run; here each is a corpus codec that reads the files of
the checkout through its view, so a run in which none of them changed
reuses the findings. =entity_writes=, =single_writer=,
=subject_conformance= and =model_rules= are scans: each file's writers, subjects or model facts are
kept per content ID, so a run after an edit maps the edited file alone.
=generated_column_refs= and =entity_binary_types= are document codecs:
each model is a unit of its own, so an edit to a model checks that model
and those that read it.

The ports follow their scripts rule for rule, including the order of their
tests, because the acceptance of a port is the same verdict on the same
commit. The rules the scripts state about one codegen model are the
exception: =model_rules= reads each model as compass.model's loaders read
it, from its parsed outline, not with the scripts' line patterns. It
differs from them only where a pattern was wrong: a heading, a keyword or
a drawer line inside a source block is text, and a level-two heading of a
document that is not an entity, junction or field group model is not a
column. The gates that read generated code to re-check what a model
states read the model instead, as code generation reads it
(=ops::generated_shape_of=): what its create script, repository row,
domain struct and table writer will hold, and whether code generation
renders each. Their findings are on the model, before it is regenerated.
The text helpers of =compass.cpp= (Python's lines,
spaces, pathlib order and the finding on a byte of a file) are shared, and
the patterns go through the Python-compatible regular expressions of
=compass.platform=.

A script's baseline of known violations is not ported. Each finding it
excused is a finding here, and the tree excuses it with an inline
exception where it stands.

A gate or rule that another check covers, or that never fires, is not
ported:

- =paste-blocks=. A pasted block that disagrees with the generated file it
  lands in is =codegen/drift=. One that agrees with it but names a symbol
  that is gone fails the build of that component.
- The C++ half of =subject-conformance=. Its pattern opens on a double
  quote and closes on a single one, so it matches nothing in compilable
  code.
- =model-sql-types=. A model's column type and its generated create script
  disagree only as =codegen/drift=. The gate compares a model with the
  first table its create script makes, and no ORE Studio model has a
  hand-written create script, so it had nothing else to compare.
- The =unknown_profile= and =profile_conflict= rules of =model-drift=. The
  model loader of =codegen= refuses a model that binds a profile that does
  not exist, or two profiles that disagree, and the refusal stops the
  check.
- The floors that asked a run to read enough to prove its patterns still
  matched: =money_decimal_columns/too_few_columns=,
  =model_drift/no_profiles=, =subject_conformance/no_declaration= and
  =entity_binary_types/too_few_compared=. A parsed model cannot go blind
  the way a line pattern can.
- =entity_binary_types/no_table=. The row and the create script compared
  are generated from one model; a row on a table its model does not
  create, a view or a staging table, is not compared.

* Inputs

- The files of the checkout, through =types::corpus_view=: =list_files=
  for the paths each gate walks and =read_file= for the bytes.
- The parsed documents of the checkout, through the same view: the models,
  the profiles and field groups they read, and the Authorised reads page.

* Outputs

- *=model_rules=.* The rules six scripts state about one codegen model
  (=money-decimal-columns=, =http-areas=, =model-drift=, =route-units=,
  the model halves of =subject-conformance= and =protocol-twin-coverage=),
  as one scan of documents. A model is a document directly under a
  =modeling/= directory of =projects/= whose =#+type:= is one ores.codegen
  loads; the map builds its =compass.model= outline once and runs the
  rules that need that model alone, and keeps what the reduce step needs:
  its =#+http_area:= keywords, the route unit it opts into, and, when it
  binds a profile, what its drawers state of each feature. A profile's map
  keeps the rows of its =Assignments= tables. An edit to a model maps
  that model, and the reduce step runs only when a fact changed or a file
  it read did.
  - =money_not_exact=, =continuous_exact=: the columns of an entity or
    junction, the children of its =Columns= section, and the fields of a
    field group, with their drawers' =:type:= and =:cpp_type:=. A name is
    continuous when one of its tokens is a continuous word, money when
    its head noun is a money word. The script's two hand-written column
    lists are the options =excluded_columns= and =continuous_columns=,
    and its baseline of 7 money columns is 7 findings on the column's
    heading.
  - =unpublished_area=, =unreadable_areas=: a frontmatter =#+http_area:=
    outside =AREAS=, less =NO_AREA=, of =route_classification.py= (the
    option =classification=), read as the Python literals they are; the
    module is read only when a model declares an area.
  - =contradicted=, =unset_required=, =self_contradicting=: the profiles
    of =projects/modeling/variability_*.org= fix features in their
    =Assignments= tables; a model binds them by its =profile= property and
    states features in any drawer. The script's =KNOWN_MODEL_DRIFT= entry
    no longer fires at 545cafca45.
  - =opt_out=: a drawer that states =ores.ts.protocol.enabled=.
  - =outside_protocol=: a drawer's =:subject:= that is not
    =component.v1.resource.verb= with a verb of the closed set or
    =list_by_...=, =component.v1.ops.operation= or
    =component.v1.events.collection.action= (=ops::classify_subject=).
  - =unreadable_model=: a model that is not UTF-8.
  - =unregistered_unit=, =twice_registered=, =missing_unit=
    (=build/scripts/check_route_units.py=): a model directly under
    =projects/ores.<c>/modeling/= whose file drawer switches
    =ores.cpp.http-route= on, read as code generation reads an override,
    owns the unit its =#+entity_singular:= or =#+name_singular:= names.
    The aggregate =projects/ores.http/<c>/src/routes/<c>/<c>_routes.cpp=
    registers each such unit, each once, and only units with a source
    beside it. The aggregates are read only when the reduce step runs, so
    a model edit that leaves the opt-in as it was reads none of them.
- *=subject_conformance=.* The data-quality half of =subject-conformance=
  (=check_subject_conformance.py=): rule =outside_protocol=, a quoted
  subject of the data-quality artefact type seed outside the protocol, by
  the same grammar.
- *=entity_writes=.* =entity-writes= (=check_entity_table_writes.py=). Rule
  =sql_writer=: a function under =projects/ores.sql/create/= whose body
  inserts into, updates or deletes from an =ores_..._tbl= table, but the
  purge. The functions and what they write are =compass.sql='s model of
  the file (=ops::model_of=): the body is the function's dollar body,
  whatever its tag, read from code and from the SQL of the literals it
  executes, never from comments. Rule =cpp_writer=: a hand-written C++ file that writes such a table
  and is not the repository of every table it writes. The 136 writers of
  the script's baseline are findings, one per function or file.
- *=single_writer=.* =single-writer= (=check_single_writer.py=), which ran
  only in ORE Studio's CI. Rule =second_writer=: a =.sql= file under
  =projects/ores.sql/populate/= that inserts into a table some
  =*_publish_from_dq_create.sql= file under =projects/ores.sql/create/=
  also inserts into, once per table on the line of the file's first insert
  into it. Inserts are read as the script read them: =INSERT INTO= and the
  table name in any case, optionally quoted, after block comments and then
  line comments are removed. A file's fact is its role and each table it
  inserts into, so an edit maps that file alone. The script's nine listed
  exceptions become =compass:except= comments beside the inserts they
  excuse, and the runtime reports one that excuses nothing as stale. On
  ORE Studio's main at =732fc2ee34= it reports the same 16 populate files
  and 9 tables as the script.
- *=entity_binary_types=.* =entity-binary-types=
  (=check_entity_binary_types.py=), a document codec over each entity and
  junction model whose repository row and create script code generation
  renders. Each column the model states that the row binds with =bind=
  or =key= has the member type the row's template gives it, from
  codegen's column flags, and the type the create script gives it; rule
  =wire_mismatch= reports two that travel in different formats, or a key
  column the row declares no member for, and =unclassified= a type the
  check cannot place, on the column's heading. The template's own
  columns (tenant, version, audit, validity) are not the model's
  statement and are not compared. At ORE Studio =c25e952663= the member
  and SQL types agree with the generated code for all 4666 columns of
  573 rows.
- *=generated_column_refs=.* =generated-column-refs=
  (=check_generated_column_refs.py=), a document codec over each entity
  and junction model. Rule =not_a_member=: a column of the model's Table
  display that is not a member of the domain struct it generates (a field
  of a domain, identity or audit group as =member.field=), when the table
  writer is generated. Rule =not_a_column=: a column one of the model's
  indexes names, outside an expression, that its create script does not
  make, when the script is generated. At =c25e952663= the create scripts'
  columns and the writers' members agree with the generated code for 579
  scripts and 442 writers.
- *=open_reads=.* =open-reads= (=check_open_reads.py=). Rule =open_read=: a
  read of a generated handler, a =list_= or =get_= method or one that
  decodes a protocol request, that checks no permission and whose subject
  the =allow_list= page does not name. The page is read from its parse:
  the rows of the tables of its first level-two =The allow-list= section
  whose first cell is one =subject= alone. Rules =unguarded_history= (a
  history registration with no literal read code), =stale_allow= (an
  allowed subject no protocol header defines) and =no_allow_list=.
- *=registry_exceptions=.* =registry-exceptions=
  (=check_registry_exceptions.py=). Rule =bad_exception=: an entry of
  =ACCEPTED_EXCEPTIONS= in =component_registry.py=, read as a literal, for
  a component =COMPONENTS_UNDER_TEST= does not list, for an item the clean
  standard's checklist does not define or twice, or with no reason, no
  acceptor or a date that is not ISO. Rule =unreadable_registry=: no item,
  or a table that is not a literal.
- *=template_sections=.* =template-sections=
  (=check_template_sections.py=). Rule =chained_tags=: a line of a
  template that holds two or more section tags and nothing else, one of
  them opening or closing a section that spans lines. The script's count
  per template becomes one finding per line, 8 at this commit in
  =cpp_domain_type_entity.hpp.mustache=, for inline exceptions to excuse.

- *=protocol_twins=.* =protocol-twins=
  (=check_protocol_twin_coverage.py=). The twin directories come from the
  =ores.ts= archetypes of the template library's graph, which
  =compass.codegen= loads as the codegen codec does, and the components
  from its catalogue and the registry's =COMPONENTS_UNDER_TEST=. Rule
  =missing_twin=: a protocol header of a checked component with no
  TypeScript twin. A model that switches the facet off is
  =model_rules/opt_out=, so a model edit does not run this codec.

- *=marketdata_identity_columns=.* =marketdata-identity-columns=
  (=build/scripts/check_marketdata_identity_columns.py=). The series
  identity table, the projector's field switch and index mapping and the
  per-asset-class views agree with the codec schema and the index grammar
  (=table_columns=, =projector_switch=, =views=, =index_mapping=). The
  table's columns are those its model,
  =ores.marketdata.market_series_identity.org=, gives its create script,
  and =table_columns= is reported on the model. A source
  that lost the shape the script reads is one =unreadable_source=
  finding, and nothing else is reported, as the script stops there.

- *=conventions_coverage=.* =conventions-coverage=
  (=tools/ore_conventions/extract.py=, then =propose.py --check=). A scan:

Three gates of the parameter value sets are one model here, not three
ports. ORE Studio's =generate_value_sets.py=, =generate_ore_element_map.py=
and =check_parameter_value_sets.py= each resolved the same curation in a
process of its own and judged its sets with two lists of rules.
=ops::value_sets::evaluate= resolves it once: the guide's sets, the code's
over them, the two reviewed files, then the sets the convention terms, the
curve leaves and the engine run settings imply, and the element map from
the curve family columns and the convention kind terms
(=ops::curve_columns= and =ops::convention_terms=, which
=curve_sections_wiring= and =ore_value_sets= write from too). It reads the
curation as JSON with =ops::json_value=, which keeps an int apart from a
float, the ORE schemas once with =ops::ore_schema=, and the policy tables
of the five Python modules as literals; the curve module's =OWN_SETS=,
which calls the schema reader, is stated in the code. Of the curation
directory it reads =engine-settings-groups.json= alone. Two codecs read the
model:

- *=ore_value_sets=.* The value set seed, the element map and its columns
  seed, byte for byte what the two scripts write on ORE 545cafca45 with
  the =r.id= exemption, and what =generate_convention_kind_terms.py=
  writes (=convention-kind-terms=): the convention kind terms seed, the
  term validation triggers and their drops, from the terms the resolution
  resolved, once. On ORE 545cafca45 the script and the codec both refuse
  the terms, because =conventions_fx_projection.cpp= reads =r.id=, which
  the script's =NOT_A_COLUMN= does not exempt. It writes nothing while the model has a problem,
  and refuses the seed, or the element map, pointing at
  =parameter_value_sets= for why.
- *=parameter_value_sets=.* Every rule, once: =unresolved= (a generator
  would raise, and why), =unlinked_parameter= (a parameter a screen draws,
  pricing or engine run setting, with no set), =clash=, =unknown_set=,
  =unnamed_set=, =impossible_set= (the generator's and the check's set rules
  as one list), =unruled_leaf= (a leaf of the map that names no authority,
  past =UNREAD_ALLOWED=), and the check's source rules =override_column=,
  =value_check= and =missing_file=. At 545cafca45 it reports one
  =unresolved= finding: the convention kind terms stop on =r.id=.

The schema walk collects the elements of a group nested in another at any
depth; =ore_schema_types.py= looks one level too deep there, which changes
nothing at 545cafca45.

These generators keep their tables in Python modules, and the codecs read
those tables through =ops::python_assignment= rather than copying them, so
an edit to a table is seen. The reader takes the literals the modules are
written in: strings with their prefixes, f-strings and sums of strings and
names, numbers as written, tuples, lists, sets and dicts (tuple keys too),
calls with positional and keyword arguments, and a lambda, read as its
body. =ops::resolved= substitutes a module's
string constants for its names. Where a script stops without writing,
because a problem is reported or a table cannot be read, the codec writes
nothing and reports a =refused= finding on its first output that says why,
so =compass check= fails where the script would, and the sink keeps the
file a good run wrote. Every generator here declares that one rule,
=ops::refusal_rules= of =compass.cpp=: =curve_sections_wiring=,
=ore_renderings_tables=, =script_library_seed=, =ore_output_catalogue=,
=er_diagram=, =conventions_dataset=, =route_inventory= and
=ore_value_sets=. At 545cafca45 =ore_value_sets= refuses twice, the
convention kind terms and the value set seed, both on =r.id=.

Where a script reads a file with a strict UTF-8 decode and would stop on a
file that is not UTF-8, these codecs read it with invalid bytes replaced,
except =model_rules=, which reports such a model.

  through and the diagnostic table they fill.

  which =model_rules= and =open_reads= read, and the loaders, which

- =compass.store= and Catch2, for the tests only.
