This page is the component overview for =compass.cli=, a simple component
in the application layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.cli= is the one host of the pipeline. It lists the files of a
checkout, resolves the IDs of its org files from git's index or the
worktree index, maps each parsed object from the store or parses the file,
builds the type registry from the contract pages, and runs the enabled
codecs from the dependency record and the result cache: those
=compass.codec= ships, the codecs of =compass.codegen=, the C++
gates of =compass.cpp=, the SQL gates of =compass.sql=, the
cross-artefact gates of =compass.crosscheck= and the document gates of
=compass.docs=, which =app::codecs= lists, then =check_inventory= and last
=rule_table=. =check_inventory= writes a project's page of every codec and
check that runs there (=app::inventory_page=): whether each is enabled, its
kind and severity, its purpose, its rules, the built-in =drift= and
=names_missing_file= of a generator included, and the check document that
defines it or gives it data, linked by its =:ID:=. Only the host sees
the whole run, so =options_of= builds the inventory from the catalogue,
the check documents and the settings (=app::inventory_of=) and sets it as
the codec's =inventory= option: a change to what runs changes the codec's
configuration, so the page is regenerated, and reported as drift until it
is. The page is a knowledge page, kept to that contract: a blurb, then
=* Detail= with the table and a section per codec, and =* See also= for
compass itself. Its other options are its =path=, under =doc/knowledge/=
by that contract and never under =compass/checks/=, and its frontmatter, the =created= and =updated= dates
fixed so the page does not change by the day. It is off by default.
=rule_table= is the host's own too: it binds =ops::rule_table= of =compass.codec= to
the list, since only the host knows every codec, and its version is
=ops::rule_table_version= of the list, so a changed rule, statement or
citation regenerates the page; its code hash is =app::code_hash=, that of
this component and everything it links, where every other codec carries
the code hash its own component's catalogue stamps. It reads every typed document, for the
memories and the titles of the pages a rule cites, writes the page to its
=path= option, and is off by default. The codecs read the other files of the checkout
through =app::checkout_files_of=, whose content IDs come from the same
resolver. =generate=, =diff= and =check= then format the files of each codec that
names formatters, through the result cache. Then each command does one
thing with what the codecs produced:

| Command           | Does                                                                     | Writes                                            |
|-------------------+--------------------------------------------------------------------------+---------------------------------------------------|
| =generate=, =gen= | Makes the files under the output root hold what the codecs emit.         | Store, records, outputs.                          |
| =diff=            | Prints what =generate= would change as unified diffs.                    | Nothing.                                          |
| =check=           | Prints every diagnostic as =path:line:column: rule: message (fix: ...)=, and a =codec/drift= diagnostic for each file =generate= would change. | Store and records, no output.                     |
| =check --commit=  | The same diagnostics at a commit, read from git's objects with no checkout. | Store and result cache only.                   |
| =check --ratchet= | Only the diagnostics the merge base of HEAD and a base lacks.            | Store and records, as =check=.                    |
| =blame=           | Traces one finding to the commit, pull request and environment that likely caused it. | Store and result cache, for bisect.               |
| =check --today=   | The same diagnostics, with exception expiry judged as of another date.  | As =check=.                                       |
| =gc=              | Drops old unreferenced objects and action objects from the store, rewriting its packs into one, and removes the first layout of the store. | Rewrites the packs, unless =--dry-run=. |
| =hook=            | Checks the one file a Claude Code PostToolUse payload on standard input names, running only the units that read or report on it. | Nothing.                                          |
| =config=          | Prints every path and codec setting in effect, and where it came from.   | Nothing.                                          |

The library holds the pipeline and prints nothing. =app/steps.hpp=
exposes it as one function per step, so a caller can time each:

| Step                                       | Does                                                                          |
|--------------------------------------------+-------------------------------------------------------------------------------|
| =list=                                     | Every file of the checkout, and its org files but =.compass.org=.             |
| =checkout_files_of=                        | The files as the codecs read them: IDs resolved once each, bytes from disk.   |
| =build_type_registry=                      | The type registry of the contract pages.                                      |
| =open_files=, =resolve=                    | One row per file, and its ID from git's index, the worktree index or hashing. |
| =load=                                     | Each object mapped from the store, or the file parsed into memory.            |
| =corpus_of=                                | The rows that loaded, typed, as the corpus the codecs read.                   |
| =read_dependency_record=, =run_codecs=     | The codecs run from the dependency record and the result cache.               |
| =store_objects=, =write_worktree_index=    | The parsed objects and the worktree index, with every listed file hashed.     |
| =store_results=, =write_dependency_record= | The result cache and the dependency record written, and the keys it retired.  |
| =write_outputs=, =plan_outputs=            | The outputs written, or planned for a diff.                                   |
| =collect=                                  | The store collected, by =gc=, or by a run once the store has grown.           |

A check of a commit runs the same steps over an =app::commit_source=: the
commit listed by =store::io::list_commit= and its object database. =list=
takes the commit's paths and its regular =.org= files, =resolve= the IDs
its trees record, =load= reads each document's blob, which the tables'
ranges need, and parses it only when the store has no object for that ID,
=build_type_registry= reads the contract pages of the commit, and
=checkout_files_of= answers a content ID from the tree and reads a blob
only when a codec that runs asks for its bytes. The drift of each output
is decided against the commit's file at its path, by ID first, as a
check of a fresh checkout of the commit would decide it, with no
written-outputs record. The run stores the objects it parsed and the
results it computed, which every worktree shares, and writes neither the
worktree index nor the dependency record of the checkout. It starts from
that dependency record, which is safe, since a unit of it stands in only
when every input it recorded has the same answer in the commit. Setting
=options::commit= is the whole interface, so ratchet mode can ask for the
diagnostics at a merge base with the same call.

On a copy of ORE Studio at =08a73b6767= (10,927 documents, codegen and the
four ported gates enabled), =compass check --commit HEAD= gave the same 24
=codegen/drift= findings as =compass check= in a =git worktree add= of the
commit. With an empty store it took 23.3 s: 17.5 s formatting, 4.0 s
running the codecs, 139 ms reading and parsing the documents and 32 ms
listing the commit. A second run took 2.9 s, and 2.2 s once the
checkout's dependency record matched, against 2.9 s for =compass check=
of the checkout itself, which lists, stats and reads files on disk.

=check --ratchet= is =app::ratchet=. It resolves HEAD and the base with
=git rev-parse= and their merge base with one =git merge-base=. It checks
the checkout as =check= does, then the merge base with =options::commit=
set, both with the checkout's configuration, so a gate the branch enables
excuses what the merge base already broke. =ops::split_new= then splits
the findings of the checkout into new and excused. A finding matches an
old one by path, rule and message, not by line, and each old finding
excuses one: a violation that moved is not new, a second copy of it is.
Among matches, one on the same line is excused first, so the copy
reported is the one on a new line. A file with findings that HEAD no
longer holds is followed to the path where HEAD holds its blob
(=ops::exact_renames=), and only when that leaves one unexplained does
=git diff -M= pair it by similarity.

A =codec/drift= finding carries =drift_sides=, the blob IDs of the file
and of what the codec generates for it, and matches on those, not on its
message. Drift is excused only when the branch changed neither side.
Matching by path and rule alone would hide a branch that edits a model
whose output already drifts. Matching by message would fail, since a
check of a checkout and a check of a commit word the same drift
differently. Excusing no drift would fail every branch of ORE Studio on
its 24 standing drift findings.

On the ORE Studio copy, a branch adding one =create table= to
=setup_schema.sql= failed on that line only, with the 24 drift findings
excused. With an empty store it took 27.2 s, 24.3 s of it the check of
the checkout, which formatted for 17.5 s. Warm, it took 5.2 s: 3.2 s for
the checkout and 1.8 s for the merge base, 0.8 s of each reading the
dependency record. The same line added to a generated SQL file failed
twice: on the line, and on the drift the edit caused.

Ratchet mode also checks the branch's provenance, when the
=commit_provenance= codec is on: that every commit of the branch, and its
pull request, state the story, task and environment they belong to, so a
break on main can be traced to the work that caused it. It runs in
=check --ratchet= rather than a codec run or a command of its own. Commit
messages and a pull request's body are not content of the checkout, so a
codec, cached by its inputs, cannot read them. The ratchet already has
the branch: its commits are =merge-base(base, HEAD)..HEAD=. Projects
already run =check --ratchet= on pull requests, so turning the codec on
is the only change their CI needs. =app::ratchet= keeps the corpus of the
checkout's check, and =provenance_of= hands =ops::check_provenance= the
branch's commits (=io::branch_commits=, one =git log=), the :ID: and
=#+type:= of every document of that corpus, and the pull request
=io::find_pull_request= reads with =gh pr view <branch> --json
number,body,url=. The branch is the one HEAD is on or, detached as in a
pull request's CI run, =GITHUB_HEAD_REF=.

What a commit must carry is the project's, never compass's. The check
document whose =* Definition= names =commit_provenance= with =:CODEC:=
gives a =Trailers= table, one row per trailer, and an optional
=Exemptions= table. A table, not codec options, because a project names
any number of trailers, and an option value can hold neither a space nor
a =|=. The codec's own options are what CI flips with =--set=:
=require_pull_request= and =gh=. ORE Studio's document would read:

#+begin_example
,* Definition
:PROPERTIES:
:CODEC: commit_provenance
:END:

,* Trailers

| trailer     | document type | pattern         | pull request label | pull request column |
|-------------+---------------+-----------------+--------------------+---------------------|
| Story-ID    | story         |                 | Story              | 3                   |
| Task-ID     | task          |                 | Task               | 3                   |
| Environment |               | =[a-z]+_[a-z]+= | Environment        | 2                   |

,* Exemptions

| subject                    | omits       |
|----------------------------+-------------|
| =^\[agile\] Record PR #= | Environment |
#+end_example

A trailer with a =document type= holds an uppercase UUID that must be the
=:ID:= of a document of that type in the checkout; any other value must
match its =pattern= whole. Its =pull request label= names the row of the
pull request body's Markdown table that states the same value, in the
=pull request column=, the label's own cell being 1. A commit whose
subject an exemption's pattern finds may omit the trailers it lists; one
it carries is still checked. Merge commits are skipped.

The findings are ordinary ones under =commit_provenance/<rule>=, among
the new findings of the ratchet, and fail it like any other: a commit's
at =commit/<first twelve digits>=, on the line of its message the
trailer is on, the pull request's at =pull/<number>=. A commit whose
value differs from the pull request's is a warning
(=differs_from_pull_request=), since a branch may touch a second task. A
branch with no pull request, or a =gh= that is missing, signed out or set
empty, gets one line, =commit provenance: ... no pull request checked:
<why>=, and its commits are still checked; =require_pull_request=true=
makes it the error =no_pull_request=, for CI. A plain =check= with the
codec on reports a check document that is missing or does not read
(=unreadable=), which the ratchet then skips with a
=commit provenance: not checked: <why>= line.

compass's own commits carry no such trailers, so its =.compass.org=
leaves =commit_provenance= off.

** Blame

A finding already on main was caused by some commit, and the agent that
reads the check is rarely the one that made it. So =check= blames its
findings: for each, it names the commit that likely caused it, the pull
request that brought that commit into main, the commit's trailers, and
the method that found it, and prints one message per environment for the
agent to pass on. A plain =check= blames every finding and reports those
whose commit main holds; =check --ratchet= blames only the findings the
merge base already had, since a new one is the branch's own. A check of
a commit blames nothing. =--no-blame= turns it off.

How a finding is traced depends on its rule, so each rule declares its
method in its descriptor (=codec::types::rule::blame=), bisect by
default; =app::blame_method_of= reads it, from the codec or from the
check document that defines the rule.

| Method   | For                                                          | How                                                                 |
|----------+--------------------------------------------------------------+---------------------------------------------------------------------|
| =line=   | A finding on the line that is wrong: a forbidden pattern, a dangling link, a malformed row. Every rule of a forbid or format check. | =git blame --porcelain -L n,n=, over the working tree, one git per file. |
| =added=  | Something missing that a file's addition made necessary: a missing section, an unregistered part, an unmet obligation. | The commit that added the finding's subject, a diagnostic's optional =subject=, else its file, following renames; with a =subject_text=, first =git log -S= on it, which finds the commit that removed or added it. |
| =drift=  | A generated file that differs from its regeneration.           | Two candidates, labelled: the newest commit among the lines that differ from the output in the run's record (a hand edit), and the first commit since the file last changed to an input the record says produced it (a source changed without regenerating). |
| =bisect= | The rest, and the fallback of the others.                      | Checks main's first-parent merges at their commits with only the reporting codec, through the result cache, to find the first that has the finding, matched by rule, path and message, then the commit of that merge's branch. |

=check= runs line, added and drift; bisect runs a check per probe, so it
is opt-in: =check --blame=bisect=, or =compass blame <path>:<line>:<rule>=
for one finding, which also reports a finding of the branch's own. On
ORE Studio's history a probe costs about 1.5 s with a warm result cache,
and a bisect over 300 merges ran 15 of them in 21 s. A
method that finds nothing falls back to bisect when bisect may run, and
otherwise says it was not traced and why. Bisect walks the last 128 merges
of main, or those since =--bisect-from <rev>=.

Main is the upstream of the branch, else =origin/main=, else the branch
=main=, else HEAD. A commit's pull request is the one its subject names
(a merge's =Merge pull request #n=, a squash's =(#n)=), else that of the
oldest first-parent merge of main whose ancestry holds it. Its trailers
are those the =commit_provenance= check document names, read with the
codec's own parser from the closing paragraph of the message and from
each paragraph before it that is all trailers
(=ops::closing_trailers=), since ORE Studio's commits often set
=Story-ID=, =Task-ID= and =Environment= apart from a closing
=Co-Authored-By= by a blank line, which git and =commit_provenance= do
not read as trailers, and the titles of the story and task they name come
from the corpus. The trailer that names who to tell is the option
=commit_provenance.notify=, by default the first trailer with a pattern,
=Environment= in ORE Studio; compass names none.

The block is addressed to the agent that reads it. A count line comes
first, then one message per environment, each finding with its commit,
pull request, author, trailers, method and fix, then the findings it
could not trace. Any method but line is a guess, so its message says
"likely broke". Commits that state no environment are grouped last, and
the agent is told to reach each commit's author through its pull request:

#+begin_example
compass blame: 2 findings already on main, traced to 1 environment; 0 from commits main does not hold yet; 0 not traced (41.2 ms)
These findings were already on main. Tell environment jolly_knuth that it broke them, with these details:
- portable_cpp/atomic_shared_ptr at src/core/cache.cpp:2: std::atomic<std::shared_ptr> is not portable
  - commit 8bf2f80aa1 '[core] Cache the current value' in PR #4966, by Marco, Story-ID E6359881 'Story: trace a break', Task-ID C6436C51 'Task: blame a finding', Environment jolly_knuth
  - found by: line blame: the last commit to change the line
  - fix: ...
#+end_example

After the codecs, =check= excuses the findings a valid exception covers
(step =exceptions=). It reads the exception comments of every document,
every file a codec read (the =file= inputs of the run's record) and every
file with a finding, adds the rows of the exceptions table of
=.compass.org= (=options::exceptions=), and hands that one
=exception_set= with the findings and =options::today= to =ops::excuse= of
=compass.codec=. A row is judged as a comment is; its problems are
findings on its line of =.compass.org=. The findings it
excuses are dropped and counted in =check_result::excused=; the problems
of the exceptions are added as =exception/...= findings. Exceptions are
read after the run and never recorded, so a reused or cached result does
not hide one that has since expired. A file whose content ID
=compass/unmarked= lists is not read: =io::read_unmarked_file= and
=io::write_unmarked_file= keep the IDs of the files with no marker, and
only a check of the checkout writes them. A check of a commit reads the
exception comments and the table of the commit (or the working tree's
table when the commit has no =.compass.org=), and ratchet mode checks
both sides with the checkout's table and the same =today=, so an
exception that expires is not new. On the ORE Studio
copy the step took about 130 ms reading 28,421 files (269 MB) and
10,927 documents, and about 22 ms once the record listed them; the warm
check went from 2.63 s to 2.66 s.

=app::generate=, =app::diff=, =app::check= and =app::gc= compose the steps;
each takes the options and returns a result. =compass.bench= calls the same
steps and adds only timing and repetition. =app::run= parses a command line, reads the configuration file,
resolves the options, calls the command, has
=io::report= print the result to the streams it is given, and returns the
exit status, so the tests drive the executable's behaviour without spawning
it. =main= only hands =app::run= the arguments, the working directory and
the standard streams.

=hook= is =app::hook=, the edit hook; the
[[id:388AD0F9-D5B5-4FC2-8722-9F88655BA5EC][How do I check edits as Claude
Code makes them?]] recipe has the settings that install it. =app::run=
reads the payload from its input stream; =io::parse_hook_payload= takes
=tool_input.file_path=, against =cwd= when relative, and whether the edit
may have created the file (Edit and MultiEdit never do; Write says
=create= or =update=). =io::checkout_of= finds the checkout as the nearest
directory above the file with a =.git=, so =-C= is not used, and its
=.compass.org= configures the run.

The hook reads the unit index of the dependency record and asks
=codec::ops::units_touching= for the units an edit to the file may change
or that report on it. None, for a file that is not a document, ends the
hook silently there: about 70 ms on ORE Studio for a file no codec reads.
Otherwise it lists the checkout, reads the heads of those units alone, and
loads the documents only when one of their codecs may read documents. It
runs only those units, and for a document every document unit of it, from
their heads and the result cache, through =ops::run='s unit filter, so a
unit whose inputs the edit did not change is reused, not called. When the
prepare step of a staged codec is among them, every part it lists is
taken, so a model that code generation lists for the first time is
generated. The run is told the edited path, whose inputs are checked
first. It reports:

- their findings on the file that their recorded findings lack, matched by
  path, rule and message as ratchet mode matches when lines moved, each
  recorded finding matching one; with =--all-findings=, every finding of
  those units on the file, which is every finding a full check reports on
  it, since a unit with a finding on the file is one the index names;
- their findings on other files that their recorded findings lack, matched
  the same way;
- the drift of each output whose blob ID differs from the recorded one, or
  that is the edited file, and of each recorded output the run no longer
  generates. Only those outputs are formatted and compared with the disk;
  a reused unit's output contents are not read, except the edited file's.
  A path two parts of a staged codec emit is compared as the later
  part's.

Reporting only new findings is the default because the hook answers
whether this edit broke something, and an agent blocked on what the file
already held learns nothing it can act on: ORE Studio's tree held about
200 baseline entries, and every edit to a file holding one blocked. The
old findings are counted, not lost: the hook says how many the last check
recorded on the file and that =compass check= lists them, in
=additionalContext= when nothing is new, so it does not block, and after
the new findings when something is.

Valid exceptions excuse findings as =check= excuses them, reading the
comments of only the edited file and the files with findings, and the
table of the checkout's =.compass.org=; the exception findings reported
are those of the edited file, so a row's own problems wait for
=compass check=. The hook writes nothing and exits
0 whatever happens. A missing record (with a =.compass.org=), a damaged
or replaced one, a configuration or load error, an edit to =.compass.org=
or a contract page, and any exception become a note in
=additionalContext=, so the agent is told the file went unchecked and is
never blocked. =io::write_hook= writes the JSON. The record is taken to
describe the checkout before the edit: a finding an earlier unchecked edit
caused on another file is reported as new until =compass check= rewrites
the record.

A check writes =compass/listing= beside the dependency record: each file
of the listing, whether it is a document, and a SHA-1 trailer
(=io::write_listing_file=), rewritten only when it changed. The hook
lists the checkout from it (=io::read_listing_file=) and does not list the
checkout with git. For a file the payload says may be new, it asks git to
list that one path (=io::list_files= with a path), which says whether the
file exists and no ignore rule covers it, and adds it to the recorded
listing. A missing or damaged record, or an edited file it lacks, falls
back to =git ls-files=. Content IDs are resolved once per run
(=app::listed_ids=), and a check keeps every listed file it hashed in the
worktree index, so a file under an attributes rule is not hashed again.

On a copy of ORE Studio at 545cafca45, with codegen and the ported gates
enabled, a warm hook spends about 45 ms reading the 11 MB index, 15 to 20
ms listing, 20 to 80 ms reading the heads of the units it runs, 60 ms
opening git's index for content IDs and 40 ms loading the documents when
needed. What an edit then costs is the units it calls:

- Code generation is a staged codec (see compass.codec and
  compass.codegen): an edit to a model reads what the models share again,
  about 140 ms, and generates that model and those that read it; an edit
  to a template renders that template's outputs.
- The gates that read every C++ or SQL file are scans. An edit maps the
  edited file, and the reduce step runs only when the file's fact changed
  or the reduce step read the file itself, so a comment added to a
  header maps it in eight scans and reduces none whose fact it left as
  it was.
- =component_docs= and =test_case_reachability= are scans too, so an edit
  to a document outside =doc/=, or a new file under =projects/=, no longer
  reads every page or every test source.

The first two columns are the machine as it was, eight cores with other
work on it. The last is with seven processes spinning beside the hook,
which took the load from 5 to 15 as the edits ran: the hook's units run on
every core, so a loaded machine gives it a fraction of them. At a load of
2 to 3 every edit is checked in under a second but a new model document;
at a load above 7 an edit that calls several gates or code generation is
not.

Over 34 single-file edits of that copy the hook's findings were exactly
those of a full check on the edited file plus those the full check gained
on other files: the 27 edits of the first comparison (SQL, C++, org
documents, a model, templates, CMake files, a recipe, a skill page,
unrelated files, a dropped include, three new files, a second definition
of a type name, a dropped include that leaves a file unreachable, a
removed registrar call and an edit to a field group model other models
read) and seven that exercise incremental code generation: a family's
central entity, a column other entities key on (17 findings), a field of
a field group, a line added to a component template (19) and to the
template of every entity's header (582), a new model and a new header.

A full warm check took 3.5 s at load 9, where it took 4.1 s. Right after a
codegen change it took 4.7 to 5.0 s at load 7 to 9, where it took about
10 s: a changed model stores its own result, about 230 KB on average,
where one unit stored all 193 MB. About 1.1 s of that is writing the 269 MB dependency
record again, and 0.8 s reading it.

* Inputs

- The command line. One argument is the command; options may come before
  or after it.

| Option                          | Default                                  | Meaning                                         |
|---------------------------------+------------------------------------------+-------------------------------------------------|
| =-C <dir>=                      | the working directory                    | The checkout, made absolute.                    |
| =--meta <dir>=                  | =#+meta:=, else =doc/meta=               | The contract pages, relative to the checkout.   |
| =--out <dir>=                   | =#+output:=, else =build/output/compass= | The output root, relative to the checkout.      |
| =-j <n>=                        | one per core                             | Threads.                                        |
| =--set <codec>.<key>=<value>=   | the file, else the codecs' own           | A codec setting; repeatable, the last one wins. |
| =--timings=                     | no                                       | =generate=, =diff=, =check=, =hook=: print each step's time and what each codec ran or reused, and how long its units ran. |
| =--commit <rev>=                | the files on disk                        | =check= only: check the commit =<rev>= names, as =git rev-parse <rev>^{commit}= resolves it, with that commit's =.compass.org=, or, when the commit has none, the working tree's, with a warning on standard error. The output root and meta directory must be under the checkout. |
| =--ratchet [<base>]=            | the upstream, else =origin/main=         | =check= only: fail only on findings the merge base of HEAD and =<base>= lacks. The next argument is the base unless it starts with =-= or names a command; =--ratchet=<base>= always takes one. Not with =--commit=. |
| =--today <YYYY-MM-DD>=          | today in UTC                             | =check= and =hook=: the date the expiry of exceptions, comments and table rows alike, is judged against, for the checkout, a commit and both sides of a ratchet. |
| =--blame[=bisect]=, =--no-blame= | line, added and drift               | =check= only: which blame methods run on the findings already on main; =bisect= adds bisect, =--no-blame= runs none. |
| =--bisect-from <rev>=           | the oldest of main's last 128 merges     | =check= and =blame=: the commit, without the finding, bisect starts from. |
| =--all-findings=                | no                                       | =hook= only: report every finding on the edited file, not only those the last check did not record. |
| =--dry-run=, =--cap=, =--grace= | no, 0 bytes, 3600 s                      | =gc= only.                                      |
| =--help=, =-h=, =--version=     |                                          | Print and exit 0, whatever else is there.       |

=--version= prints one fact per line: the release; the full and short commit;
whether its tree was dirty; the branch; the commit's committer time; the build
time; the install time; and the store formats the binary reads and writes (the
store layout, 2 for packs, the pack, dependency record, action, written
outputs, format cache and worktree index versions). The commit facts come from =compass.manifest=, a =key=value= file
the =compass.cli.version= target writes beside the binary on every build
through =cmake/generate_version.cmake=; the binary finds it beside its own
resolved path, so a link to the binary works. The build time is the binary's
last write time, read at runtime. A missing or damaged manifest gives
=unknown=, and the exit status is still 0. No compiled file holds the commit,
so a commit recompiles and relinks nothing. =build/scripts/install_compass.sh=
installs a build as the one compass all environments share: the binary, its
mtime kept, and the manifest, with the install time added, in
=~/.local/opt/compass/=, and =~/.local/bin/compass-ng= linked to the binary;
the name keeps it apart from ORE Studio's Python =compass=.

- The configuration file, =.compass.org= at the root of the checkout. It
  is optional: without it every value is the default. =#+output:= and
  =#+meta:= set the paths, relative to the checkout. The first table under
  the level-1 heading =* Codecs= has one row per codec: its name, =yes= or
  =no= for enabled, and its options as space-separated =key=value= pairs.
  A first row whose first cell is =name= is a header, and separator lines
  are skipped. A codec with no row keeps its defaults. The first table
  under the level-1 heading =* Exceptions=, which is optional, has one
  exception per row: path, line (empty for the whole file), rule,
  expires, approver and reason. =config::parse_repository_file= reads it
  into =layer::exceptions= with =codec::ops::add_exception_row=; a row
  that does not hold is a malformed exception on its line, not an error.

#+begin_example
#+output: build/output/compass
#+meta: doc/meta

,* Codecs

| name              | enabled | options                     |
|-------------------+---------+-----------------------------|
| document_index    | yes     | path=doc/document_index.tsv |
| required_sections | yes     |                             |

,* Exceptions

| path          | line | rule                              | expires    | approver | reason            |
|---------------+------+-----------------------------------+------------+----------+-------------------|
| doc/task_b.org |    2 | required_sections/missing_section | 2027-06-30 | marco    | written elsewhere |
#+end_example

- Precedence, key by key: the codec's and compass's defaults, then the
  file, then =--out=, =--meta= and =--set=. =config::resolve= is the one
  function that applies it. A row with other than three cells, an enabled
  value other than =yes= or =no=, an option that is not =key=value=, a codec
  named twice, a file with no =* Codecs= table, and a codec or option the
  catalogue lacks are errors. Each names the file, the line and the fix,
  and the command exits 2.
- The checkout: every tracked file and every untracked one no ignore
  rule covers, as =git ls-files --cached --others --exclude-standard= lists
  them, less the tracked files deleted from the worktree, which
  =-t --deleted= marks in the same call, so a codec lists what a script
  globbing the disk finds. Its org files but =.compass.org= are the
  corpus. Every file is visible to the codecs' file reads, listings and
  existence tests. The configuration file is not a document, so an edit
  to it re-runs exactly the codecs whose configuration changed, through
  the configuration hash in the dependency and cache keys.
- The store and the result cache under the git common directory, and the
  worktree index, dependency record and written-outputs record under the
  checkout's own git directory, and =compass/unmarked= beside them.
- The exception comments of the files =check= reads and the exceptions
  table of =.compass.org=; see
  [[id:5B528519-8BCE-4CB8-A48E-B525FD71F873][How do I excuse a finding?]].

* Outputs

- Standard output: =generate= prints one line of counts (written,
  unchanged, restored, removed, kept), the output root, the corpus, the
  units each codec ran rather than reused, and the wall time. =diff= prints the unified diffs. =check= prints one line per
  diagnostic, sorted by path, line and column, then the count and, when
  any, how many findings exceptions excused. Its
  diagnostics include one per file =generate= would write, restore or
  remove, under the rule =drift= of the codec that emits it, at the first
  byte that differs; a file outside the checkout is named by its absolute
  path. =check --ratchet= prints only the new diagnostics, in the same
  form, then, when =commit_provenance= is on, one line with the commits
  it checked and the pull request it read or why none, then one line with
  their count, the excused count, the merge base and the renamed files
  followed. Before the count, =check= prints what blaming the findings
  already on main found, as the Blame section shows; =blame= prints the
  same block for its one finding. =gc= prints
  the entries and files it removed, or would remove, the size of the store
  and its packs before and after, and the files of the first layout it
  removed. =config=
  prints one line per path and codec setting, as
  =<key> = <value> (<source>)=, the source being =default=,
  =.compass.org:<line>= or =command line=.
- Standard error: for a run that collected the store, one line with
  what it removed and kept
  (=compass: collected the store: removed <n> entries and files, ...=),
  or a warning when the collection failed, which fails nothing; for
  =generate=, one warning per file whose rewrite
  deleted what may be code written by hand
  (=compass: warning: <path>:<line>: generate deleted <n> lines its output
  lacks, from "<first line>"; ...=), as =codec::io::find_hand_edits= finds
  them before the write; the summary of =diff=; with =--timings=, one line per
  step (=tree= for a commit, =types=, =list=, =resolve=, =load=, =record=,
  =codecs=, =format=, =persist=, =collect=, =write= or =plan=, =exceptions=) with its wall time,
  and one line per codec
  with the units it ran, took from the record and took from the cache,
  and what formatting its files did; every error of the configuration
  file, every file that did not load,
  every problem of the codec registry or the output root, and the message
  of a command that throws, as =compass: <what>=.
- Exit status: 0 when nothing would change and no diagnostic fires, 1 when
  =diff= finds a change or =check= a diagnostic, 2 on failure or bad usage.
  =check --ratchet= exits 1 only on a new diagnostic, and 2 when either
  check fails or the base cannot be resolved. With =--timings= it prints
  the steps of the checkout, then =compass: merge base:= and those of the
  merge base.
  =generate= and =gc= exit 0 when they succeed.

The line and column of a diagnostic are those of the first byte of its
range, 1-based, the column counted in bytes. The rule is written as
=codec/rule=, so two codecs may have rules of one name.

* Dependencies

- =compass.codec= for the codecs, the runner, the records, the format
  cache, the sink and the diff.
- =compass.codegen= for the =codegen= codec.
- =compass.cpp= for the C++ gates.
- =compass.sql= for the SQL gates.
- =compass.crosscheck= for the cross-artefact gates.
- =compass.docs= for the document gates.
- =compass.model= for its JSON reader, which reads the hook's payload
  and what =gh= prints.
- =compass.ingest= for the parser and the type registry builder.
- =compass.store= for IDs, the store, collection and the git object
  reader.
- =compass.org= and =compass.platform= for the tables and mapped files,
  which the steps' =corpus_files= exposes, and =compass.platform= for the
  executable's own path.
- =gh=, at run time, for the pull request of a branch, when
  =commit_provenance= is on; without it the commits are still checked.
- Catch2, git and bash, for the tests only.
