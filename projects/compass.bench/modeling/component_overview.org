#+title: compass.bench
#+description: The frozen benchmark harness. It times reading every tracked file of a git checkout, building its include graph, parsing its C++ and SQL with tree-sitter, parsing its org documents into the compass.org tables, resolving their types, storing them, finding the git blob ID of every file, running the codecs over the loaded corpus and loading the codegen models.

This page is the component overview for =compass.bench=, a simple component
in the tooling layer of the
[[id:8A9A460F-8024-4890-B091-C0D02FD84218][System Model]].

* Summary

=compass.bench= is the harness every compass-ng measurement runs through. It
installs as =compass-bench= and runs in stages. All list the tracked files
of a checkout with one =git ls-files -z= call and map files with
=compass::platform::filesystem::mapped_file=.

- =read= folds every byte of every regular file into a checksum, on N
  threads.
- =includes= scans every C and C++ file (=.hpp=, =.cpp=, =.h=, =.hh=, =.cc=,
  =.cxx=, =.ipp=, =.tpp=) for =#include= directives on N threads. The scanner
  is hand-written and skips comments and string, char and raw string
  literals. The stage then resolves each include through the directories of
  =compile_commands.json=, builds the include graph and computes the
  transitive fan-in of each file, on one thread. Each step is timed
  separately.
- =parse= parses every C and C++ file (the =includes= extensions) and every
  =.sql= file with tree-sitter. Each language runs on its own, on N threads
  over ranges balanced by bytes, with one parser per thread over the mapped
  bytes. Per file it records the fastest parse time over the repetitions and
  the count of =ERROR= and =MISSING= nodes, found with a tree cursor that
  skips subtrees without errors. Each tree is deleted after counting.
- =org= parses every =.org= file with the =compass.ingest= org parser, on N
  threads over ranges balanced by bytes. Each thread keeps one set of
  =compass.org= tables and refills it for every document.
- =types= builds the type registry from the =document_type_*.org= pages of a
  meta directory and the codegen model names, then parses every =.org= file
  as =org= does and resolves its first =#+type:= keyword against the
  registry. Each repetition builds the registry and resolves every file.
- =store= stores every =.org= file as an object and loads it back, on N
  threads. The cold run maps each source, computes its git blob ID, parses
  it, encodes the tables and writes the object; the objects are removed
  before each repetition, outside the timing. The warm map run builds each
  object's path from its blob ID, maps the object and decodes it, which
  reads no column. The warm verify run also checks each checksum, which
  reads every column. Last, outside any timing, the dump of every loaded
  object is compared with the dump of its parse. The warm runs take the blob
  IDs from the cold run and read objects the page cache holds.
- =ids= finds the git blob ID of every tracked file, on N threads. Each
  repetition builds a =compass.store= =id_resolver=, which reads the index,
  the configuration and the attributes files, then asks it for the index ID
  of every file, one =lstat= each, then hashes the files that got none.
  Last, outside any timing, a sample of the IDs is checked against
  =git hash-object --no-filters=. Nothing is written to the checkout or its
  git directory.
- =codecs= loads every =.org= file as a corpus and runs the codecs of
  =compass.codec= over it. The corpus is loaded once: the ID of each file
  comes from an =id_resolver=, its object is mapped from the store and
  checked, and a file with no usable object is parsed into memory. Every
  source and object stays mapped, and the type of each
  document is resolved against the registry of a meta directory. The enabled
  codecs then run =--repeat= times on N threads, each repetition from the
  dependency record the checkout had, so a unit whose inputs are unchanged
  is skipped, and with the repository's result cache, so a unit another
  worktree ran with the same inputs is taken from it. Without =--write= the outputs stay in memory. With it, the
  files of the last repetition go to the output root through
  =compass.codec='s output sink, which writes only those whose content
  changed. After the run the parsed objects go to the store, the units that
  ran go to the result cache, and the worktree index, the dependency record
  and, with =--write=, the
  written-outputs record are written to the git directory, each only when it
  changed. With =--diff= the outputs are planned against the root by the
  same sink and printed as a unified diff, and nothing is written: no
  object, no record and no output.
- =models= parses the =.org= files of every =modeling= directory under
  =projects/= once, then loads every codegen model among them into the
  =compass.model= tables, on one thread, =--repeat= times. A model reads
  other documents, such as its profile, through a finder over the same
  parsed set, which parses a document outside it the first time it is
  asked for. =--dump= writes each model of the last repetition as
  canonical JSON, for =build/scripts/codegen_model_diff.py=.

=gc= is not a stage either. =ops::run_gc_stage= collects the store once with
=compass.store='s =io::collect=, keeping the action objects of the result
cache that any worktree's dependency record names (=compass.codec='s
=io::action_keys=), and reports what it found and removed.

=org-dump= is not a stage. It parses one org file and prints its tables in
the line format of =compass::org::io::dump=, which
=build/scripts/org_element_dump.el= prints for org-element.
=build/scripts/org_diff.py= compares the two over a set of files.

* Inputs

- =compass-bench read <checkout> [-j N] [--repeat R]=. =-j= defaults to all
  cores and =--repeat= to 5.
- =compass-bench includes <checkout> --compile-commands <file> --source-root
  <dir> [--isystem <dir>]... [-j N] [--repeat R]=.
  - =--source-root= is the directory the compile commands were generated
    against. It is required because the entries of a unity build all live in
    the build tree, so no prefix of the "file" entries names the source root.
  - =--isystem= adds an implicit system directory of the compiler, which
    compile commands do not list. Print them with
    =clang++ -E -x c++ -v /dev/null=.
- =compass-bench parse <checkout> [-j N] [--repeat R]=.
- =compass-bench org <checkout> [-j N] [--repeat R]=.
- =compass-bench types <checkout> --meta <dir> [-j N] [--repeat R]=. =--meta=
  is the directory of the contract pages, such as =doc/meta=.
- =compass-bench store <checkout> [--store <dir>] [-j N] [--repeat R]=.
  =--store= is the objects directory; without it the stage uses
  =compass/objects= under the git common directory of the checkout.
- =compass-bench codecs <checkout> --meta <dir> [--store <dir>] [--set
  <codec>.<key>=<value>]... [--write <root> | --diff <root>] [-j N]
  [--repeat R]=. =--meta=
  and =--store= are as for =types= and =store=. =--set= adds one row to the
  codec configuration: =--set required_sections.enabled=false= disables a
  codec and =--set document_index.path=build/index.tsv= sets an option.
  =--write= names the output root; output paths are relative to it.
  =--diff= names the root to compare against and exits 0 when nothing
  would change, 1 when a file would be written, restored or removed, and 2
  when the run fails. The two are exclusive.
- =compass-bench gc <checkout> [--store <dir>] [--cap <bytes>] [--grace
  <seconds>] [--dry-run]=. =--store= is as for =store=. =--cap= defaults to
  0, which removes every unreferenced object past the grace period, and
  =--grace= to 3600. =--dry-run= chooses the victims and removes none.
- =compass-bench ids <checkout> [-j N] [--repeat R] [--verify N|all]=.
  =--verify= checks N IDs spread evenly over the files, or all of them; it
  defaults to none.
- =compass-bench models <checkout> [--dump <dir>] [--repeat R]=.
- =compass-bench org-dump <file>= prints to standard output.
  =compass-bench org-dump --list <list>= reads one input path, a tab and an
  output path per line and writes each dump to its output.
- A git checkout. Tracked entries that are not regular files (submodules,
  symlinks) are skipped. A tracked file that is missing on disk is kept and
  counted as an error.
- For =includes=, the compile commands of the commit the checkout holds.

* Outputs

- For =read=: a stage table of files, bytes, errors, median, min and max wall
  milliseconds over the repetitions, and MB/s (10^6 bytes) at the median. The
  checksum, the thread count, and the =git ls-files= and =lstat= setup times
  on their own lines. The top 15 extensions by bytes, with file counts.
- For =includes=: the median, min and max wall milliseconds of the scan,
  resolve, graph and closure steps. Files and bytes scanned, includes found
  by kind, and how many resolved inside the checkout, outside it (external)
  and nowhere (unresolved). Distinct edges, the setup times, and the counts
  of compile commands, directories and search contexts. Then the top 10
  unresolved names, and the top 15 files by direct and by transitive fan-in.
- For =parse=: a stage row per language (=cpp=, =sql=) with the columns of
  =read=, then the thread count and setup times. Per language, the files
  with parse errors, the total error nodes, and the top 10 files by error
  nodes and by parse time.
- For =org=: one stage row with the columns of =read=, then the thread count
  and setup times, the rows the tables took summed over the documents
  (elements, objects, headings, links, names), and the top 10 files by parse
  time.
- For =types=: one stage row for parsing and resolving, the median registry
  build time and the resolve time summed over threads. Then one row per
  contract page saying whether it fits the extraction rule and where its
  level, folder, state and sections came from; the documents per registered
  type with its kind, and the types no document uses; the documents with no
  =#+type:=, the first 20 listed; and every unresolved type with its count
  and up to five of its files.
- For =store=: one stage row for the cold run, whose bytes are source bytes,
  then the thread count, the setup times and the objects directory. The
  median, min and max wall milliseconds of the cold, warm map and warm verify
  runs. The distinct objects against the files, the object bytes against the
  source bytes with their ratio, the objects that did not load and the files
  whose two dumps differ. Either of the last two counts fails the run.
- For =gc=: the store and options, the git directory of each worktree read,
  the live IDs and the action keys the records name, then counts and bytes
  of the files stored, live, within the grace period, old and unreferenced,
  temporary, chosen and removed, and of the action objects stored and named;
  the
  size of the store after the collection against the cap; and the wall
  milliseconds of each phase. A store left over its cap because its live
  objects fill it is data, not failure. An index that cannot be read exits
  with status 1 and removes nothing.
- For =codecs=: the org files and the documents loaded, the registered
  types, the load time with the objects loaded, parsed and written, every
  problem of the codec registry, and the units and bytes of the dependency
  record read, with whether the new one was rewritten and why an old one
  was not used. The result cache: the lookup time, and the results and
  manifests stored, with their bytes and time. With =--write=, the outputs written, unchanged, restored,
  removed and kept, the time of the sink, whether the written-outputs record
  was rewritten, and why an old one was not used. One row per codec: its unit and output kind, the documents
  it was given, the units it ran, skipped and took from the cache, its
  output files and their
  bytes, its
  diagnostics, and the median, min and max milliseconds spent inside it,
  summed over threads; then the wall time of a run. Each output file with
  its size. Per codec with diagnostics: the documents with any, the count by
  rule, the 15 most frequent messages and the first 10 findings as
  =path:line: severity: codec/rule: message. fix=. A file that does not
  load, a registry problem or outputs the sink refuses (an escaping path,
  a path two codecs produce) fail the run; diagnostics are data.
- For =codecs --diff=: the unified diff on standard output, then on
  standard error what writing would do (write, restore, remove and keep
  counts, and unchanged), the output root, the corpus with the objects
  loaded and parsed, the run's wall time, the plan and diff times, and
  every failure.
- For =models=: the documents parsed and the time to map and parse them,
  the models and the value rows of the last repetition, the count of each
  model type with how many ores.codegen refuses or are not ported, and the
  min, median and max milliseconds of loading every model.
- For =ids=: the index version, its entries and how many may lend their
  ID, and whether =core.autocrlf= converts; the thread count and setup
  times; the files whose ID came from the index and those hashed, with the
  bytes hashed; the median, min and max wall milliseconds of reading the
  index, stat-ing and hashing; and the IDs verified with the mismatches. A
  file that cannot be hashed or any mismatch fails the run.
- A =FAILED= line and exit status 1 when the stage read or scanned no files
  or hit any error. For =parse= this holds per language: a language with no
  files, or a file that cannot be read, fails the run. Parse errors inside a
  tree are data, not failure. For =types=, a meta directory with no contract
  page fails the run, and an unreadable meta directory or page exits with
  status 1; unresolved types are data. A usage error exits with status 2.

* Resolution

Each compile command contributes its =-iquote=, =-I= and =-isystem=
directories. A directory under the build directory of the command stays
absolute and is external, so generated headers resolve as external while the
build tree exists. Any other directory under the source root is rebased onto
the checkout. Directories outside the source root stay absolute and are
external.

A command is anchored at the checkout directory it compiles. That is the
directory of its file or, for a unity source in the build tree, the
build-tree directory above =CMakeFiles=. Each file is searched with the
union of the commands anchored at or below its nearest ancestor that has any.
A source file therefore gets the directories of its own target, and a header
gets those of every target in its component. A file in no compiled component
gets the union of all commands.

A quoted include tries the directory of the includer, then the =-iquote=,
=-I=, =-isystem= and implicit directories. An angle include starts at =-I=.
In an internal directory, a hit must be a file of the file table. In an
external directory, a hit must be a regular file on disk.

The rule for headers is an approximation. A compiler searches a header with
the directories of the translation unit that includes it. A header whose
includes depend on the directories of its includer, such as a shared test
fixture, can be unresolved here although it compiles. Conditional
compilation is not evaluated, so an include under =#ifdef _WIN32= counts on
Linux.

* Data shape

| Type              | Holds                                                                          |
|-------------------+--------------------------------------------------------------------------------|
| =file_table=      | Columns of path, size and extension id; extensions interned once.              |
| =file_range=      | A contiguous run of file ids for one thread, balanced by bytes.                |
| =stage_result=    | Files, bytes, errors, checksum, first error and one wall time per repetition.  |
| =compile_command= | One compile_commands.json entry: directory, absolute file, argument words.     |
| =search_paths=    | Interned include directories, search contexts, and the context of each file.   |
| =include_table=   | Columns of includer, line, kind, header name and target per =#include=.        |
| =include_graph=   | Compressed sparse rows of distinct include edges over file ids.                |
| =includes_result= | The include table, the graph, the fan-in columns and wall times per step.      |
| =language_result= | A =stage_result= and columns of file id, parse ms and error nodes per file.    |
| =parse_result=    | One =language_result= per =language= (=cpp=, =sql=).                           |
| =org_result=      | A =stage_result=, columns of file id and parse ms, and the table row counts.   |
| =meta_registry=   | The type registry and, per contract page, its path and =contract_report=.      |
| =types_result=    | A =stage_result=, registry times, and per file its resolution, type and value. |
| =codecs_result=   | Load counts and times, the codec registry, times per codec, the last run.      |
| =codecs_diff=     | A =codecs_result= never persisted, the counts of the plan, the diff and times. |

* Dependencies

- =compass.platform= for =mapped_file=.
- =compass.ingest= for the org parser and the type registry builder, and
  =compass.org= for the tables, their dump, the object codec and the type
  lookup.
- =compass.model= for the model tables, the loader and the JSON dump.
- =compass.codec= for the codec registry, the runner and the codecs.
- =compass.store= for blob IDs, object paths, object writes, the ID
  resolver and collection.
- tree-sitter from vcpkg, and the =tree-sitter-cpp= 0.23.4 and
  =tree-sitter-sql= 0.3.13 grammars from the overlay ports in
  =build/cmake/overlays/common=. The ports compile the generated parsers
  their releases ship.
- The C++23 standard library, POSIX (=posix_spawnp=, =lstat=, =stat=) and
  =git= on the =PATH=.
- Catch2, for the tests only.
