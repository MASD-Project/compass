#+description: Codegen entity model for corpus.section: the plain text a heading holds before its first subheading, or the preamble's, with the search vector computed from it.
#+type: masd.codegen.entity

#+brief: The searchable text of one heading of a corpus document.
#+entity_singular: section
#+entity_plural: sections
#+created: 2026-11-22
#+updated: 2026-11-22

One section per heading, and one for the preamble when the preamble has prose.
The text is the heading's own section as plain text, without drawers,
keywords, planning lines, clocks or comments. Search reads =tsv=.

* Flags
:PROPERTIES:
:product:    compass
:component:  db
:schema:     corpus
:profile:    owned-child-row
:END:

The profile =owned-child-row= assigns no feature. It says a row is identified by its owner's key and its =ord= and deleted with its owner, and it switches on the row's =COPY= writer.

* Columns

** hash
:PROPERTIES:
:type:         bytea
:cpp_type:     store::types::blob_id
:primary_key:  true
:key_kind:     content_hash
:END:

The blob ID of the document's source: the owner's key. The writer takes it as an argument, so the row type leaves it out.

** ord
:PROPERTIES:
:type:         integer
:cpp_type:     std::uint32_t
:primary_key:  true
:key_kind:     ord
:END:

The row's place among its document's rows of this table, from 0. It is the index of the row in the aggregate's vector, so the row type leaves it out.

** heading_ord
:PROPERTIES:
:type:      integer
:cpp_type:  std::uint32_t
:nullable:  true
:member:    heading
:END:

The =ord= of the section's heading in =corpus.heading=; NULL for the preamble. The row type names the member =heading=, not =heading_ord=; see Notes.

** text
:PROPERTIES:
:type:  text
:END:

The section's text as plain text. A link becomes its description, or the link as written.

** tsv
:PROPERTIES:
:type:      tsvector
:computed:  writer
:END:

The search vector. The writer computes it in the insert: the document's title
weighs A, the path of its heading =h= B and the text D, under the database's text search
configuration (=compass.setting= =text_search=):

#+begin_src sql
setweight(to_tsvector($1::regconfig, coalesce(d.title, '')), 'A') ||
setweight(to_tsvector($1::regconfig,
    coalesce(array_to_string(h.path, ' / '), '')), 'B') ||
setweight(to_tsvector($1::regconfig, s.text), 'D')
#+end_src

A generated column could not compute it, because it reads another table's
row and a setting. =:computed: writer= leaves it out of the row type and the
=COPY= column list.

* Foreign keys

** hash
:PROPERTIES:
:references:  corpus.document
:on_delete:   cascade
:END:

The document this row belongs to. Deleting the document deletes the row.

* C++

The row is =compass::db::types::section_row= of
=compass.db/types/section_row.hpp=, generated: =std::optional<std::uint32_t>
heading= and =std::string text=. =hash= and =ord= are left out by their key
kinds and =tsv= because the writer computes it; =write_copy= of
=compass.db/io/section_copy.hpp= takes the hash and the ord beside the row.

* Notes

- =:member: heading= names the member of the column =heading_ord=.
- The weight-B input of =tsv= is the heading's path. #176 staged it as a
  column the table lacks; the insert now joins the staged heading and joins
  its =path= with " / ", so every staged column is a column of the table.
- The expression of =tsv= stays the writer's: it reads the staged document's
  title and the configured =regconfig=, which a generated column cannot.
