One row per note. A note belongs to a campaign and may name a scenario and a
step. It is open until someone addresses it with a reply.

* Flags
:PROPERTIES:
:product:    compass
:component:  db
:schema:     activity
:profile:    activity-record
:END:

The profile =activity-record= fixes =current_state= and =retained=: the table holds test activity that exists nowhere else, so a model change that drops or retypes one of its columns needs a migration in the same pull request.

* C++

#176 has no C++ for this table; [[id:C1DC377F-4A1B-4131-B734-FE28DB63CF03][Serve the documents]]
will need its row, reader and insert. The row the model generates is the
specification of that code.

* Notes

- =state= has both a default and a value list. The default is written as SQL
  text (='open'=); a generated enumeration would need the default as a value
  of the list, =open=, to initialise its member.
- Nothing ties =state= to =reply=, =addressed_by= and =addressed_at=: the
  table lets an addressed note have no reply. The model states the table as
  it is.
