One row per migration applied. =migrate= inserts the row in the same
transaction as the migration's SQL, under an advisory lock, and reads
=max(version)= as the schema's version.

* Flags
:PROPERTIES:
:product:    compass
:component:  db
:schema:     compass
:profile:    bookkeeping
:END:

The profile =bookkeeping= is not one the investigation names; this model proposes it. It fixes =current_state= and withdraws the table template: the [[id:02089780-F445-4220-89E1-3CBCA0347B37][task]] keeps the schema =compass= hand-written, because the migration runner creates it before any migration runs. The model describes the table and generates nothing.

* Columns

** version
:PROPERTIES:
:type:         integer
:cpp_type:     std::uint32_t
:primary_key:  true
:key_kind:     natural
:END:

The migration's number, from 1 with no gap.

** name
:PROPERTIES:
:type:  text
:END:

The migration's name, such as =the corpus, test and activity schemas=.

** applied_at
:PROPERTIES:
:type:        timestamptz
:default:     now()
:written_by:  database
:END:

When it was applied. The database writes it.

* C++

None: the profile =bookkeeping= switches every MASD facet off.
=schema_status= of =compass.db/io/schema.hpp= reads the version as a
=std::uint32_t=, and =migrate= inserts =version= and =name= with =exec=.

* Notes

The table is created by =bookkeeping_sql()= with =CREATE TABLE IF NOT
EXISTS=, before and outside the numbered migrations, so no migration and no
=schema.sql= creates it: the schema model does not list the schema
=compass=, and the profile generates nothing. The model stays so every table
is reviewed in one form.
